> 公开整理版 · 2026-11-25。保留成文时点的记录；计划、文献结果和本地实测请分别理解。 环境路径已泛化，未收录的附件已标注；发布范围见 [整理说明](../../../PROVENANCE.md)。

- 训练以 Megatron 分片保存 checkpoint-10946。使用训练镜像 TP4 重新分片导出 BF16。Swift 导出时重写了部分 tokenizer/config 文件。推理视图通过硬链接使用学生的全部权重和索引，模型架构、tokenizer、processor 和模板文件复制自相同底模。两套图文服务使用相同镜像、硬件和参数。导出前后的核验见 weight-audit.json。
- 第一轮图库外 canary 使用单轮输出上限 32768，协调方在 3600 秒上限之前手动中止了两边的试跑。原始记录位于 runs/first-sft-eval-20261123-001/canary，标记 operator_interrupted。早先状态将此写成“预算超时”有误。该试跑没有产生模型质量或正式超时结论。
- 第二轮 canary 的单轮上限为 8192。这个参数限制单个响应，整条轨迹可包含多轮。整题保留 3600 秒时限。启动前的目录/参数组装错误在实际推理前修复。
- 第二轮 canary 在两个模型都读回真实 PNG、生成可独立冷启动的 HTML 快照后达到基础设施检查条件。分别在隔离浏览器中采了 9 帧，均有 WebGL 绘制且无外部请求。两条原始 CLI 继续按 60 分钟规则运行，最终结束状态单独归档。正式 dev/test 使用同两台机器上另一组各 4 张空闲 H800，与 canary 使用不同的推理进程和 GPU。
- 原版自然结束的 canary 和部分 dev 轨迹在 tool 消息后收到 HTTP 400。vLLM 0.21 的 Anthropic 协议拒绝 messages 数组内的 system 角色，本机项目既有兼容镜像会将其文本按原顺序拼入顶层 system。已对照实际源码实现同一转换；没有内嵌 system 的请求按原字节转发。两臂相同请求均实测原路径 HTTP 400、修正路径 HTTP 200。原 canary 保留异常结束。dev 只重跑终态精确符合该基础设施错误的运行，旧的流、工作区、用量与耗时完整移入 dev-transport-incident；不根据成片结果重跑，单列补跑费用。隐藏 test 从第一条请求就走相同兼容层。
