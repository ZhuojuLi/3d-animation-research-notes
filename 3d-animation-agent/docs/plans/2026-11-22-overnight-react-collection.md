## 每题三条独立轨迹

用户确认同一 case 可以并发采样 3 次再选优。先为现有 16 个长程 case 补齐 trial-2/3/4，立即形成 **48 条新轨迹**。后续每个新 case 也默认 3 次独立采样，64 个新 case 对应最多 **192 条新轨迹**。

- 同一 case 的 3 次运行是独立候选，不是 3 个独立 case。
- 每个 case 默认只选 1 条主样本，依据最终交付、关键断言、实际画面、ReAct 价值和成本选优。
- 只有解法或有效返修路径有实质差异时才保留额外汇本，不能为了增加条数把同题近似轨迹全部混入。
- 三次采样是用户批准的固定采集预算，不是失败后无界重试；超过三次仍不为质量结果继续刷。
- manifest 和 summary 按 trial 分文件保存，原始 trial 永不覆盖。

## 配比与难度

64 个新训练候选按约 40% 难点、30% 中等、15% 简单、15% 健康控制组织：

- 难点约 26：优先真实 Qwen 失败与已验证单缺陷。
- 中等约 19：一段明确的观察→修改→复验。
- 简单约 10：短工具链和直接成功路径。
- 健康控制约 9：初始已合格，检查后保持并交付，验证最终哈希未变。

难点必须满足：Qwen 失败可重放、非坏 fixture/配置错误、Kimi 能完成、独立断言能区分好坏。不能仅因场景复杂就记为难点。

## 四波采集

每波 16 个唯一 case，Kimi 默认 16 并发；只有错误率、浏览器和磁盘都稳定时才允许下一波升到 32。Qwen 保持单并发。

### A · 纠偏批次（约 01:30–02:30）

- 6 个中等题：明确单点修复和复验。
- 4 个简单题：离线打包、单常量、相机、暂停、交付等短任务。
- 6 个健康控制：使用已验证正确 fixture，要求检查后原样交付。

目的：纠正当前全难题偏向，补足正确停止与最低充分操作。

### B · 真实失败修复批次（约 02:00–03:30）

优先从现有失败工作区创建新 trial，而不是重新跑同一个生成 prompt：

- 凸轮冲压不足、轨道对接取景、双臂交接初始化、波干涉暂停。
- 提花机换卡、石拱/船闸初始化、铁路道岔、纸盒折痕。
- Qwen 真实失败及旧种子中证据充分的故障。
- CCORE 单缺陷派生补足到 16 题。

每题先做 fixture 预检：坏版必须被目标断言拒绝；能找到原好版时，好版必须通过。失败原因属于模型能力才进入教师队列。

### C · 新机制与交互批次（约 03:00–05:00）

从 research 的新机制继续扩展，避免当前题换皮：

- 多阶段装配/拆卸及中途可行性。
- 真实输入改变后的状态分支与复位。
- 时序、接触、支撑、遮挡和镜头联合约束。
- 合格控制分支，验证模型不会无故修改。

优先原创程序化场景和 CCORE 可运行源码；独立 test 的不同家族提前冻结，不反向派生训练变体。

### D · 覆盖补齐批次（约 04:30–06:00）

根据 A–C 的真实结果补机制与类型，不按数量机械补难题：

- 合格率低时优先中等、简单和健康控制。
- 某一家族或断言系统性失败时暂停该族，修 fixture，不刷模型失败。
- 只有当 A–C 已产生足够多合格轨迹时，才启用额外难点题簇。

若合格轨迹已达到今晚验收处理能力，可提前停止新增采集，把剩余时间用于复核。

## 验收与数据准入

技术候选必须同时满足：

1. 正常结束、正式交付、最终 HTML 真正自包含且可编辑源码齐全。
2. 独立浏览器检查与题目关键断言通过。
3. 查看实际关键帧；开放视觉任务保留连续视频供复核。
4. 原始流工具调用/返回一一对应，图片保留在真实轮次。
5. 能看出有效观察、定向修改和同项复验；健康控制则证明检查后正确停止。
6. 无失控重复、无图视觉结论、预算外运行或未解决交付契约问题。

失败轨迹只进入诊断/负例池，不混入正样本。技术候选仍需后续连续视频、语义复核和 OpenAI/Swift 验证，不能因检查通过直接称为训练成品。

## 并行与止损

- Kimi 默认 16 并发；若限流、网关错误或异常率明显升高，降到 8 或 4，不继续消耗额度盲目重试。
- 单题墙钟上限 3600 秒；超时保留工作区，不无限补跑。
- 配置/基础设施失败允许有界补跑 1 次；模型质量失败不反复采样。
- 不覆盖已有 trial，不为腾资源停止他人任务。
- 系统性 fixture/检查器问题超过本波约三分之一时暂停该波，先修题再决定是否继续。
- **06:30 后不再开启新 case，07:00 起只读收割，08:00 前形成报告。**
