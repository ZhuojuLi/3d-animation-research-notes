## 对齐

已有万级 one-shot 主要改善代码完整性和生成速度，不能替代复杂长程任务中的理解、行动、观察、修正与交付。当前最缺的不是更多简单 HTML，而是**中等思考强度下，真实多轮 ReAct 轨迹**。

教师数据保留原始 thinking、assistant 正文、tool calls/results、实际图片、工作区和最终验收。首版不改写思维链，不做特殊权重矩阵；输入保留真实工具反馈，监督有效 assistant 决策。明显空转、重复和错误失败轨迹不作正样本。

## 首批立即运行

`evals/react-v1/` 先跑 4 道新的长程生成题：挖掘机挖装、火箭分级任务、双机械臂工厂分拣、四冲程发动机。它们要求多阶段状态、对象关系、相机事件可读性以及真实浏览器验收，不再只是“出现一个模型”。

Qwen 原生 BF16 medium/256K 与专用 Kimi medium 在同一通用 Claude Code 沙盒中配对运行。Kimi 并发 2，Qwen 单并发。教师采集不为获得更好结果反复采样；配置错误有界补跑，质量失败保留。

同步准备 Qwen 实际失败接管和局部编辑题。优先使用真失败工作区、真实构建/离线/确定性错误和单缺陷状态，而不是继续堆简单生成。

## 轨迹价值门槛

1. 最终离线交付、独立浏览器检查及任务关键断言通过，实际画面可接受。
2. 能指出任务难点、实际观察、对应修改和同项复验，而不是只有最终代码。
3. 优先包含有意义的“构建或检查失败 → 定位 → 修改 → 复验”循环；不要求人为制造循环。
4. 保留实际 thinking 和工具链；明显重复空转、无图视觉结论、预算失控和未交付不收。
5. Qwen 容易而教师同样一次通过的题降低优先级；Qwen 失败而 Kimi 能完成并复验的题最高优先级。
6. 修复/编辑还要检查非目标状态保持，隐藏 test 使用不同场景家族。

先收割这 4 题的完整轨迹和成本，再扩展后续 200 个 case；不等待长期方案再次讨论后才启动教师队列。
