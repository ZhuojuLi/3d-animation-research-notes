# 千条级 ReAct 候选轨迹采集与数据组成（执行版）

> 公开整理版 · 2026-11-25。保留成文时点的记录；计划、文献结果和本地实测请分别理解。 环境路径已泛化，未收录的附件已标注；发布范围见 [整理说明](../../../PROVENANCE.md)。

2026-11-22

## 目标调整

用户明确要求不再逐波人工推动，今晚用持续队列和高并发形成大规模候选轨迹。执行目标为：

- 现有 16 个长程 case 的 trial-2/3/4：**48 条原始轨迹**。
- Astra 新设计 320 个 train case，每题 3 条独立轨迹：**960 条原始轨迹**。
- 合计目标：**1008 条原始候选轨迹**。

这些是候选池，不是上千个独立 case，也不是上千条可直接训练的成品数据。

## 调度方式

- Kimi 使用 `scripts/run_claude_collection.py`，不再等待用户逐波确认。初始规模化与 Aodi 两个队列各 **16 路**。用户随后明确允许 32 并发，已按归档和进程核验流程将规模化原队列安全切换为 **32 路**；Aodi 原 16 路队列已完成。没有启动第二个规模化采集器，实际并发以 `collection-planned.json` 和进程记录为准。
- 同一 case 的 3 次采样在同一工作单元执行，防止三个 trial 各 32 路形成 96 路。
- 全部 planned trials 预登记，已有 summary 跳过，支持断点续跑。
- 单题单轨迹最多 3600 秒；三次采样之外不为质量结果继续刷。
- 配置/基础设施失败单独分类，只允许有界补跑；系统性 fixture/checker 缺陷标 `invalid_case`，不记模型失败。
- 早期估计的“06:30 停开新 case、07:00 收割”不是全量完成保证。2026-11-22 03:18 的早段实测约为 36 条/小时（规模化）与 30 条/小时（Aodi），全量可能超过早晨。按当前全量目标继续保持既定队列，07:00 可先做阶段报告，最终报告必须等全部 trial 有最终记录或明确分类，不把提前收割称为全量完成。

## 最终训练数据组成

### 通用代码底座

- 10,697 条 answer-only train / 812 validation，负责 Three.js 场景与代码覆盖。
- Aodi 已训练的 step-900/step-2591 作为已有 one-shot 对照，不重复训练同一万条。
- 通用代码和 Agent 数据的混合比例按**有效监督 token**计算，不能按 case 条数计算。

### 新增 ReAct 候选池

按独立 case 约 40% 难点、30% 中等、15% 简单、15% 健康控制组织，保留生成、修复和局部编辑。

- 难点要求 Qwen 实败可重放、Kimi 可完成、独立断言能区分；未跑 baseline 的只能标 `prompt_complexity_only`。
- 健康控制要求检查后保持并交付，不能误改。
- 同一 case 默认只选 1 条主样本；只有解法或有效返修路径有实质差异时才保留额外汇本。
- 原始失败 trial 永久保留作诊断，不因三次采样中有一条成功就删除。

### 独立评估

按更新后的评估调研，dev/test 不混入这 320 个 train case：

- Agent dev：6 个新 family × 2 case = 12。
- Agent test：12 个新 family × 4 case = 48。
- 同源场景、模板、故障和教师轨迹形成谱系连通分量，先 split 再派生。
- 三次采样可估计稳定性，但主结果仍是 `Accepted@1`，不能用 `pass@3` 美化。

## 数据准入

每个主样本至少满足：

1. 正常结束、正式交付、真正自包含 HTML 与可编辑源码。
2. 独立浏览器检查和任务必要语义通过。
3. 修复/编辑的非目标状态保持。
4. 实际画面达到最低可读性，保留连续视频供复核。
5. 工具调用/结果完整，图片在真实轮次，原始 thinking 可追溯。
6. 能看出有效观察、定向修改和复验；健康控制则证明正确停止。

未经上述筛选的 1008 条只称为原始候选池。最终报告同时给原始轨迹数、技术候选数、语义验收数、独立 case/family 数和实际有效监督 token，不以运行量冒充训练数据量。
