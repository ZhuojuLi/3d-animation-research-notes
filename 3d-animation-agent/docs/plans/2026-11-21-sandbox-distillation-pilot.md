# Three.js 沙盒蒸馏首轮实验草案

> 公开整理版 · 2026-11-25。保留成文时点的记录；计划、文献结果和本地实测请分别理解。 环境路径已泛化，未收录的附件已标注；发布范围见 [整理说明](../../../PROVENANCE.md)。

2026-11-21。验证多轮操作轨迹能否在同一批教师成品的基础上，提高 Qwen3.8-27B 在 Claude Code 沙盒里的返修和交付能力。题单、样本量和后续消融根据试跑结果调整。项目对表（本地附件未发布） · [调研依据](../../../research/3d-agent-sandbox-distillation-20261120.md)

1. **采集。** 先用同一套 Agent、工具、题目、参考素材、初始工作区和预算跑原生 27B 与 Kimi。原生 27B 用来定位基模容易卡住的环节。对通过独立验收的 Kimi 运行，配对保留最终可运行交付和完整轨迹。单文件题可保留 JS，多文件题保留实际所需的 HTML、源码和素材。记录每轮工具调用、返回、实际可见的图像或文字观察、文件改动、复验和正式提交。失败运行另用于诊断。
2. **训练。** 两组从同一个原生 27B checkpoint 出发，使用同一批通过验收的 Kimi 任务。one-shot SFT 学从题目、参考素材、初始文件直接产出最终源码或补丁。多轮 SFT 学同一批教师运行里的读写、构建、检查、返修、复验和提交。尽量对齐训练设置，记录样本数、步数及训练 token。
3. **观察与思考。** 图片随模型真正看到它的那一轮记录。文本试点让教师和学生使用同样的执行反馈和视觉工具文字观察。教师推理原样归档，首轮多轮组以行为监督为主。短决策说明、原样推理和原生图片训练在后续单独比较。短说明只引用当轮已有证据。
4. **题集。** 按原始场景、素材和任务模板家族划分训练、开发和隐藏测试。源自同一案例的改写、镜头和故障变体放在同一侧。简单题测基本交付，中等题重点测能否用反馈修复接缝、裁切或时间轴问题，困难题测多零件装配、镜头和交互等组合要求。生成、修复和局部编辑都要覆盖。
5. **评测。** 在开发集选定配置和 checkpoint 后，让原生 27B、one-shot SFT 27B、多轮 SFT 27B 和 Kimi 在同一冻结沙盒跑同一批隐藏题。评测时两组学生都拥有完整工具和相同的迭代预算。按题配对报告正式交付、技术与任务断言、返修成功、连续视频盲评，以及每次成功的耗时和 token。按难度和任务类型拆开看，重点关注多轮组能否更常修对并交付，以及简单题是否回归。Kimi 的成绩用作参照。

## 试跑范围

先冻结精简的 Claude Code 沙盒，用一对好坏动画验证检查器，再用两张不同的图验证会话回放。首批暂按 12 道采集题估算，生成、修复和局部编辑各 4 道，优先选择可测时序或几何的任务，加入几道确实需要看图的题。每道 Kimi 运行一到两次，保留前后产物、可见前缀、接受理由和失败统计。先看轨迹能否重放、每次合格交付的成本和失败分布，再决定是否扩大采集和训练。开发与隐藏测试使用另行留出的题簇。
