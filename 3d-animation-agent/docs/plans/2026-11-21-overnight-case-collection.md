## 1. 今晚目标与边界

目标分为两个阶段：先用 12 道种子题验证采集、重放、筛选和成本；达到放行条件后，在夜间预算内扩展到累计 48–60 道独立题簇，并争取获得约 25–40 条通过验收的 Kimi 轨迹。原生 Qwen3.8-27B 与 Kimi 始终在同一精简 Claude Code 沙盒中使用相同题目和预算。12 道只是探针，不是最终训练集；扩展数量须由实测 medium 成本和合格率决定，不靠重复轨迹凑数。

- 生成、修复、局部编辑各 4 道。
- 两个模型均使用 medium；这是用户为控制思考时间选择的折中，不再重新论证档位。
- xhigh 不进入批量队列，可在已有结果中保留质量参照。
- 不使用专用 3D Harness，不限制创作流程；独立验收只评价最终产物和轨迹。
- 今晚不直接启动 SFT。训练前必须完成轨迹重放、质量筛选、数据格式和 loss 验证。
- 不覆盖历史运行，不读取或记录凭据，不把基础设施失败算成模型能力失败。

## 2. 启动前硬条件与可并行工作

### 正式队列的阻断条件

1. 冻结沙盒：CLI、工具面、system/Skill、任务挂载、依赖、浏览器、预算和输出协议有哈希清单。
2. 27B medium 推理与 Kimi medium 各通过一个短 canary；实际模型 ID、停止原因和用量能保存。
3. 能保存最终交付、原始流、每次请求、工具调用/结果、工作区快照及图片到达记录。
4. 12 题的 prompt、初始文件和验收断言存在；修复/编辑 fixture 已通过构建，单一缺陷已用反例验证。
5. 至少一对已知好坏动画通过检查器区分测试。

### 不阻断文本观察队列

- 原生图片进入训练的反向验证。
- 统计报告页面美化和正式大样本统计检验。
- 短决策说明、原始思考监督等后续消融。

原生图片若参与今晚运行，先用两张不同图验证请求中的图序、轮次和哈希；未通过时相关 case 只能使用固定视觉工具的共享文字观察，不能假装模型看到了像素。

## 3. 十二道采集题

所有 fixture 都必须是本轮新建的、经过构建验证的最小场景。修复题从合格 fixture 制造一个明确缺陷；局部编辑题先保存合格基线及逐时刻状态。不得依赖今晚尚未生成的 Kimi 成品作为启动输入。

### A. 生成 4 道

| case_id | 场景与任务 | 关键行为 | 最小独立验收 |
|---|---|---|---|
| `gen-watermill-loop` | 简单。程序化水车磨坊，6 秒循环；水车持续旋转、水流持续运动，宽镜头始终覆盖磨坊、水车和水道。 | 完成几何、绝对时间动画和循环。 | 水车角速度非零；水流状态随时间变化；首帧已运动；首末与接缝速度检查；关键对象投影不越界；最终看图确认水车/水道关系清楚。 |
| `gen-rocket-sequence` | 中等。8 秒非循环火箭装配、点火、升空；各阶段顺序明确，尾焰只在发射阶段出现，升空后位置持续上升。 | 多阶段时间编排与状态切换。 | 阶段顺序正确；点火前无尾焰；发射后高度单调增加；非循环不回到初始状态；关键时刻与末帧看图。 |
| `gen-solar-trackers` | 中等。6 块太阳能板随太阳同步转动，6 秒循环；使用实例或共享几何，所有板与太阳始终可见。 | 多对象同步、共享相位与实例化。 | 面板数量 6；法向/倾角随太阳相位变化且各板一致；首末一致；无面板互相穿插；正常播放与最终看图。 |
| `gen-conveyor-sorter` | 困难。传送带运送 6 个包裹，机械臂将包裹分到两个料箱；8 秒循环，接触顺序清楚。 | 传送、机械臂、接触事件与循环复位组合。 | 包裹数量与轨迹正确；机械臂只在接触窗口改变包裹轨迹；料箱归属正确；无非预期相交；接缝和全程取景；连续视频人工复核接触可读性。 |

### B. 修复 4 道

| case_id | 初始 fixture 与单一缺陷 | 需要的行为 | 最小独立验收 |
|---|---|---|---|
| `repair-ferris-seam` | 新建摩天轮 fixture；座舱运动正确，但末端角速度在循环接缝被人为置零。给源码和接缝文字测量。 | 定位时间函数而非重做场景。 | 接缝两侧位置与速度连续；其他对象和周期不变；修复前后同相位证据。 |
| `repair-arm-contact` | 新建机械臂/包裹 fixture；机械臂在抓取帧穿过包裹而非接触表面。给源码、碰撞测量或固定视觉工具观察。 | 将几何缺陷映射到关节/位置参数并复验。 | 接触窗口无穿透且抓取后同步运动；其他时段无新增碰撞；看图或共享视觉文字确认。 |
| `repair-rocket-framing` | 新建火箭升空 fixture；运动正确，但固定相机在末段裁掉火箭。给源码和投影越界报告。 | 修相机/取景，不改变火箭轨迹。 | 全时刻火箭投影在安全边界内；轨迹、速度、时长和尾焰时序不变；首末实际看图。 |
| `repair-solar-pause` | 新建太阳能场景；点击暂停后时间停止但渲染循环仍持续绘制。给源码和真实控件。 | 修复正常播放路径而非只修 `renderAt`。 | 真实点击后时间、像素和 draw count 均保持；恢复后继续；其他运动不变。 |

### C. 局部编辑 4 道

每题除目标断言外，都用 fixture 的逐时刻对象状态证明非目标对象和运动未变化。

| case_id | 编辑要求 | 保持不变 | 验收重点 |
|---|---|---|---|
| `edit-watermill-camera` | 仅把水车场景相机方位改为右侧约 30°，保持原循环与全部运动。 | 几何、水车、水流、时长、光源。 | 相机角度变化符合要求；对象轨迹逐项一致；新视角无裁切。 |
| `edit-rocket-ignition` | 仅将火箭点火时刻从 4 秒提前到 3 秒。 | 装配、尾焰持续规则、升空轨迹、相机、时长。 | 只在指定阶段边界发生时序平移；其他时刻状态一致。 |
| `edit-solar-material` | 仅把 6 块面板从深蓝改为指定的青蓝色，保留其余材质。 | 面板数量、追日运动、太阳、地形、灯光和镜头。 | 材质目标变化；全部几何与逐时刻状态一致；最终看图无意外曝光。 |
| `edit-conveyor-arm` | 仅反转机械臂分拣动作的旋转方向，并保持包裹仍能进入原来两个料箱。 | 包裹轨迹、传送带、接触时刻、料箱、相机。 | 臂角速度方向反转；包裹最终归属和时序不变；无新增穿插。 |

### 覆盖说明

- 简单/中等/困难均有；循环与非循环、单对象与多对象、几何接触、相机、真实控件和保真编辑均覆盖。
- 修复题测“反馈→定位→修改→复验”，局部编辑题测非目标保持，生成题测完整场景与时序。
- 首轮不专门加入角色骨骼、复杂 GLB、滚动叙事或大规模粒子；这些留给后续 OOD，不在今晚增加 fixture 风险。
- 每题最终都需要实际看图或连续视频复核；自动探针只证明对应断言，不给艺术质量打分。

## 4. 夜间双队列

### 并行准备轨

- 轨 A：冻结沙盒、检查器好坏反例、图片回放测试。
- 轨 B：编写 12 题 prompt、fixture、断言和 manifest。
- 轨 C：检查 Kimi API 当前模型与 27B medium 推理服务，验证输出捕获。

A/B 未完成对应 case 不得进入正式队列；C 是全部正式运行的阻断条件。

### 模型队列

- **Qwen 队列**：27B + medium，12 题各 1 次。先单并发，确认显存、吞吐和进程清理后才升至 2。
- **Kimi 队列**：当次实际可用 Kimi + medium，12 题各 1 次，默认并发 2。与 Qwen 队列使用不同资源时可并行。
- 两队列共同使用 `gen-watermill-loop` 和 `repair-solar-pause` 作为采集 canary；确认轨迹可重放、交付和用量齐全后再放行其余题目。
- 推荐顺序：`G01 → R04 → R01 → E03 → G02 → E01 → R02 → E02 → R03 → E04 → G03 → G04`（对应上表 ID），保证生成/修复/编辑尽早都有结果。

### 种子通过后的扩展队列

- 12 道种子题完成后，先核对轨迹重放、实际 medium 成本、教师合格率和失败分布；采集格式或检查器存在系统性问题时暂停扩展。
- 扩展题必须来自新的题簇，继续覆盖生成、修复和局部编辑。不得把既有题目只换颜色、对象名或镜头后重复计数。
- 放行后以累计 48–60 道为今晚目标，Qwen baseline 与 Kimi 都尽量覆盖同样的扩展题；若资源不足，优先保证同题配对，不保留无法配对的超额教师样本充数。
- 扩展阶段沿用相同沙盒、预算和验收。以约 25–40 条合格 Kimi 轨迹为采集目标，但实际数量由独立验收决定，不设人为放行比例。
- 每个扩展批次结束后重新估算剩余时间；达到夜间止损时间后停止开新题，保留完整队列状态供下次续跑。

### 止损与补跑

- 单题墙钟上限 60 分钟；预算、上下文和输出上限必须在运行前固定，超限时保留原始结果并停止。
- 基础设施/传输错误单独标 `infra_error`，修复后允许原样重试 1 次；不得记为模型质量失败。
- Qwen baseline 只对基础设施错误重试，不为了得到更好作品反复采样。
- Kimi 只有在“结果不合格但轨迹完整”或“可修复的运行失败”时补跑 1 次；所有题完成首轮后才进入补跑队列。
- 同一目标只允许一个写入者；新运行使用新工作区，不覆盖失败或历史版本。
- 06:30 后不再开启新任务，07:00 开始只读收割。medium 的真实吞吐尚未测量，以上是止损顺序而不是完成时间承诺。

## 5. 每个 run 必须保存

```text
case_id / case_version / family / task_type / split
sandbox_hash / cli_version / tool_schema_hash / prompt_hash / fixture_hash
requested_model / actual_model_reported / reasoning_effort / trial
workspace / initial_state_hash / final_delivery_hash / source_hash
raw_stream / requests / responses / tool_calls / tool_results / finish_reasons
每轮实际可见消息、图片路径与哈希、发送请求 ID、缺失或丢弃原因
raw_thinking（原样归档）/ visible_text / edits / rebuilds / checks / videos
status / stop_reason / infra_or_model_error / usage / wall_seconds

```

图片或思考缺失时保留事实，不根据最终 session 猜测恢复。排队、实际发送、成功接收和后续历史占位是不同状态。

## 6. Accept / reject

Kimi 轨迹进入候选训练集必须同时满足：

1. 正式交付且最终源码/产物/证据哈希一致。
2. 独立技术检查与题目必需断言通过；`unknown` 不自动算通过。
3. 人工打开实际截图或连续视频并确认可接受。
4. 轨迹完整可重放，工具调用和返回顺序正确。
5. 没有无图视觉结论、明显无效重复、超长失控或预算外运行。
6. 有明确接受理由和对应证据。

失败轨迹保留作诊断、修复 fixture 或后续负例，不直接混入正样本。未交付候选、基础设施失败和模型质量失败分别统计。

## 7. 明早收割与训练准入

汇总每行一个 run：case、模型、trial、正式交付、技术通过、任务断言、视觉接受、返修成功、时间、token、截断、基础设施错误、轨迹重放、接受/拒绝原因。

进入 one-shot/多轮 SFT 前至少满足：

- 12 题的原始记录、prompt、fixture 和检查版本齐全。
- 至少 8 条 Kimi 候选通过全部筛选，且生成/修复/局部编辑各不少于 2 条。
- 所有入选轨迹可重放；one-shot 与多轮使用完全相同的入选任务集合。
- 文本观察或原生图片的数据格式、loss mask、EOS 和来源 manifest 验证通过。
- 若不足，先补 cases 和采集，不靠增加 epoch 或重复同题轨迹掩盖数据不足。

明早人工必须实际打开所有入选作品，并抽查失败作品；不能只读 Agent 自审或汇总分数。

## 8. 今晚暂不做什么

- 不跑 xhigh 批量。
- 不引入专用 Harness、复杂 OOD 或大矩阵。
- 不改写教师思维链作为首轮训练目标。
- 不在数据未验收时启动 LoRA/全参训练。
- 不把今晚 12 题同时用作最终隐藏 test；dev/test 需要另行留出的题簇。
