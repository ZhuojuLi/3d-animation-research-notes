# 3D Agent 数据构造复盘：主调研方独立报告

> 公开整理版 · 2026-11-25。保留成文时点的记录；计划、文献结果和本地实测请分别理解。 环境路径已泛化，未收录的附件已标注；发布范围见 [整理说明](../../PROVENANCE.md)。

日期：2026-11-23。本报告在读取 Fable 结论之前完成。训练已由其他 AI 启动；本轮只读复盘，不修改训练或项目生效决定。

## 结论速览

1. **首版已经具备真实的多轮教师数据，不应推倒重来。** 249 条最终 ReAct 候选有完整工具链、2,546 张实际图片和 15,722,203 个监督 token，格式、loader/template 与实际 EOS 均通过验收。
2. **最大的设计偏差是难度标签。** 最终 249 条的难度均只是 prompt 复杂度或来源标签，没有一条能据此称为“Qwen 可重放失败难点”。它们适合训练复杂任务处理，但不能证明精准补齐学生失败边界。
3. **最终数据以生成为主，不是均衡的修复/编辑训练。** 生成 221、修复 23、局部编辑 5；这与最后采集计划的生成侧重一致，但与早期“修复和局部编辑占多数”的设想不同。
4. **三次采样选优提高了教师质量，也引入选择偏差。** 它适合造正样本，不代表教师或学生的单次成功率。不能用 `pass@3` 代替 `Accepted@1`。
5. **实际 loss 配方已偏离早期草案。** 早期写“首版不监督 thinking”，最终却使用 thinking 0.5、正文 1.0、工具调用 2.0。该配置可作为实验，但不能视为已验证最优或用户已确认的永久约定。
6. **下一版最高杠杆不是单纯增加 case，而是请求级捕获、学生失败驱动、独立评估和采集前置质量门禁。**

## 一手证据

### 1. 从运行量到最终样本的真实漏斗

| 队列 | 计划轨迹 | 技术候选 | 初审主候选 | 最终 Ready |
|---|---:|---:|---:|---:|
| 规模化 Kimi | 960（959 正常终态 + 1 用户中断） | 831 | 211 | 207 |
| Aodi Kimi | 576 | 88 | 43 | 42 |
| 合计 | 1,536 | 919 | 254 | 249 |

原始 320 + 192 = 512 个计划 case 全部是 train。最终 249 条对应 82 个来源内 family、237 个不同交付 HTML。规模化的 207 条只覆盖 40 个 family，说明它是有控制的题族变体集合，不是 207 个完全独立场景。

证据：`reports/overnight-collection-report-20261122.md`、`reports/sft-conversion-20261123-001/REPORT.md`、`training-candidate/final-distribution-002.json`。

### 2. 难度和任务类型偏差

规模化最终 207 条相对原计划：

| 难度标签 | 计划 case | 最终入选 | 入选率 |
|---|---:|---:|---:|
| hard | 128 | 89 | 69.5% |
| medium | 96 | 51 | 53.1% |
| simple | 48 | 44 | 91.7% |
| health_control | 48 | 23 | 47.9% |

全部最终记录的 `difficulty_evidence` 均为 `prompt_complexity_only`；Aodi 的 42 条也没有学生失败标签。因此“hard”表示题面复杂，不表示学生失败已重放。

最终任务类型为 generation 221、repair 23、local_edit 5。最后的规模化采集计划本来就安排 generation 256、repair 52、local_edit 12，所以这是计划与筛选共同形成的分布，不是转换阶段意外造成；但它意味着首版主要检验生成与交付能力，修复和局部编辑的证据较弱。

### 3. 质量门禁发现的实测问题

规模化 366 条质量排除中：

- 定帧后仍运动：209；
- 小视口可读性不足：136；
- 跨 trial 结果读取、复制或审计产物访问：21。

前两类占 94.3%。这说明仅运行基础 checker 不够，也说明墙钟稳定性和 640 视口可读性可以在采集阶段更早自动检查，减少后续审核负担。

既有评估联合调研还指出：320 个规模化 train case 的 1,312 条断言全部读取模型自报 `s.*`；64 个 case 的 128 条断言在采样时刻不匹配时直接 `return true`。这些断言可以提供训练反馈，但不能独立证明真实对象、画面或物理语义正确，更不能直接作为隐藏评估。该结构问题不能换算成最终正例的错误率，最终样本仍需逐题做独立语义验收。证据：`research/3d-agent-evaluation-system-20261122/README.md` §2C。

转换阶段又排除了三条超长 thinking 和两条续跑上下文不完整记录。多会话 stream 的最后段选择正确仍不够：教师回答引用未捕获历史时，必须排除独立训练资格。

最终正例保留 396 次 `is_error=true` 工具反馈。失败操作后修正属于 ReAct 正例的一部分，不应误删；但失败轨迹整体未交付或质量不合格仍不能混入正样本。

### 4. Kimi 采集成本与检查器使用

最终入选轨迹的 wall time：

- 规模化中位数约 1,265 秒，p90 约 1,821 秒，最大约 3,123 秒；
- Aodi 中位数约 1,145 秒，p90 约 1,897 秒，最大约 2,629 秒。

medium 是推理档位，不是长度上限。仍有三条单段 thinking 超过 32,768 token，且最终完整序列有 167 条超过 64K、最大 171,524 token。下一版需要控制无效思考和超长读取，而不是把 medium 当成成本保证。

最终 249 条中，只有 1 条直接引用通用 `check_claude_case.mjs`，3 条引用 `case.json`，1 条引用 `check.json`。因此没有证据支持“教师普遍直接读取公共检查器”。更实际的风险是教师自写验证覆盖不足，需要独立隐藏测试，而不是禁止正常的测试驱动行为。证据：`teacher-checker-access.json`。

### 5. 配比和 loss 口径

最终 ReAct 监督 token：

| 段 | 原始 token | loss_scale | 加权后 token |
|---|---:|---:|---:|
| thinking | 9,006,875 | 0.5 | 4,503,437.5 |
| 正文 | 305,799 | 1.0 | 305,799 |
| 工具调用 | 6,409,529 | 2.0 | 12,819,058 |
| 合计 | 15,722,203 | — | 17,628,294.5 |

工具调用参数包含大量代码，所以“工具调用加权”同时也在给代码加权，不能全部解释为 Agent 行为学习。

若只用 Aodi 的 127,463,249 个可见 answer-only assistant token 作近似分母，ReAct 未加权自然占比约 10.98%，加权后约 12.15%。这不是最终训练梯度占比：Aodi 分母不含完全相同的 EOS/模板口径，实际还受记录采样、epoch、batch reduction 和 optimizer 影响。该数字只用于暴露口径差异，不替代训练日志。

早期 `2026-11-21-simple-first-sft.md` 写“首版不作为监督目标”指 thinking；最终配置来自 swift-preprocess 的 thinking 0.5/content 1/tool 2。复盘时必须确认正在运行的训练实际采用哪个配方。

### 6. 训练/推理一致性与评估边界

- 历史 stream 没有完整 system、工具 schemas 和逐次请求；`tools=[]` 是未捕获，不是教师没有工具。
- normalize 插入默认 system，不等于 Claude Code 教师原文。首版可把它作为探索性限制，但下一版应捕获消息拼装、压缩和图片到达后的真实请求。
- 当前 512 个 case 全是 train，Qwen 只有四题 baseline。不能据此声称“复杂任务成功率显著提升”。
- Aodi one-shot 与 ReAct 的 26 个实际配对画面里存在互有胜负；ReAct 不是在每个场景都更好。one-shot 底座仍有价值。
- 连续视频、完整语义、语义级 token 区间 mask 映射和 Megatron 训练 smoke 不属于本次格式通过的证明范围。

## 迁移推论与项目建议

### P0：直接影响结果可信度或训练/推理一致性

1. **冻结并核对实际训练配方。** 记录真实输入文件哈希、thinking/tool 权重、曝光、epoch、有效 token 和 checkpoint 起点。验证正在运行的配置，而不是根据 Ready 目录推断。
2. **补齐请求级捕获并跑文本/双图 canary。** 保存实际 system、工具 schemas、压缩后的消息、图片哈希和丢弃原因；下一版训练与评测使用同一条消息契约。
3. **先校准检查器，再冻结独立题族 dev/test。** 用 good/mutant/alternative/healthy 和伪造状态包验证检查器能拒绝坏版，覆盖题面必要项；按源场景、fixture、模板和故障谱系先 split 再派生。用相同 harness/预算比较原版、Aodi-only 对照和混合学生，主指标用 Accepted@1、非目标保持、健康误改、可读性及成功成本。

### P1：提高下一版教师数据的针对性与采集效率

4. **从学生真实失败构造难点。** 新增 `student_failure_reproduced` 证据字段，与 `prompt_complexity_only` 分开。优先选择“学生可重放失败、教师可完成、独立检查可区分”的修复和局部编辑任务。
5. **把定帧、640 可读性和跨 trial 隔离前移。** 采集后立刻自动验收；不同 trial 使用真正不可互访的目录和临时根目录，而不是只靠提示词声明独立。
6. **控制长上下文成本。** 保留 medium 作为起点，但监控单段 thinking、总序列和无效读取；优先减少重复读取与无效操作，不让另一个模型自由改写教师思维链。

### P2：增加多样性和后续训练选项

7. **扩大题族而不是只扩同族变体。** 保留 controlled variants 做机制覆盖，同时增加新场景、新交互和新故障；对 one-shot 已更强的场景不强行改成 ReAct。
8. **保留失败池用于诊断或后续偏好训练。** 当前不把失败轨迹塞进正样本 SFT；只有完成且审核通过的整体轨迹中的纠错反馈保留。

## 首版结果应如何解读

- 若执行率提高，可能来自 Aodi 通用代码底座，不应全部归因于 ReAct。
- 若复杂生成改善而修复/编辑不变，符合当前 221/23/5 的任务分布，不应意外。
- 若 hard 标签上改善，也只能先说明复杂题面改善；没有学生失败基线时不能声称“原本不会的题现在会了”。
- 训练 loss、pass@3、教师 best-of-3 入选率都不能替代学生的 Accepted@1。
- 首版可以回答“这种数据配方是否出现积极信号”，不能单独证明最优比例、完整思维链价值或长程 Agent 能力已经解决。

## 未知项与证据边界

本轮没有读取或修改其他 AI 正在运行的训练配置，因此其实际数据子集、训练长度、epoch、学习率和资源状态均不在本报告结论内。没有新增模型运行、浏览器验收或外部论文检索；所有结论来自本地原始报告、case JSON、Ready/provenance 和实际转换验收文件。
