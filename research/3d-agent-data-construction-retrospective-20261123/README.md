# 3D Agent 数据构造与 Kimi 教师采集：联合复盘

> 公开整理版 · 2026-11-25。保留成文时点的记录；计划、文献结果和本地实测请分别理解。 环境路径已泛化，未收录的附件已标注；发布范围见 [整理说明](../../PROVENANCE.md)。

2026-11-23。主 Agent 先完成[独立报告](main-report.md)，随后读取 [Fable 独立报告](fable-report.md)并抽查关键新发现。训练由其他 AI 运行；本复盘不修改训练配置或项目生效决定。配比与 loss 的专项联合调研另见 `research/3d-agent-sft-mix-loss-20261123/`。

## 结论速览

**首版数据工程链路是通的，但数据分布、教师采集契约和训练归因都有明显限制。下一版不应从“再跑更多 case”开始，而应先修题面/检查器/沙盒/请求捕获，再按学生真实失败造数。**

最重要的结论：

1. **249 条最终 ReAct 候选有真实价值，但不是 249 个独立、经验证的学生难点。** 它们只有 82 个来源内 family，难度均只是 prompt 复杂度；完整语义和连续视频尚未验收。
2. **真实缺陷修复为 0，局部编辑仅 5。** 任务表中的 23 条 repair 全是健康控制，检查后不改。首版主要是生成、测量和交付数据，不是均衡的维修 Agent 数据。
3. **底座与 ReAct 教不同交付契约。** Aodi 底座是 CDN/r160/单轮代码，ReAct 是离线/r180/renderAt/写文件。需要通过 system 和任务上下文明确区分，否则可能互相抵消。
4. **教师轨迹含环境噪声。** Fable 实测 106/249 条含 257 次自动记忆文件写入；约 66% 的工具调用含采集机 case/trial 绝对路径。下一版应使用中性 `/workspace`、独立 Claude 配置并关闭自动记忆。
5. **质量门禁建立太晚。** 定帧、640 可读性、`file://` 单文件加载没有同时写入题面、fixture 预检和教师自检，导致大量本可避免的采集与审核成本。
6. **首版不能单独证明 ReAct 有效。** 当前训练没有同超参 100:0 底座对照；学生评测必须看 Accepted@1 和独立题族，不看教师 pass@3 或训练 loss。

## 双方共识、分歧与最终取舍

### 一致结论

- 难度标签没有学生失败证据；下一版难点必须来自可重放的学生失败。
- 生成占 221/249，修复和局部编辑不足；健康控制应与真实修复分开计数。
- 同题三次采样用于选优和稳定性分析，不代表三次独立 case，也不能替代 Accepted@1。
- 默认 system、`tools=[]`、未捕获的逐次请求和 compaction 是真实训练/推理差异。
- 最终 249 条是格式、loader/template 合格的候选，不是完整语义批准的数据。
- 失败工具反馈可以是有价值的 ReAct 上下文，但整体失败的轨迹不能混入正样本。

### Fable 带来的新增证据

- 真实 `fix-*` 最终为 0；23 条 repair 与健康控制完全重合。
- 161/211 个主候选的选择理由为 `lowest_wall_seconds`，存在偏向短轨迹的方向；这与长程返修目标有张力。
- 多个健康/编辑 fixture 自身存在定帧漂移，教师正确保持原样也会失败；这些题本应在开跑前被预检拦截。
- Aodi 的 480 条模块/CORS 失败横跨 scenes-v1/v2/GLB，不是 GLB 特有问题；题面未明确 `file://` 契约，应归为任务/检查器契约缺陷，而非模型能力。
- 正在运行的首版训练实际为 16×H800、180,224 长度、10,946 步、batch=1、1 epoch；ReAct 为 249/10,946 = **2.27% 的更新步机会**。
- 项目已冻结 60 题 holdout-v1（dev 12、test 48），但浏览器基线仍 pending，且其短英文题面、函数检查和修复公式公开等协议与训练分布不同。

### 主 Agent 的补充与核验

- 最终 ReAct 的 thinking/content/tool 监督位置分别为 9,006,875 / 305,799 / 6,409,529；加权后为 17,628,294.5 token。
- 工具参数包含大量 Write/Edit 代码，因此 tool ×2 同时也是代码加权，不等于纯 Agent 决策加权。
- 最终 249 条只有 1 条直接引用通用 checker；公共检查器直接读取不是普遍现象，更大的风险是自报状态和教师自写测试覆盖不足。
- 主 Agent 用较宽的路径字符串条件重算为 8,213/12,450 次调用含 Kimi trial 路径；Fable 的严格口径为 8,166。两者都约 66%，差异来自匹配条件，不影响环境泄漏结论。
- 自动记忆写入的 257 次、106/249 条已独立重算一致；真实修复 0、23 条健康 repair 和训练 batch/步数配置也已核对。

### 保留的分歧和不可过度解读处

1. **2.27% 是更新步机会，不是已证明的梯度占比。** batch=1、per-token loss、梯度裁剪和 Adam 会影响实际作用；不能把“每条更新量级完全相同”当作已证明事实。loss_scale 的精确归一化分母也需源码核验。该问题交给配比专项继续研究。
2. **Fable 对在线 loss 的观察只作探索性诊断。** 窗口均值、样本打散和单条 ReAct 损失推算仍有假设，不能据此宣称“模型没有学到 ReAct”。
3. **是否 mask 所有出错工具调用不是显然最优。** 语法/路径错误与不有效但有信息量的探索不同；可以按错误类型做对照，保留恢复动作，不能一刀切后宣称更好。
4. **“没有 holdout”已纠正。** ReAct Ready 自身确实全是 train；但项目已有独立输入层面的 60 题 holdout。缺的是基线运行、完整独立语义证明和同分布留出，而不是连题包都不存在。

## 下一版优先级

### P0：先避免白跑和错误归因

1. **同一份门禁贯穿题面、fixture 预检、教师自检和采集后验收。** 明确 `file://`、renderAt 后状态与像素冻结、640/1280 双视口；健康 fixture 必须先通过。禁止在已有 stream 的目录续跑。
2. **采集沙盒去标识化并捕获真实请求。** 使用 `/workspace`、独立 `CLAUDE_CONFIG_DIR`、关闭自动记忆、不加载个人 skills；保存真实 system/tools/压缩后 messages/图片到达记录。训练与推理模板逐 token 对照，并行 tool results 的轮次合并也要一致。
3. **先跑基线和对照，再决定下一批难点。** 原生、首版学生、Kimi 单次参照使用同协议；补同分布整族留出和 100:0 同超参底座对照。holdout 修复题不应把正确公式直接写给模型。
4. **冻结实际训练配方账本。** 同时报告记录数、更新步、输入 token、监督 token、loss 加权 token、每题曝光、batch reduction 和梯度裁剪；不要只写“Agent 占 10%”。

### P1：提高数据的针对性与效率

5. **用学生真实失败生成修复和局部编辑。** 好版/坏版/合理替代/伪造状态均预检；难点标记为 `student_failure_reproduced`，不再以题面复杂度替代。
6. **预先登记选样规则。** 默认第一条通过完整门禁的轨迹，或按质量而非最快时间选择；报告教师 Accepted@1 与“第几次才合格”，不把 best-of-3 当单次能力。
7. **把 thinking 和错误调用处理做成显式对照。** 比较 thinking 0 与 0.5，测超时和成功 token；错误调用按类型决定是否 mask，保留后续恢复。健康控制按 fixture 去重并控制过度审计。

### P2：补证据而非先扩量

8. 连续视频、独立语义和段级 token mask 映射只针对最终入选集补齐；保存角色/内容段到 token 区间。
9. 保留 one-shot 更强的场景，不为“全部 ReAct 化”而降低教师质量；GLB/Godot 等外围导入验证后排。

## 首版结果的正确读法

- 首版可证明 27B 全参数长序列、多图训练链路和工程恢复能力；不能单独证明 ReAct 配比有效。
- 如果变好，需要先排除万级代码底座的作用；如果没有变化，也不能否定 ReAct，因为更新步剂量、契约冲突和超长监督都可能解释。
- 重点记录 Accepted@1、超时、输出 token、CDN 引用、只贴代码不写文件、训练集特有路径/记忆调用、非目标保持和健康误改。
- 不引用“249 个独立难点”“ReAct 梯度占比 12.14%”“教师 66% 就是单次能力”等说法。
