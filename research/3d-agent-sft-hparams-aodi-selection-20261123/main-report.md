> 公开整理版 · 2026-11-25。保留成文时点的记录；计划、文献结果和本地实测请分别理解。 环境路径已泛化，未收录的附件已标注；发布范围见 [整理说明](../../PROVENANCE.md)。

2026-11-23。只读审计现有配置、数据与公开资料；未修改正在运行的训练，未启动新训练、模型服务或全量浏览器任务。

## 一、直接结论

1. **首版有完整且经过 smoke 的工程配置，但没有形成行为导向的超参数证据。** `1e-6`、约 3% warmup、cosine、Adam 默认项、视觉冻结等主要沿用 Aodi 旧 run；batch、归一化窗口和数据已经变化，不能把“旧 run 能训练”当成“新 run 已调优”。
2. **当前最值得先补的是 checkpoint 行为选择和纯 Aodi 对照，不是大规模网格搜索。** Aodi 旧实验 step-900 技术通过 21/30，step-2591 为 20/30，且各题型有得有失，已经直接否定“最后一步自然最好”的假设。
3. **没有证据证明一万条必须全部等权使用，也没有证据支持主观砍掉一批。** 全量 11,509 条 train+validation 中，prompt/answer 原文及规范化精确重复均为 0。真正的问题是三源任务契约、短 GLB 题面的占比、标题变体权重、版本依赖和运行质量，而不是大量完全复制。
4. **建议保留全量池和全量对照，同时构建覆盖约束的分层核心集。** 先比较“同规模随机核心 vs 分层核心”，再比较“全量单遍 vs 核心集重复到同预算”。前者检验筛选策略，后者才回答剩下的数据是否值得保留。
5. **若只有再跑一版的预算，不应把未经对照的精选集当成默认更优。** 先完成当前模型与纯 Aodi 对照；若能做短跑，再用固定数据流比较 `1e-6` 与一个更高学习率，而不是直接采用其他论文的数值。

## 二、训练参数审计

实际入口：`3d-animation-agent/reports/first-sft-20261123-001/launch.sh`；运行参数：`${SHARED_DATA}/3d-agent-sft/first-sft-20261123-001/start/output/args.json`。旧对照：`${REFERENCE_DATA}/code2video/training/runs/full-sft-64k-thinking-3node-001/launch.sh`。

| 参数 | 首版实际值 | 依据与缺口 | 后续优先级 |
|---|---|---|---|
| 模型与精度 | 原版 BF16 27B，全参数 LLM | 明确的任务起点；不是扫参结论 | 固定，作为各臂共同起点 |
| 视觉参数 | `freeze_vit=true`、`freeze_aligner=true` | 沿用 Aodi，降低显存与优化自由度；尚未证明对读图反馈最优 | 首版固定；若失败集中在读图，再单独解冻对照 |
| 最大长度 | 180,224，最长样本 171,524 | 为保留全部 ReAct 的数据覆盖选择，并有最长样本 smoke；不是“越长质量越好” | 保持。降到 64K 会删除 167/249 条 ReAct 和 80.46% ReAct 标签，是另一项数据实验 |
| 并行与重计算 | TP4/PP4/CP1/DP1，SP，全层重计算，TE 融合 CE | 主要由 16×H800、27B 全参和长序列显存决定；smoke 证明可运行，不证明吞吐最优 | 作为工程基线，不与数据/LR同时改 |
| micro/global batch | 1/1 | 长序列与流水线配置下的工程选择；同时改变梯度噪声和 loss 归一化窗口 | 不为提速直接改 batch=4；若改，单独重测 LR 与来源权重 |
| 更新数与 epoch | 10,946 步，1 epoch | 草案明确“先做一版、不做复杂消融”；不是 epoch 对照结果 | 比较保留的中后段/最终 checkpoint；下一轮保存 25/50/75/100% 行为评估点 |

| warmup | 328/10,946，约 3.0% | 与旧 run 80/2,591≈3.09% 一致，明显是沿用比例 | 与 LR 一起固定 warmup 比例和 decay horizon |
| Adam 与裁剪 | weight decay 0.1，β=(0.9,0.95)，ε=1e-8，`clip_grad=1` | 框架/旧 run 默认项，没有专项研究 | 记录裁剪和实际更新，不仅看 train loss |
| loss 权重 | thinking/content/tool=0.5/1/2 | 有旧配置参考和模板验证，无当前任务行为对照；`Write.content` 单项占 ReAct 权重和 47.38% | 等失败分类后做窄字段对照，不先扫全矩阵 |
| 数据顺序 | 固定种子 20261123 预打乱，loader shuffle=false | 可复现；ReAct 在四个顺序四分位分别为 71/44/61/73，非严格配额交织 | 对照臂按 UUID 与来源配额固定，不把顺序差异混入结果 |
| 验证 | 812 条 Aodi code validation，最终步计算 loss | 能测代码预测，不测 Agent 行为；没有替代浏览器 dev | 每个候选 checkpoint 跑同一 Agent dev，最终 test 只确认 |

### 梯度裁剪的新证据

读取当时已有的 806 个训练记录点（iteration 1 至 8050），`grad_norm` 全部大于 1；最小 1.112、中位 1.826、p99 6.334、最大 14.628，而 `clip_grad=1`。这说明全局裁剪在日志点持续生效。**它不是 NaN 或训练失败证据，也不能单凭此判断 LR 过大或过小**；但后续分析必须把 LR、batch、Adam 和裁剪作为同一优化系统，而不是孤立解释某个数值。

### 与公开配方 correctly 的关系

[Tülu 3](https://arxiv.org/html/2411.15124v2) 对 SFT 学习率、epoch 和 loss 类型做过实验，并报告其 70B 配方为 2e-6、有效 batch 128、4,096 长度、2 epochs。可借鉴的是“在自己的数据和评估上选择”，不是把 2e-6 或 batch 128 直接搬到本项目的 27B、180K、batch=1 场景。该文还说明 sum/mean loss 需要配合 LR 重新验证。

## 三、Aodi 全量数据到底由什么组成

数据卡与 manifest：

- Scene-v1：MiniMax M3.1 Flash；41 个 train 领域；复杂度 1–10 是标注，不是学生失败率；每条有发布方参考图。
- Scene-v2：教师未知；50 个 train 领域；复杂度 1–8 是课程标注；validation 按概念 family 留出；每条有参考图。
- GLB：教师未知；40 个 train 领域，无复杂度标注；发布方声明全部渲染、导出并验证 GLB。Godot 导入和完整语义不是该声明的等价物。

### 全量静态审计结果

可复现脚本：`audit_aodi_corpus.py`；完整输出：`aodi-corpus-audit.json`。审计同时读取 10,697 train 与 812 validation。

| 项目 | Scene-v1 train | Scene-v2 train | GLB train |
|---|---:|---:|---:|
| 记录 | 3,933（36.77%） | 3,263（30.50%） | 3,501（32.73%） |
| 题面字符中位数 | 265 | 283 | **37** |
| 题面字符 p90 | 430 | 331 | 397 |
| 答案字符中位数 | 36,744 | 39,938 | 27,209 |
| 复杂度 | 1–10，各级约 383–399 | 1–8，课程标注 | 无 |
| voxel | 389 | 1,357 | 无此标注 |
| 完整 `</html>` | 3,933 | 3,263 | 3,501 |
| Three.js 契约 | 3,928 条检出 r160 | 全部 r160 core | 多版本，addons/GLTFExporter |
| 主要依赖 | cdnjs | cdnjs | jsDelivr 3,500，unpkg 1 |

**精确重复。** 11,509 条中，raw prompt、NFKC/空白/casefold prompt、raw answer、同规范 answer 的重复组均为 0，train/validation 精确交叉也为 0。因此没有“先删除大量完全相同记录”的空间。

**标题变体。** train 中有 267 个规范化重复标题组，全部来自 GLB，共 1,178 条；若每个标题只留一条会去掉 911 条，但这些记录题面与答案均不同。例如 Oak tree 的简短题面在 train，多个详细树干/树冠要求在 validation。它们可视为同主题变体并调整权重，不能标成复制样本。

**近重复边界。** 脚本使用 5-word shingles、32-permutation MinHash 和 LSH，候选对再以 Jaccard≥0.75 验证，只形成 9 个小组；实际例子主要是“Make/Create a standalone HTML…”共享模板，内容对象完全不同。因此该结果**不能用于自动去重，也不能证明没有语义近重复**。若要做语义去重，需要先去模板或采用内容感知嵌入，并人工校准阈值。

**异常命中不是坏数据标签。** 69 条 Scene-v2 没有代码 fence 但仍有完整 HTML；Scene-v2 的远程链接抽查主要是资料引用，不是远程模型资产；早期 8 条 Scene-v1 缺 system，其中可见 r128 老契约样本，适合列为版本异常复核。初版 `\bTODO\b` 忽略大小写把葡萄牙语 `todo`（全部/整体）误报 4 条，已修正为大小写敏感后重跑，不能将这些记录列为占位代码。

**已有运行证据。** 192 条原始样本按三源各 64 检查，189 条静态协议可运行；GLB 有效导出 62/64。该结果支持“语料不是未经验证的纯文本”，但每源 64 不足以覆盖全部领域、复杂度、长度、标题簇和版本，更不是当前离线 ReAct 协议的全量验收。证据：`reports/aodi-one-shot-static-browser-summary-20261122.json`。

## 四、是否全需要：支持与反对的真实理由

### 支持保留全量池/全量对照

- 没有精确重复，答案覆盖面真实存在。
- Scene-v1 复杂度近似均衡，Scene-v2 有 50 领域和概念 family 设计，GLB 有 40 领域与发布方导出验证；随意按“看起来简单”删除容易破坏这些刻意覆盖。
- Aodi 万级 one-shot 已把原生 2/30 提升到 step-900 21/30，证明整体语料具有领域价值，尽管不能归因到每一条。
- 简单、短题面可以承担基本几何、材质、相机、代码完整性和格式稳定，复杂 Agent 不是唯一训练目标。

### 支持分层、降权或核心集

- GLB 占 32.73%，题面中位数只有 37 字符，且大量同标题配置变体；如果目标是长程动画 Agent，自然记录配比并不等于目标能力配比。
- Scene core/r160、GLB addons/多版本、ReAct 离线/r180/renderAt 是不同交付契约，混合时需要明确上下文，必要时重平衡，而非无差别曝光。
- 192 条验收不能证明其余全部运行质量；机械完整性也不等于几何、动画和视觉语义正确。
- 当前 batch=1 的逐样本归一化使每条记录都有更新机会，但长 ReAct 与短 Aodi 的计算和监督结构不同；单纯按记录数“全收”没有解释目标预算。

### 不能支持的结论

- 不能说“删除 20%/50% 一定更好”。
- 不能只保留 level≥7；这些 level 不是 Qwen 实测难点，且会造成领域与基础能力偏差。
- 不能把 GLB 全部删掉；它提供经验证的部件、资产和动画先验，应与 Godot/GLB 专用目标分开加权。
- 不能把标题相同或模板相近的记录直接当重复。
- 不能用 LIMA 的 1,000 条证明本专业代码任务只需 1,000 条；[LIMA](https://arxiv.org/html/2305.11206) 研究的是强底座上的通用对齐、风格与指令遵循，不是 Three.js 领域代码覆盖。

## 五、可执行的数据分层方案

原始池永远保留，以下状态写入新 manifest，不改原文件：

| 层 | 准入规则 | 用法 |
|---|---|---|
| 覆盖保留 | schema/完整 HTML 通过；按 source×domain×level（有标注时）×长度×版本记录；稀有层优先保留 | 全量对照和核心集共同候选 |
| 运行复核 | 缺 system、旧版本、无 fence、外部加载/API、结构异常，以及每个分层抽样单元 | 运行失败才排除或替换，字符串命中本身不删除 |
| 变体降权 | GLB 规范化标题簇，保留不同配置；抽样时限制单簇权重 | 避免 Oak tree 等同主题变体主导核心集 |
| 契约分组 | Scene core、GLB export、ReAct offline 分开记录 system/依赖/版本/交付要求 | 通过上下文明确任务，不用静默改写答案制造“统一协议” |
| 排除 | 实际浏览器/导出失败、截断、无完整交付，或与目标许可证/安全要求冲突且无法修复 | 保存原因和证据，不靠主观难度排除 |

运行审计不要只按三源抽 64：至少覆盖全部 **131 个 source×domain** 单元和 Scene 的 **18 个 source×level** 单元，再按题面长度、GLB 标题簇和版本补样；小单元全取或优先取，大单元随机抽样。所有静态异常进入复核集。记录每层失败率及置信区间，不能把抽样失败率直接外推为全量精确失败数。

## 六、下一轮最小实验路线

### P0：不训练，先让当前 run 产生可解释结果

1. 同一 harness、解码、时间和 token 预算，对原生、当前保留的中后段 checkpoint、最终 checkpoint 做 Agent dev Accepted@1。
2. Aodi step-900/2591 作为已有参照，但区分 one-shot 与 Agent 协议，不把它们当同配置纯 Aodi 对照。
3. 主指标按题族宏平均，记录目标成功、非目标保持、CDN/只贴代码、非法工具、超时、成功耗时与 token。dev 用于选，48 题 test 保持锁定。

### P1：必须补的归因对照

**Full-mixed vs Full-Aodi。** 同一原版、同一 UUID 顺序位置、batch=1、长度、LR schedule 和总更新数；纯 Aodi 臂在原 ReAct 槽位替换为预先固定的 Aodi 样本。这样回答“加入 ReAct 的净效果”，同时如实记录纯臂多出的 Aodi 曝光。没有这项，当前混合版的变化无法与万级代码底座分开。

### P2：学习率只做 coarse probe

在同一 25% 固定数据流上比较 `1e-6` 与 `2e-6`，warmup 比例、decay horizon、batch、裁剪、UUID、ReAct 配额完全相同；比较 50% 与 100% checkpoint 的 dev 行为。2e-6 只是对当前峰值的倍率探针，不是文献推荐最优值。差异小于预注册门槛就视为难分并保留当前值，不在 12 题 dev 上反复扫到“碰巧赢”。若改变 global batch，必须另开优化实验，不能沿用这项结论。

### P3：Aodi 筛选分两步回答

1. **随机核心 vs 分层核心，同规模、同更新预算。** 从 train 内固定 K 条，随机臂保持自然来源分布；分层臂覆盖 source/domain/level/长度/版本并限制标题簇权重。两臂使用同一 ReAct UUID、优化器和 LR schedule。它回答“筛选规则是否比随机更好”。
2. **全量单遍 vs 胜出的核心集重复到同预算。** 固定与全量对照相同的 Aodi 更新数、ReAct 槽位和 LR schedule，核心集可重复多次，记录每 UUID 曝光。它回答“为了同算力下的行为表现，是否需要全部一万条”。如果核心重复更好，说明全量不是必须；如果全量更好，说明独特覆盖或较少重复有价值；如果分层核心只在第一步赢、第二步不赢，则不能把筛选收益与重复/覆盖效应混为一谈。

短跑胜出的配置才进入全预算确认。若 P2 改用了新 LR，旧的全量 run 不能无条件充当 P3 的同配方对照，需要补相应 full reference。

### P4：最后才做 loss 字段和视觉解冻

- 失败主要是选工具、读反馈、停止：只把 `Write.content` 从 2 降为 1，固定其他权重。
- 失败主要是冗长思考、超时：比较 thinking 0 与 0.5，测成功 token 和时间。
- 失败主要是读图反馈：先证明图像确实影响当前行为，再单独考虑 aligner/ViT 解冻与相应显存/LR。

## 七、公开资料能借鉴什么

- [DataComp-LM](https://arxiv.org/html/2406.11794)：固定训练配方、比较数据筛选与混合，并强调不同架构、计算和超参数会混淆数据结论。本文采用其“受控比较”方法，不迁移其预训练过滤器的最优结论。
- [FineWeb](https://arxiv.org/html/2406.17557v2)：数据 ablation 使用相同架构、token 数和下游评估；其全局去重曾产生反效果，说明“去重必然更好”不成立。它是 Common Crawl 预训练，不是本项目的直接配方。
- [D4](https://arxiv.org/html/2308.12284)：在 OPT 预训练中，去重后做多样化选择及有选择的重复可优于随机重复。可借鉴“去重+多样化+记录重复曝光”，不能宣称本项目也必得相同提升。
- [Tülu 3](https://arxiv.org/html/2411.15124v2)：LR、epoch、loss 类型需要联合实证；开发/未见评估与数据去污应前置。
- [LIMA](https://arxiv.org/html/2305.11206)：高质量与多样性对通用对齐很重要，但不能推出专业代码数据只需一千条。

## 八、Opus 调用边界

同一专用 Opus 路由已实际调用。前两次整体训练/调参任务均被其“开发竞争模型”自动风控拒绝；第三次仅做本地语料审计也在读取数据后拒绝，三份 JSON 均保存 `is_error=true`、`stop_reason=refusal` 和实际 `claude-opus-5-5` modelUsage。另将任务缩为纯软件示例库统计抽样复核，结果见最终 README；主报告不伪称已有 Opus 对训练参数的认可。

## 九、复核限制

- 本轮未重新运行 10,697 条浏览器，静态统计只用于分层和复核，不证明视觉/动画语义。
- MinHash 结果只覆盖其模板文本相似度与召回范围，不是完整语义去重。
- 梯度日志是当时快照，不用于持续监控或判断最终训练结果。
- 当前没有同超参纯 Aodi 对照，也没有学生完整行为结果；所有下一轮数值均为待检验设计，不是已证实最优配置。
