## 二、专题一：数据组成与配比硬经验（1,000+ 组消融与前沿开源配方）

### 1. OpenThoughts3（`arXiv:2506.04178`）：1,000+ 组可控 SFT 消融的 4 条反直觉结论
OpenThoughts 团队围绕数学、代码、科学推理跑了超过 **1,000 组**严格对照的 SFT 数据配方消融，几乎条条打中我们踩过的痛点：
- **来源“少而精”打赢“大杂烩”**：直觉以为拼 8–16 个多样来源更好，但实测**只保留 Top 1–2 个高质量、风格一致的核心源**稳定击败广泛混拼——混入过多风格/契约不一致的异构来源只会稀释主能力。
  - *对照我们*：首版把 10,697 条 CDN/r160/无思考 Aodi 全量灌进离线/r180/思考 ReAct，正是“异构源污染”的典型反例；Round 2 把 Aodi 缩到精选 2,250 条且用独立 system 隔离完全正确。
- **筛选策略分任务：代码看难度，推理看长度，绝不按“最短”选**：传统 embedding/fastText 过滤普遍输给 LLM 驱动过滤；**代码类任务按题目固有难度筛（保留难题）收益最大**，数学/科学按教师响应长度筛（保留更长、更细的推理链）收益最大。
  - *对照我们*：彻底解释了首版 161/211 条按 `lowest_wall_seconds` 选优为何把深度排错能力滤掉了。
- **高价值硬题可“同题多次采样”扩量（最多至 16×）**：当独立高质题源有限时，让教师对同一道难题多次采样并去重，是性价比极高的扩量轴，不会像简单复制同一条轨迹那样迅速过拟合。
  - *对照我们*：在独立题族扩容到 100–200 个的过渡期，对高难修复/生成题保留 2–3 条不同解决路径的去重合格轨迹，比直接 5× 复制同一条轨迹健康得多（前提：与 `devtest-v2` 保持零题族重叠）。
- **教师跑分高 ≠ 蒸馏效果好**：实测 `QwQ-32B` 作为蒸馏教师稳定击败在部分基准上分数更高的 `DeepSeek-R1`。原因是学生能否吸收取决于**教师输出与学生先验的分布契合度（可模仿性）**。
  - *警钟*：DeepSeek `v4.1-flash-1017 (high)` 自身视觉与修复能力极强，但仍必须通过 Round 2 的 `v2-full` vs `v2-oneshot-only` 留出实测，验证 27B Dense 学生是否真正吃得下其推理风格与长代码密度，而不是只看教师 Canary 得分。

### 2. Kimi-Dev（`arXiv:2509.23045`）与 SWE-Swiss（`ACL 2026 Findings`）：为什么“单轮先验 + 技能拆解 + 多轮 ReAct”是最稳组合
- **Kimi-Dev（`2509.23045`）**：核心发现是 **Agentless（单轮可验证任务）训练会形成极强的“技能先验（Skill Prior）”**——先把定位、编辑、代码生成与自检写稳，再拿仅 **5,016 条**多轮 SWE-Agent 轨迹做 SFT，就能把 SWE-bench Verified 拉到 **48.6% Pass@1**，比从零硬训多轮 Agent 省数据得多且更稳。
  - *直接背书*：完美验证我们 Round 2 **“24–28% 离线带思考 One-Shot + 22–25% 多轮 ReAct”** 的双轨协同设计！更进一步，如果 Round 2 同批混合仍有单/多轮互相牵制，Round 3 可以试 **两阶段课程**（Stage 1 偏 One-Shot + 通用底座打牢编码与审美先验 → Stage 2 混入完整比例多轮 ReAct + Hard 修复）。
- **SWE-Swiss（`2026.findings-acl.790`）**：将复杂软件修复显式拆成 **Localization（定位）+ Repair（修复）+ Unit Test Generation（验证）** 三项原子 SFT 数据，避免模型只靠端到端盲改。
  - *对照我们*：3D Agent 的对应原子能力是 **视觉/状态缺陷诊断（看图 + 查 `__3D_STATE__`）→ 局部精准修改（不破坏非目标区域）→ 离线自检与及时收尾**，Round 2 题型按 45% 缺陷修复 / 25% 从零生成 / 20% 局部编辑 / 10% 健康对照划分，正好把这几项能力铺开。

### 3. SWE-Lego（`arXiv:2601.01426`）与 SWE-smith（`arXiv:2504.21798`）：真实 vs 合成配比 & 怎么造“不假”的修复题
- **SWE-Lego（`2601.01426`）**（纯 SFT 把 `Qwen3-8B` 推到 **42.2%**、`Qwen3-32B` 推到 **52.6%** Pass@1，TTS@16 达 **58.8%**）：
  - 任务组成：**32,119 条**可执行实例 = **18,409 条真实 PR（57.3%）+ 13,710 条合成 bug（42.7%）**，约 **1.34 : 1**。真实题供给复杂上下文与多文件深度，合成题供给可控广度与高通过率。
  - 轨迹组成：**18,110 条**验证轨迹 = **14,110 条完全解决（77.9%）+ 4,000 条半解决但文件定位完全准确（22.1%）**。
- **SWE-smith（`2504.21798`）的造 bug 教训（Usability–Diversity Trade-off）**：
  - `LLM-Modify`（局部小改语法/常数）：可执行率高，但行为多样性极低，模型学完只会修表面小错；
  - `LLM-Rewrite`（大段重写函数）：多样性高，但极易引入非预期环境噪声导致不可用；
  - **Reverse-Fix（从真实正确代码逆向回退/注入结构性缺陷）** 在行为独特性与可用率上同时夺冠！
  - *对照我们*：Round 2 扩容 45% 修复题库时，最省力且最高质量的造题法正是 **Reverse-Fix**：拿高质量、已通过视觉验收的 Three.js 场景，按明确缺陷谱系（几何穿模/浮空、动画时间轴停转/非无缝循环、相机遮挡/过曝、离线打包外链断链、局部交互失效）**结构化注入可复现缺陷**，保证既真实又 100% 可修复可验收。

### 4. UI-TARS-2（`arXiv:2509.02544`）与 ADP（`arXiv:2510.24702`）：多模态 Agent 混合与格式统一
- **UI-TARS-2（`2509.02544`）**：原生 GUI + 终端 + 文件系统多模态 Agent。其核心经验一是 **SFT 必须把领域 Agent 轨迹与通用对话/推理/代码混合**（SFT 阶段领域占比显著高于续训阶段，多篇 GUI/终端 Agent 配方落在约 1:1 附近，避免能力偏科）；二是建立 **双路数据飞轮**：通过验证的轨迹（$V=1$）入 SFT 固化技能，未通过的轨迹（$V=0$）不直接污染 SFT 而是转入世界知识/诊断分析，避免离线示范与在线探索的 off-policy 分布断层。
- **Agent Data Protocol（ADP，`2510.24702`）**：用统一 schema（标准化 Action + Observation）打通 13 个异构 Agent 数据集联合 SFT，带来约 **+20%** 平均增益。印证我们把多轮 ReAct、离线 One-Shot、SWE 回放统一成干净一致的 OpenAI/Swift 协议与工具 schema 的重要性。

## 三、专题二：轨迹筛选、步级掩码与难度课程（打破“全丢 / 全留”二选一）

这是本次调研**性价比最高的可直接抄作业板块**——无需多花一分教师 API 费用，仅改数据后处理与 mask 逻辑就能拿到实打实的百分点。

### 1. Step Rejection Fine-Tuning（SRFT，`arXiv:2605.10674`，JetBrains Research）
- **惊人数据实测**（对 5,000 条已解决 + 5,000 条未解决 SWE-smith 轨迹做步级标注）：
  - **已解决轨迹（Resolved）**：95.9% 有效步，但仍有 **4.1% 有害步**（无效重试、错参工具调用、跑偏探索）；
  - **未解决轨迹（Unresolved）**：竟有 **93.0% 有效步**，仅 **7.1% 有害步**！传统 RFT 一刀切丢弃全部未解决轨迹，直接浪费约 61% 的采集算力。
- **关键消融（SWE-bench Verified）**：
  - Base：`7.0%`；
  - 传统 RFT（只留通过轨迹）：`30.9%`（+2.4pp over 对应基线）；
  - **反面教材——无掩码直接塞入未解决轨迹**：反而跌到 **`28.5%`**（-2.4pp，模型把失败习惯学进去了！）；
  - **SRFT（保留完整上下文，但用 critic 掩掉有害步 loss）**：升至 **`32.2%`**（超越纯 RFT **+1.3pp**，且不额外采数据）。

### 2. SWE-Lego（`arXiv:2601.01426`）的两大 SFT 绝招：步级错误掩码 + 轮数难度课程（合计 +3.8% Pass@1）
1. **带例外条款的步级错误掩码（Step-Level Error Masking）**：
   - 掩掉工具格式错、无效编辑、死胡同尝试的 assistant turn loss（同时**保留它们在上下文中**，让后续正确步能基于错误历史继续推理）；
   - **关键例外**：**不要掩掉正常诊断行为触发的报错**（例如首次运行验证脚本复现 bug、首次跑渲染发现缺图/黑屏），因为“主动诊断 → 读报错 → 修复”正是我们要教的核心动作！
2. **用轨迹轮数做三阶段难度课程（Difficulty-Based Curriculum）**：
   - 作者发现任务通过率与教师轨迹轮数存在极强负相关（**$r = -0.95$**），直接按轮数分档：Easy（0–50 轮）→ Medium（50–70 轮）→ Hard（70–100 轮）；
   - 采用**渐进累积式课程**（Stage 1 训 Easy → Stage 2 训 Easy+Medium → Stage 3 训全量），每阶段保留前序数据防遗忘。
   - **实测收益**：步级错误掩码 + 轮数难度课程叠加，相对 vanilla SFT 直接带来 **+3.8% Pass@1** 净增益！

### 3. Agent-R（`arXiv:2501.11425`）：何时纠偏最有效？
- 纯克隆黄金路径无法教会学生从自己的错误中恢复；**Agent-R** 指出，不要等到整条轨迹结尾失败再复盘，而要定位**首个出错步（first error step）**，将错误前缀与正确恢复路径在出错点做即时拼接反思（timely revision）。
- *衔接 Round 3*：与 `arXiv:2605.12913`（AggreVaTe）思路完全共振——Round 3 让 `v2` 学生跑出首个渲染/断言/工具报错后，立刻由 DeepSeek 1017 在同工作区接管修复，训练时对学生出错前缀 `loss=False`、只监督 DeepSeek 纠偏与收敛段。

## 四、专题三：专治 40.8% 超时死循环——Overthinking、DAG 裁剪与显式 `REVISE vs STOP`

首版 `devtest-v2` 中 **49/120（40.8%）死于超时，其中 43/49 已过浏览器检查、34/49 已精确复现**，且 Round 2 Canary 中 DeepSeek `high` 也在无上限时跑出 110 轮/57 图超时。文献对这一现象有高度一致的诊断与实证药方：

### 1. 为什么模型“做对了却停不下来”？
- **DeepSeek-V3.2（`2512.02556`）** 公开记录了完全相同的现象：在长程工具循环中，无约束推理链极易陷入 **“冗余自检循环（redundant self-checking）”**，导致轨迹 token 膨胀并触发退化或上下文耗尽。
- **进展幻觉（Progress Mirage）与无止境微调**：当缺乏外部硬收敛信号时，模型在纯主观视觉检查下容易反复“微调细节→再截图→再挑小刺”，形成高成本低收益的伪进展循环。

### 2. 文献验证过的 4 套“刹车与裁剪”组合拳

| 方法 / 论文 | 核心机制 | 实测效果 | 适合我们何时用？ |
|---|---|---|---|

## 五、专题四：混合 Thinking / Non-Thinking、跨轮保留思考与脚手架一致性

这一块直接回答首版最诡异的权重级退化：**为何仅学生出现 `empty_think_only_end_turn`（9/60、6/60 vs 原版 0/60）与 5.1× `InputValidationError`？**

1. **Thinking Mode Fusion 的模式隔离红线（Qwen3 `2505.09388`、ThinkDial `2508.18773`）**：
   - Qwen3 将长思考（thinking）与直接作答（non-thinking）融合进同一权重时，明确依赖 **chat template / system 级显式模式标记**（`/think` vs `/no_think`），并严格控比以防 **Thinking Leakage / Mode Bleeding**（两种模式梯度串扰，导致非思考模式乱吐思考、或思考模式提前空思考 EOS）。
   - *对照我们*：首版 87.9% 无思考 Aodi 与多轮 ReAct 共用退化的 `"You are a helpful assistant."` 且无模式隔离，相当于把“立刻结束不思考”的梯度硬冲进多轮思考区间！Round 2 既压低 Aodi 监督占比（36–42%），又给 Aodi 加**显式单轮无工具 system prompt** 做分布隔离，完全符合 Qwen3/ThinkDial 机理。
2. **多轮工具调用必须保留历史思考（DeepSeek-V3.2 `2512.02556`、GLM-4.5）**：
   - DeepSeek-V3.2 在 *"Thinking in Tool-Use"* 中强调：多轮工具交互中如果每轮清掉前序 `<think>`，模型就被迫每轮重推计划，规划能力明显退化；必须采用 **Preserved / Interleaved Thinking**（保留工具轮之间的推理链，直到整轮用户问题结束）。
   - *对照我们*：Round 2 Canary 已核验 `history_thinking_preserved=true`，统一走 `repos-logging-proxy` 抓真实 `/v1/messages` 链路时，务必持续把 `history_thinking_preserved=true` 作为导出硬断言！
3. **脚手架强耦合与“有毒验证器”（R2E-Gym `2504.07164`、SWE-rebench `2505.20411`）**：
   - 跨 SWE 脚手架实证研究发现，**高达 ~64% 的轨迹行为指标方差来自执行脚手架（harness）本身**（例如 OpenHands vs SWE-agent 的工具定义、错误回显、上下文格式），跨脚手架行为规律往往无法直接迁移。这证明首版把 `tools` 置空为 `"[]"` 是致命硬伤，而 Round 2 按方案 A 彻底统一到 `repos-logging-proxy` 真实请求流，是保证训练–推理零偏移的底线。
   - **R2E-Gym（`2504.07164`）** 指出纯执行测试存在 **Toxic Tests**（放过错误实现或误杀正确实现），单靠执行筛选会在 ~42–43% 撞天花板，引入**无执行评审 + 执行验证双轨过滤**才能破局。这正好呼应我们首版 `capture.cjs` 假阳性（放过 55 条断链 HTML）与 Round 2 `cycloidarch` 假阴性（题面未写死 `__3D_STATE__` 字段名），也支持 Round 2“确定性硬检全过 + 10% 视觉抽检/多模态评审”的双轨策略。
4. **纯 SFT 难以彻底根除格式泄漏**：
   - 最新多模态/推理 SFT 失败分析表明，纯 SFT 即使 loss 收敛，仍常残留少量格式跳过、标签未闭合或思维泄漏（早期 checkpoint 甚至可达 20–25%），必须靠**入库前零容忍清洗 + tokenizer 逐 token 模板一致性核验**把 SFT 漏网率压到最低；若 Round 2 评测仍有残余 1–2% 格式小毛病，Round 3 轻 RL/偏好对齐才是终极收口。

## 六、专题五：视觉代码 / 3D 渲染返修 Agent 的专项经验

与我们最贴近的“代码生成 → 无头渲染 → 看图诊断 → 修改代码”视觉编程 Agent（3D/CAD/动画/GUI）在 2025–2026 年已收敛出清晰配方：

1. **IterCAD（`arXiv:2606.13368`，视觉 3D/CAD 交互式生成与编辑）**：
   - **三阶段渐进训练**：Stage I 单轮初始代码生成（把无效代码率 IR 从 Base `62.30%` 压到 `7.50%`，AUC-TR `0.21→0.52`）→ Stage II 加入 **IterCAD-RS（结构化几何扰动 + `REVISE`/`STOP` 双态监督）**（IR 再压到 **`0.80%`**）→ Stage III 几何感知多轮 RL（GSPO）+ **可存活前缀掩码（GVPM）**（IR **`0.30%`**，AUC-TR **`0.61`**，Mean CD **`13.04→5.09`**）。
   - **核心启示**：单轮 SFT 主要解决“写得出可运行代码”，真正把多轮视觉修复稳下来、学会不胡改也不死循环，靠的是 **Stage II 的显式扰动修复 + STOP 判停数据**；而突破几何精度上限（如 3D 空间穿模、轨迹对齐），最终要靠 Stage III（我们对应的 Round 3）的在线纠偏 / 可验证多轮优化。
2. **Articraft（`arXiv:2605.15187`，可动 3D 资产 Agent）**：
   - 将复杂可动 3D 资产（关节/机构/机械臂等）归约为“面向确定性验证器/SDK 写代码 + 结构化执行反馈循环”，避开底层文件/依赖噪声，产出 Articraft-10K。这印证我们统一 **离线 Three.js r180 单文件契约 + `check_browser.mjs` 结构化检查反馈** 的路子非常正。
3. **联动本地已读两篇视觉代码基准**：
   - **ManimCode（`arXiv:2611.08294`，已存档）**：同一批 8,416 个动画输入上，加入渲染验证精修监督让 ManimData-test 渲染率 `57.2%→63.2%`、ManimBench `69.0%→76.0%`，证明视觉执行精修数据确有显著增益。
   - **3DCodeVerse（`arXiv:2610.22341`，已存档）**：104K 对 / 75M token 配方中，把目标 3D 方言份额从 15% 提至 34% 让留出几何指标 F@0.05 从 `0.705→0.816`，说明在保证通用底座不崩的前提下，目标领域有效监督占比拉到 **25–50%** 区间（我们 Round 2 离线 One-Shot + ReAct 合计 ~46–53%）正是甜点区。

## 七、专题六：多轮长短混训的 SFT 优化暗坑（容易默默吃掉 3–5 个点）

1. **梯度累积与长短序列的 Loss 聚合 Bug（`arXiv:2604.23747`，*SFT-then-RL Outperforms Mixed-Policy Methods*）**：
   - 该文揪出了 TRL / OpenRLHF / LLaMA-Factory / DeepSpeed 中长期潜伏的两大工程 bug：① CPU offload 下静默丢弃梯度累积中间 micro-batch；② **把各 micro-batch 的平均 loss 再做简单算术平均**，而不是按真实有效监督 token 总数做全局加权平均——当短单轮（~1K tok）与长多轮（~40K tok）混训时，该 bug 会严重扭曲真实梯度方向、压低 SFT 上限！
   - *Round 2 放量前必查*：切到 `M7 binpack@65K + gbs=8` 正式开训前，检查一次 Megatron-SWIFT 日志里的 per-microbatch loss 归一方式（确认 `calculate_per_token_loss` / packed sequence 内跨 DP & microbatch 梯度按真实有效标签权重正确归约）。
2. **Off-Policy Token 梯度尖峰与遗忘（DFT `arXiv:2508.05629` & Off-Policy Token Clipped SFT）**：
   - 当学生（Qwen3.8-27B）去拟合异构强教师（DeepSeek 1017）的长轨迹时，教师轨迹里少量学生概率极低的 token（如特定长代码模板、独特话术）在标准交叉熵里会产生极大梯度，频繁触发 `clip_grad=1.0`（首版日志就是 100% 步触发裁剪！），不仅把同批其他样本的梯度压扁，还会引发通用/OOD 能力遗忘（文献实测用 token 级裁剪或概率重加权 DFT 可显著降低 OOD 遗忘超 11%）。
   - *Round 2 实操建议*：保持 `gbs=8`（比首版 `gbs=1` 方差降 8×）、记录每步 `grad_norm` 裁剪比例与分轨 val loss（Aodi / One-Shot / ReAct）、控制在 **2–3 epoch** 不过拟合；若分轨 val 出现早期过拟合或通用回退，再评估加权/调 lr 或引入 DFT 思想。
3. **SFT 的定位边界（Tülu 3 `2411.15124` & Incomplete Learning Phenomenon）**：
   - 多篇 2025–2026 研究一致指出：SFT 本质是**建立行为协议、工具格式、技能先验与收敛纪律的“冷启动去噪阶段”**，过度拉长 SFT epoch 反而过拟合而不产生新推理能力；把 Round 2 做成干净、均衡、高通过率的坚实冷启动底座，再在 Round 3 接 **AggreVaTe（学生出错前缀 + 教师接管）** 或轻 RLVR，才是投入产出比最高的演进路径。

## 八、给 Round 2 放量前与 Round 3 的“可直接抄作业”行动清单

### P0：Round 2 放量前（改动极小、几乎零额外 API 成本，直接补齐文献最强经验）
1. **在“通过轨迹”内部补上轻量“步级错误掩码（SRFT / SWE-Lego 规则）”**：
   - 导出 `ready.jsonl` 时，不只按整条轨迹过滤，对通过轨迹里**明显有害的中间 assistant 步**（空参 `tool_use`、触发工具 schema 报错的畸形调用、连续两次完全重复的无进展命令）保留在上下文中，但将对应 assistant span 设为 `loss_scale=0`（`loss=False`）；
   - **严格遵守 SWE-Lego 例外规则**：不掩掉“首次跑 `check_browser.mjs` / 看截图发现真实 bug → 随后修复”的正常诊断步！
2. **把“显式 `STOP` 收敛纪律”落到数据后处理（IterCAD-RS + DAG Refinement 思路）**：
   - 除给 `run_claude_cases.py` 加 `--max-turns`（生成 `<=40`、修/改/健康 `<=28`）和强化 `TEACHER_CONVERGENCE_PROMPT` 外；
   - 在数据审计脚本中加一条 **“首绿后冗余轮统计与清理”**：若教师某条轨迹在第 $k$ 轮已经通过全部确定性检查且后续又做了 5 轮无实质改动的重复看图/微调，标记为冗余返工并优先选取**首次验通后 1–2 轮内干净收尾**的样本（或在验证产物等价的前提下做尾剪）。
3. **扩容 45% 真实缺陷修复题时，用 SWE-smith / IterCAD 的 `Reverse-Fix` 造题法**：
   - 少用随机小改（多样性太差），多从高质量已验收场景按缺陷分类表做**结构化逆向注入**（几何穿模/离地、循环断帧/停转、光照遮挡、外链断链、局部交互错乱），同时保证每题都有清晰的 `__3D_STATE__` 断言字段声明，消除有毒测试假阴性。
4. **开训前做 2 项硬体检（防工程暗坑）**：
   - 抽样 1 条 ReAct + 1 条 One-Shot + 1 条 Aodi，用 **真实 27B tokenizer 逐 token decode**，核验 `<think>`、`# Tools`、`history_thinking_preserved`、单轮/多轮 system 隔离与 vLLM `chat_template.jinja` 100% 对齐；
   - 确认 `M7 binpack@65K + gbs=8` 训练日志中 **有效监督 token 级 loss 归一正确**，并监控 `grad_norm` 裁剪率（不能再像首版 100% 顶满裁剪）。

### P1：Round 2 训练策略可选加分项（低成本单变量消融）
5. **同题多采样去重扩量（OpenThoughts3 经验）**：若独立高难修复题一时来不及扩到 400 个，可以对每道高难题采样 2–3 条不同合理修复路径并去重（严控与 `devtest-v2` 零重叠），比单一轨迹高频重复更稳。
6. **轻量化轮数难度课程（SWE-Lego 经验）**：若 Round 2 全量混合（~8h）训完后观察到短题已过拟合而长难题仍欠拟合，可做一次同预算 2 阶段课程消融（Epoch 1 全量 / 偏 Easy+One-Shot 打底 → Epoch 2 侧重 Medium+Hard ReAct 同时保留底座防遗忘）。

### Round 3 演进衔接（等 `v2-full` 在 `devtest-v2` 拿到明确跃升后）
7. **AggreVaTe / Agent-R 省算力学生纠偏**：让 `v2-full` 在独立新题跑出首个报错或坏渲染状态 → 同工作区 + `repos-logging-proxy` 前缀无缝切换 DeepSeek 1017 接管修好并干净 `STOP` → 学生前缀 `loss=False`、只监督教师纠偏段（零反事实分叉成本）。
8. **若 SFT 后仍有 1–2% 残余格式泄漏或审美/几何上限卡住**：进入 IterCAD / SWE-Swiss 路线，用确定性硬检 + 视觉评审做小步多轮 RLVR / 偏好对齐。
