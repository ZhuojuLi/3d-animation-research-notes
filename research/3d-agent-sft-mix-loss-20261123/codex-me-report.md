codex-me 独立报告，2026-11-23。研究对象是原版 Qwen3.8-27B 上已启动的首轮混合 SFT。以下复算只读本地训练输入、模板审计和源码。

**首版一遍自然混合已经给 ReAct 10.975% 的有效监督位置。当前每步一条记录，ReAct 占 2.275% 的计划更新步。** 放大记录采样、增加工具参数权重和把更多长序列放入同一个更新批次，是三种不同干预。下一轮建议先比较监督剂量，再单独检验工具权重。

## 一、事实：一遍训练到底看到多少

只计 train。A 为 Aodi answer-only，R 为完整多模态 ReAct。一个输入 token 是渲染后序列里的一个位置；一个有效监督 token 是目标模板给出有效 label 的位置。审计已检查掩码和正权重位置逐点相等。下表最后一列统一用 R / (A + R)，但每行的计量单位不同。

| 完整输入位置 I | 129,242,866 | 19,159,013 | 148,401,879 | 12.910% |
| 有效监督位置 U | 127,527,431 | 15,722,203 | 143,249,634 | 10.975% |

这些是 token 数和系数和。要判断模型在哪部分产生大损失，还缺各 token 的交叉熵；要归因参数更新，还需梯度方向、裁剪、学习率与 Adam 状态。

**实际 reduction。** 静态查阅运行参数与镜像代码。Swift 的 get_batch_on_this_pp_rank 同步平移 label 和 loss_scale；MegatronTrainer.loss_func 返回「逐位置交叉熵乘 scale 后的和」以及「label 有效的位置数」。calculate_per_token_loss=true 时，pipeline 在一次更新窗口累积有效位置数，finalize_model_grads 跨 DP/CP 汇总计数并按其倒数缩放梯度。TP=4、PP=4 让 16 个 rank 共算同一记录；DP=CP=1，micro/global batch 都是 1，无 packing。每步只有一条完整记录。loss 的日志汇总路径与反传路径需分看。运行参数（本地附件未发布） · Swift 平移（本地附件未发布） · 损失函数（本地附件未发布） · 调度（本地附件未发布） · 梯度归一化（本地附件未发布）

对更新窗口 B，设 m 为有效 label 指示量，w 为权重，ℓ 为逐位置交叉熵。分子 N_B = Σ(mwℓ)，分母 D_B = Σm，目标 L_B = N_B/D_B。给全窗口所有 w 同乘常数会同比缩放目标；若改成除以 Σmw，则这个常数抵消。若各微批分别归一化再等权平均，短微批会取得更大的单 token 系数。例：两条记录分别有 1、9 个 label，各自平均 CE 为 3、1，权重均为 1。同窗总 token 平均为 1.2，先取两条均值再平均为 2.0。可用此标量例子、异权重及极不等长例子复查下一轮实现，并比对把同一全局 batch 拆分 rank 或 microbatch 后的分子、分母与梯度缩放。

**当前一条一更新意味着什么。** 每条 i 的监督系数总和是 Wᵢ/Uᵢ。长记录在一步里平摊到更多位置，长度本身不会使该步按 token 数同比放大。按全程各步等权、静态样本各一遍求和，A 为 10,697，R 为 Σ(Wᵢ/Uᵢ)=283.3216，R 占 **2.580%**。这里先逐行相除再求和；R 归一化系数中工具部分占 73.38%。这个数只描述该批设置下、同等看待各步时的名义系数，实际优化还会随样本 CE、学习率和梯度变化。在更大的全局 batch 里，长记录会按 Uᵢ/D_B 占窗口中的位置；改变 packing、累积步数、分布式分母后应重新复算。算术上，R 权重和最大的 25 条占 R 全部 W 的 17.27%，也不能据此说它们贡献同份额的更新。逐行复算（本地附件未发布） · [训练配置](../../3d-animation-agent/reports/first-sft-20261123-001/REPORT.md)

## 三、迁移推论：如何定采样和曝光

**先选要检验的量。** 用 U_R/(U_A+U_R) 描述监督剂量，用来源内 case/family 覆盖与重复约束选择记录。记录概率 p 是调度器的输入，I 是计算量的一个代理，W 是权重分布，Σ(N_B/D_B) 与逐步优化有关。不存在一个百分数可以填这四列。epoch 写明是“数据文件遍历一遍”还是“有放回抽 n 次”，并以日志中实际提交的 update 核对重启、跳过、过滤和尾批。

平均每条 A 有 11,921.79 个监督位置，R 有 63,141.38 个，长度比 r=5.2963。若每次抽一条完整记录、各域内均匀抽样，要获得长期有效监督份额 q，记录抽到 R 的概率为 p=q/[r(1−q)+q]。固定 n 次抽样时每条 R 的期望曝光 np/249，每条 A 为 n(1−p)/10,697。若按任务族分层、截断或筛掉长序列，先重估各层均长。要设计加权位置份额，同一式中改用 W 的均长比 5.9384。

| R 占全部 U 的目标 q | 抽记录时 p(R) | 相对于每条 A 平均 1 次，每条 R 平均曝光 |
|---:|---:|---:|
| 5% | 0.984% | 0.427 次 |
| 10% | 2.055% | 0.901 次 |
| 自然遍历 10.975% | 2.275% | 1.000 次 |
| 20% | 4.508% | 2.028 次 |

反例：若设置 20% 的**记录**来自 R，则预计 R 占全部 U 的 56.97%，每遍 A 对应每条 R 平均 10.74 次。自然混合已接近历史研究在旧规模下提出的 90:10 监督预算。没有从 2.275% 的行数份额直接上调到 20% 的依据。要衡量已完成曝光，应按成功更新关联 UUID，记录抽样次数、未见率及每族分布；重复出现的前缀、试跑和断点回滚另计成本。[历史建议及当时的规模假设](../3d-agent-data-mix-20261121/README.md) · [旧资料中的数据分工](../3d-agent-training-data-composition-20261122.md)

**工具参数里的代码。** 我按已入选的 249 个 UUID 读取各自 OpenAI 导出并验证哈希。12,450 个调用中，Write 1,818 次。解析参数 JSON 后，所有字符串字段的值共有 16,259,122 个 Unicode 字符，其中 Write.content 单项为 11,471,761 个（70.56%），加上 Edit.old_string 和 Edit.new_string 共 83.52%。其中既有代码或文件正文，也有编辑旧串；字符占比不能当作代码 token 占比。Bash.command 再占 1,400,027 个字符。当前 2 档同时奖励工具选择、格式、路径和长参数。监督量集中于这一档已经实证，是否损害修复、是否改善代码完整性须用留出题检验。原始行映射（本地附件未发布） · 字段计数方法（本地附件未发布）

**怎样控制放大。** 首先按记录、回合、工具名、字段（schema/名称、路径、正文、旧串、新串）标记渲染后的 token 区间，与 shift 后有效 label 核对；另按 family、交付哈希、长度分位数聚合 U、W、N 和每窗口 W/D。回合展开时只给新增 assistant 决策打 label，共享的历史前缀只作上下文。标记重写同一整文件的次数；对照时保留完整参数、图片、失败反馈、收尾和 EOS，避免切断动作与结果。现有转换没有保存完整语义段→token 的逐位置证明，故不能把上述字符盘点提升为字段级 CE 证据。

在同一记录流只把 tool 2 改成 1，R 的 W 从 17,628,294.5 降至 11,218,765.5，工具占 R 的 W 从 72.72% 降至 57.13%，R 占两域 W 从 12.14% 降至 8.09%，U 与覆盖相同。这同时改变 R 总强度和段内相对比例。若要单独检验段内重分配，对每一条 R 将新正权重乘 Wᵢ旧/Wᵢ新，保留该条旧 Wᵢ 及旧 Wᵢ/Uᵢ，再比较工具合法性、文件可执行性、非目标保持。只有在字段级归因指向超长正文后，再试仅给长参数的系数和设上限，或给名称/协议与代码正文不同权重。对所有轨迹一律长度倒数降权，会在当前逐记录归一化之上再次惩罚长样本；需有明确目标和对照。

## 五、项目建议：不超过三个同起点短跑

**待否证的假设**：在相同未加权监督预算下，把 R 的份额从约 10% 提到 20%，能在新题族上带来足以抵偿通用代码回归与计算成本的首次交付增益。此轮固定 0.5/1/2。独立的工具系数试验留在剂量选择之后。现有长跑用于定位自然混合和能力趋势，只有起点、数据、实际预算及日程也匹配时，才可复用其 checkpoint 充当正式对照。

| 组 | 两域全部 U 中的 A/R 份额 | 每组 60M 个 U 时的 A/R 抽取量估算 | 解释 |
|---|---|---|---|
| G，可选第三组 | 100% / 0% | 约 5,033 / 0 条 | 检验任何 ReAct 增量对同预算纯代码 SFT 的净收益。原版未经 SFT 的 27B 也可作零训练参照。 |
| L | 90% / 10% | 约 4,530 / 95 条 | 与当前自然剂量接近，ReAct 目标约 6M 个 U。 |
| M | 80% / 20% | 约 4,026 / 190 条次 | ReAct 目标约 12M 个 U。与 L 比较以 ReAct 监督替换部分 Aodi 的效果。 |

60M 是便于排期的试验预算示例。只有两个短跑时，以 L/M 回答剂量选择；若首要决策改为“是否加入任何 ReAct”，则优先 G/L。不能用 L/M 估计零剂量效应。**预算和覆盖的做法**如下。

1. 先按已审计 U 和题族、任务类型、长度分层，固定 L 和 M 共用的 R 子集与顺序种子，尽量覆盖 82 个来源族及稀少 edit、health 样本。选定子集约 6M 个 U，L 看一次，M 同组再一遍；在这个具体试验中 M 明确检验已见题的第二次曝光。若改为 M 抽约 190 条不同 UUID，则同时增加覆盖，须另命名干预。A 按同一分层顺序取嵌套子集，余量用完整 A 记录填充。冻结实际清单、总 U（每组距目标 ≤1%）和真实 p；达不到覆盖目标时报告缺失的 family，不能事后宣称检验了全部任务类型。
2. 每组从同一原版 BF16 checkpoint、同一初始优化器/RNG 出发；固定冻结层、模板、shift/mask、图像预处理、上下文上限、数据质量与去重规则、batch=1、packing 关闭、并行策略、优化器、峰值 LR、裁剪与采样种子。将 warmup/衰减位置按**已消耗 U / 60M** 对齐，预先规定唯一终点。此设计选择等监督预算，会有不同的更新次数、输入量与运行时间。按池均长估计，L/M 分别约 4,625/4,216 步、62.0M/63.3M 输入位置。预算表同时记录实际 GPU·小时；若任何组无法达到同一预算，使用事先冻结的共同进度点或标记结果不具可比性。
3. 固定同一评测 harness、可见工具/资产、单题时间和 token 上限、解码参数、seed、盲评规则及可重跑的基础设施错误标准。在冻结 dev 上按 case 配对，各题一次。Accepted@1 要求可运行正式交付、全部必要断言、可读的目标动作与适用的非目标保持同时通过。按题列出赢/输/同；同族先取平均，再对 family 等权，区间按族成块配对重采样。6 个 dev family 只适合粗选。现有 dev 的 12 题是 6 生成 + 6 修复，缺 local edit、专门的健康控制；另设独立校准子集时须在比较前冻结，条件不足就明确这些能力的 dev 证据缺口，不能挪用 test 补选型。冻结划分（本地附件未发布） · 任务类型清单（本地附件未发布）
4. **预注册晋级与停止规则示例。** 到共同预算即停。若出现非有限损失、mask/实际曝光与清单不符，停止该试验臂并作无效标记。较高剂量要在 12 道 dev 题上净增至少 2 个 Accepted@1、增益涉及至少 2 个 family，同时 Aodi 原 812 条按 U 汇总的未加权验证 NLL 回退不超过 0.02 nat/token（相对较低剂量组），且冻结修复题中不增加破坏非目标的例数，才晋级。同步检查可执行代码子集、调用合法率、超时、每次成功总 token/秒数（含失败成本）。2 道和 0.02 是建议的实用门槛，执行前按最低可接受增益与历史噪声确认。证据相持时保留较低剂量，报告不确定性；dev 小样本无法确证细微优劣。
5. 锁定方案后用同一推理预算在隐藏 test 上仅作一次配对确认。test 为另 12 族、48 题（24 生成、12 修复、12 局部编辑）。报告各类分子/分母、family 宏平均、逐族差值和区间、超时与视觉盲评。若 test 的配对增益消失或严重回归，登记“未复现”，停止推广。任何新配比重新走 dev，避免根据这 48 道题反选超参数。
