## 二、损失怎样跨 token、样本和设备归一化

对记录 \(i\)，记 \(n_i\) 为有效标签数，\(W_i=\sum_t w_{it}\)，\(S_i=\sum_t w_{it}\,\mathrm{CE}_{it}\)。两次核对都很重要，一次看 Swift 如何构造分子，另一次看 Megatron 在哪里应用分母。

1. 镜像源码快照的 ms-swift 4.5.2 把 labels 与 loss scale 一起左移。`MegatronTrainer.loss_func` 在有效位置以 `loss_scale` 乘逐 token loss，返回损失和及 `loss_mask.sum()`。后者为有效标签数。做日志归约的是一份 detach 后的副本。标签移位（本地附件未发布） · 损失实现（本地附件未发布）
2. 保存参数为 `calculate_per_token_loss=true`、`enable_dft_loss=false`、`is_binary_loss_scale=false`。Megatron-Core 0.19.0 对这一路径累积更新窗口内的 token 计数，在流水线组广播，并跨相应 DP/CP 组归约，最终按总计数缩放梯度。窗口目标为 \(\sum_i S_i/\sum_i n_i\)。若关闭该开关，源码另有先除 microbatch 的 token 数、再按 microbatch 数缩放的路径；多卡或累积数改变时须重查。TP、PP 的协作设备不能作为独立样本重复计数。调度函数（本地附件未发布） · 最终梯度缩放（本地附件未发布）
3. 实际参数快照为 TP=4、PP=4、CP=1、DP=1，micro/global batch 均为 1，`num_microbatches=1`。故当前每步为 \(S_i/n_i\)。整轮把每步名义系数等权相加，Aodi 每条贡献 \(W_i/n_i=1\)，共 10,697；逐条重算 ReAct 得 \(\sum W_i/n_i=283.321612\)。ReAct 的名义系数份额为 **283.321612 / 10,980.321612 = 2.5803%**。ReAct 内部按这一逐步口径，thinking、权重 1、调用档分别占 ReAct 系数和的 **24.5737%、2.0508%、73.3755%**。保存的参数（本地附件未发布） · 逐行模板审计（本地附件未发布）

可用两条人工记录做训练方的归约验算。若有 10、90 个单位权重标签，各自平均 CE 为 2、1，同一更新窗口按有效标签数归一得到 \(110/100=1.1\)，两个局部均值等权则为 1.5。再加入非单位权重，核对分母仍为有效标签数；同步验证单设备、DP 拆分和累积拆分的结果。应同时采集每个窗口的 \(\sum S_i,\sum n_i,\sum W_i\)、来源和成功更新标志。**2.5803%** 假定每条成功曝光一次且每步等权，未乘学习率、CE 或梯度；Adam 状态、梯度方向和裁剪也无法从数据包反推。

**项目建议与取舍。**

- 优先诊断调用名、参数名、参数值、代码负载、EOS 各自的 token 数、权重和与未加权 CE；按轨迹长度、工具、回合位置以及前一回包成功/失败分桶。配套评测首次工具选择、参数可执行性、错误后的修正成功、终止及最终交付。长代码的 CE 改善不能单独证明工具决策改善。
- 最窄的权重对照是仅把完全落在 `Write.content` 内的 token 从 2 调到 1，保留包装、调用名与其他参数权重。固定现有包后，ReAct 权重和将从 17,628,294.5 降至 **13,451,840.5**，占新混合包全部权重和 **9.5417%**。若把整个调用档从 2 降到 1，则相应为 **11,218,765.5、8.0858%**。前者检验长文件正文权重，后者连短工具语法也一起降权。实施时须回归 offset、并行调用、转义和 EOS。
- 要检验是否学习 thinking，可固定其输入可见性，只把非空 thinking 从有效标签中移除；按新的 \(n_i\) 重算。移除目标会改变同条其他 token 的归一化系数，保留长上下文仍有计算成本。另行删除输入 thinking 会改变条件分布，应单独实验。
- 若要严格同条等权，可比较 \(S_i/n_i\) 与 \(S_i/W_i\)。后者令每条总名义系数为 1，保留条内相对权重。若要限制单次长调用，可在训练 split 预定长度阈值 \(K\)，对长度 \(L\) 的参数正文乘 \(\min(1,K/L)\)。两种方法都会削弱一部分长代码监督，需用代码完整性与修复交付检验。将轨迹拆成逐轮样本时，只监督新一轮，记录重复编码前缀的成本，否则早期回复可能得到额外曝光。

## 五、预算紧张时怎样选下一轮

**候选。** 以 Aodi 每条记录的抽样赔率为 1，ReAct 每条分别取 \(m=1\) 或 \(m=2\)。来源内保持现有分布和 0.5/1/2 权重。下表是假定完整来源构成不变时的设计值，短跑必须回报实际分母。若训练方优先排查长代码权重，则用上节的 `Write.content=1` 替换第二臂，保持 \(m=1\)。

**固定条件与成本。** 两臂从同一 27B 权重和相同初始优化器状态开始，固定 tokenizer、模板、视觉预处理、长度上限、冻结范围、学习率曲线、并行配置、归一化、数据质量筛选和推理解码。使用各来源共享的随机排列，在短窗口内按预设来源配额交织，再在来源内无放回轮转，避免某臂恰好少见长题。若总预算为 \(B\) 个同型号 GPU·小时，可各给训练 \(0.4B\)，预留 \(0.2B\) 给统一评测或复核。主比较在相同训练 GPU·小时截点进行，学习率进度按共同预算比例对齐；另报最近相同步数的敏感性结果。固定步数和固定算力通常对应不同曝光，不应同时宣称完全匹配。

每臂记录实际成功步数、来源抽数、覆盖题族、每族重复数、有效标签与权重和、输入/视觉 token、图片 grid、按长度分桶的耗时与峰值显存，以及重算、重试的 GPU 时间。若配额太小而某类任务没有曝光，将该类效果列为无法比较。不要从总输入 token 直接换算长上下文与视觉处理的算力。

**隔离与指标。** 使用已冻结 Agent dev 的 12 题、6 族选型，Agent test 的 48 题、12 族仅用于最终一次比较。Aodi 812 条 validation 单独检查代码能力。按场景母体、源程序、素材、模板、修复/编辑派生关系和交付近重复构连通分量，核对 train/dev/test；仅题名或精确哈希不同不足以排除泄漏。保留原生 27B 的同题结果作参照。当前冻结说明已明确，声明 lineage 和字面词项无法完全证明语义独立。冻结评测说明（本地附件未发布）

- **主要指标**取每道冻结题一次尝试中，“正式交付、可运行且全部必要任务断言通过”的比例。先在族内按题平均，再对题族等权平均。同步列出逐题配对胜、平、负，以及生成、修复、局部编辑各自的成功数/尝试数。
- **护栏**包括编辑或修复后的非目标保持、固定连续片段的盲评、Aodi 验证的未加权代码 NLL 与固定代码题执行率、非法调用和超时次数。成本报告每次成功消耗的总推理 token 与 GPU 时间，失败尝试的消耗计入分子。
- **停选规则**可预登记为：两臂达到共同算力截点后才选型。候选至少在两个独立 dev 族上净改善，整体族宏平均上升；已通过的关键非目标断言没有新增回归，固定 Aodi 代码题执行率下降不超过 1 个百分点，且推理成本在冻结预算内。1 个百分点的分母是两臂共同的固定代码题数。发现跨 split 泄漏、有效标签错位或大量更新跳过，暂停该次比较并排查。若改善集中在单一题族、护栏失败或六族结果无法区分，保留原配比并记录未决；不得反复查看 test 挑比例。这些是项目候选阈值，六个 dev 族只能支持较粗的筛选。

**核验范围。** 本次实际复算了最终记录身份、混合包输入与标签和、修正版权重直方图、逐样本归一化系数、题族与母源曝光，以及工具参数内部 token；静态核对了训练配置和归约源码。仍待训练或评测方测量的是成功更新的逐条曝光、实际分组 loss 与梯度、同算力学习曲线、独立题族的行为收益和视觉成本。没有启动模型、训练、采集或浏览器。
