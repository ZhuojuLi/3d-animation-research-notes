## 双方共识：从记录到一次参数更新

A 为 Aodi answer-only，R 为长多模态 ReAct。只计 train，假设每条完整记录成功参与一次更新。Aodi validation 的 812 条另算。下表最后一列始终用 R / (A + R)，但每行的量纲不同。

| 一遍的账目 | A | R | R 份额 | 可以解释什么 |
|---|---:|---:|---:|---|
| 记录 | 10,697 | 249 | **2.2748%** | 从整轮取一个位置落在 R 的频率；当前也等于计划更新步份额 |
| 完整输入位置 | 129,242,866 | 19,159,013 | **12.9102%** | 上下文处理量；视觉 grid、长度和 GPU 时间另记 |
| 有效标签 U | 127,527,431 | 15,722,203 | **10.9754%** | 实际要预测的位置数；R 每条平均 63,141 个，约为 A 的 5.30 倍 |
| 正权重和 W | 127,527,431 | 17,628,294.5 | **12.1444%** | 去掉 token 交叉熵后，全包分子中各来源配置了多少权重 |
| 逐条 Wᵢ/Uᵢ 之和 | 10,697 | 283.321612 | **2.5803%** | 每步等权、整轮各记一次时，R 的名义系数份额 |

Swift 4.5.2 使 label 和 loss_scale 同步移位，返回加权交叉熵和 S = Σ(w·CE) 及有效标签数 U。Megatron-Core 0.19.0 在当前 per-token-loss 分支对一个更新窗口累积 U，在流水线组广播、跨数据/上下文并行组归约，按总 U 的倒数缩放梯度。实际 micro/global batch 均为 1，DP=CP=1，无 packing，每步目标为 Sᵢ/Uᵢ。于是 12.14% 是先汇总原始 W 再取份额，2.58% 是先逐样本除以 Uᵢ 再汇总。学习率、真实 CE、梯度方向、裁剪、Adam 状态及跳步都影响参数更新。这些表值无法反推出“梯度有多少来自 R”。改 batch、累积数或 packing 后，要按新窗口重算。模板全量审计（本地附件未发布） · 运行参数（本地附件未发布） · Swift 损失函数（本地附件未发布） · Megatron 梯度归一化（本地附件未发布）

**覆盖限制。** 249 个 ReAct case 对应 82 个声明题族和 237 个不同交付哈希。42 个 Aodi 衍生 ReAct 与 answer-only train 共用题源。局部编辑只有 5 条、171,613 个标签，占 R 有效标签的 1.09%。Astra 还在冻结顺序中数到前 128、512、1,000 条各只有 2、8、18 条 ReAct；短跑尤其要按实际读到并成功更新的 UUID 记账。codex-me 对照了两种血缘定义：加入模板、协议、批次等连接后，249 条只落在 43 个组件中。题族独立性、重复曝光与监督量要分别报告。修正版分布（本地附件未发布） · 训练索引（本地附件未发布） · 血缘图（本地附件未发布）

## Astra 独有的字段证据与联合复核

早期草案拟归档 thinking、只监督正文和调用。最终采用非空 thinking 0.5、正文及相应模板边界 1、assistant 工具调用 2。三档分别有 9,006,875、305,799、6,409,529 个标签，占 **ReAct 权重和**的 25.55%、1.73%、72.72%。工具返回、图片等被屏蔽的上下文仍影响下一步预测和计算成本。长度上限也会改变配比：若整条删除超过 65,536 的记录，167 条过长轨迹带走 **80.46% 的 R 标签**。[早期方案](../../3d-animation-agent/docs/plans/2026-11-21-simple-first-sft.md) · 候选清单（本地附件未发布） · [Astra 长度与掩码核算](astra-report.md)

| 字段证据 | Astra 原报告 | 联合复核，按原生参数边界 |
|---|---:|---:|
| 全部工具段 token | 6,409,529 | 6,409,529 |
| 完全位于任一参数值内的 token | 5,906,328 | 5,906,336 |
| 完全位于 Write.content 内的 token | 4,176,454 | **4,176,462** |
| Write.content 占工具段 token | 65.1601% | **65.1602%** |

8 个 token 的差异集中在 `lab-fan-sweep` 的第 6 个权重 2 段。文件正文中也出现了字面闭合标记 `</parameter>`，从渲染文本解析标签会提前结束该字段。联合复核按原生调用的字段顺序和值重建字符区间，逐段验证重建文本与 Ready 完全相同，再对同一次编码的 offsets 归属。只有完全落在值内的 token 算入该字段，跨边界的仍单列。其余 `Bash.command`、`Edit.new_string`、`Edit.old_string` 的 478,775、454,611、348,446 个 token 可复现。**47.38% 衡量写入文件正文得到的静态权重**；字段中可含普通文字，是否挤压工具选择或修复能力仍需行为对照。Astra 原始计算事件，item_67（本地附件未发布） · 联合字段复算程序（本地附件未发布） · 核算结果（本地附件未发布）

## 分歧与最终取舍：两个短跑回答一个问题

| 选择 | codex-me 提案 | Astra 提案 | 联合取舍 |
|---|---|---|---|
| 剂量与预算 | 10% 对 20% 的 R 有效标签，每臂例如 60M 个标签；比较同等监督预算下的数据替换。 | 原赔率对两倍赔率，主比较用相同 GPU·小时；衡量固定算力回报。 | 首轮用同算力的赔率对照，报告实际 U、步数及 GPU·小时。在共同 U 或步数附近作敏感性比较。两种预算回答不同问题。 |
| 工具权重 | 可降低整个调用档；若要隔离条内重分配，可校正到原逐条 W。 | 仅把 Write.content 内部 token 从 2 降到 1，保留工具名、包装及其他参数权重。 | 有明确错误类型时先做窄字段对照。全段降权会同时削弱工具语法。若要进一步隔离总强度，再另做逐条 W 守恒对照。 |
| 晋级门槛 | 重视配对净增交付数、跨族收益、Aodi 验证 NLL。 | 重视族宏平均、固定代码题执行率、非目标保持及推理成本。 | 用行为成功率主选；通用代码执行和 NLL 分别守住功能与预测质量，阈值在看组间成绩前锁定。 |

**方案一：原赔率 vs 两倍赔率。** 问“在相同可用算力下，更频繁抽到行为轨迹，能否提高新题首次交付？”把每条 A 的抽样权重固定为 1，每条 R 取 m=1 或 2，段内固定 0.5/1/2。每列按 mR/(A+mR) 得到下面的全池设计值。

| R 份额，按列分母计算 | m=1 | m=2 |
|---|---:|---:|
| 全部记录条次 | 2.2748% | 4.4484%（498 / 11,195） |
| 完整输入位置 | 12.9102% | 22.8681% |
| 全部有效标签 | 10.9754% | 19.7799% |
| 全部标签权重和 | 12.1444% | 21.6585% |
| 整轮逐样本名义系数，单条一步 | 2.5803% | 5.0307% |

498 是等效抽样条次，独立 R 仍为 249 条。按来源预先排列、配额交织、池内无放回轮转，区分新 UUID 覆盖与重复曝光；若要专测“相同轨迹看第二遍”的作用，则两臂锁定同一 R 子集。等算力短跑不要求跑满 11,195 步，也未必达到表内整轮份额。纯 Aodi 第三臂仅在需要回答“加入任何 ReAct 有无收益”时增加。[Astra 对照设计](astra-report.md) · [codex-me 等标签预算设计](codex-me-report.md)

**方案二：只降低 Write.content 权重。** 问“面对相同记录，少奖励长文件正文，能否改善选工具、按反馈修正或及时停止，同时维持代码可执行？”固定 m=1、UUID 流、同一成功步数、原始上下文及所有有效 label，仅把完全位于该字段内的 token 从 2 降到 1。按联合复核，整包 R 权重和由 17,628,294.5 降为 **13,451,832.5**，占两域新 W 的 **9.54%**；R 的记录与有效标签份额仍为 2.27% 和 10.98%。因此比较得到的是字段降权的整体效果，包含 R 整体强度下降。若所有工具都改成 1，则 R 权重和降至 11,218,765.5；这是范围更广的另一个实验。字段复算（本地附件未发布） · [原独立报告与降权口径](astra-report.md)

**固定条件和停选规则。** 两臂从同一原版 BF16 27B、相同初始优化器状态出发，固定模板、视觉预处理、上下文上限、筛选规则、batch/reduction、优化器及预先对齐的学习率进度。评测固定同一 harness、解码、seed、单题时间和 token 限额。以冻结 dev 的 **12 题/6 族**逐题配对比较 Accepted@1，要求首次正式交付、可运行、目标动作可读、全部必要断言及适用的非目标保持通过；先族内平均，再族间等权。当前 dev 只有生成和修复，编辑收益须另验。建议预注册：到共同预算即停，候选净增至少 2 题、覆盖至少 2 个改善族、族宏平均上升，且无新增关键非目标破坏；Aodi 812 条验证 NLL 回退至多 0.02 nat/token，若有预冻结的可执行子集则执行率下降至多 1 个百分点。记录失败成本在内的每次成功耗时与 token。发现泄漏、mask 错位、大量跳步时该臂停查。小样本难分或护栏失败就保留原方案；锁定后只用另 **48 题/12 族**隐藏 test 作一次确认。这些门槛是预注册建议，尚无本项目胜出配置。留出冻结（本地附件未发布）
