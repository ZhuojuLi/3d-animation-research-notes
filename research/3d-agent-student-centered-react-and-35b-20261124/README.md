## 需要长期对齐的研究方向

### 完整 episode 与验收口径

- 主要训练和评价单位是“生成→执行→观察→修改→复验→交付”的完整 Agent episode，不是压缩后的题目→最终代码，也不是单轮代码 RL。
- `Accepted@1` 指一次完整、独立、无人工接管的 Agent 运行最终通过验收。
- 第一阶段质量优先，轮数、token 和时间只记录作诊断，不作为主要惩罚，避免模型少检查和提前交付。

### 学生中心数据与工程前提

- 保留 249 条完整 ReAct 作冷启动，但主攻学生真实状态上的教师纠偏，而不是只增加教师从头成功轨迹。
- 核心链路：学生交互→定位首个关键错误→恢复错误前快照→教师局部纠偏→学生继续→独立验收。
- 沙盒需要支持文件、浏览器/场景、相机/时间轴、消息与图片引用、证据哈希、模型和工具版本的可恢复快照与共享前缀分支。
- 成功轨迹仍需动作级审查；错误动作可屏蔽正例损失或作为偏好负例，真实恢复过程保留。
- 视觉数据强调“当前截图→具体可见问题→对应修改→新版本新图→缺陷消失”的因果关系，不能把截图只变成口头评价或文本摘要。

### 分阶段实验

沿用原文 A→F：当前混合 SFT→真实修复与动作选择性屏蔽→学生状态教师纠偏 SFT→同前缀分支偏好→完整 episode 结果 RL→独立视觉过程信号。先证明学生中心数据的增量，再扩大 RL，避免同时改数据、偏好、RL 和视觉奖励。

### 学生基座与思考协议

- 35B-A3B 只作为候选：先与 27B 在相同 Harness 配对，再做相同数据短 SFT；质量不降才切换主开发线。激活参数少主要可能加速 rollout，不意味着全参数训练按 3B 成本运行。
- 教师批量轨迹建议 `high`，难题救援、关键错误归因和审核建议 `max`；学生建议以 `high`＋保留历史思考作为主档候选，`max/xhigh` 只通过质量上限对照决定。
- 学生失败采集、RL rollout、评测和目标部署应尽量统一模型、思考配置、历史保留和上下文压缩协议；不同档位不能混在同一优势组里。
- 教师高档思考不等于原样高权重监督学生；动作、证据利用、代码和关键思考需要分层处理。

## 证据边界

这是**用户提供的调研原文归档**，不是本轮独立文献复核。RLEF、DAgger、SCoRe、SceneAssistant、CADCodeVerify、长上下文 SWE Agent 的具体数字，Qwen3.6／3.8 与 35B-A3B 的准确型号，以及 Kimi K3 的 `low/high/max`、默认档位和 Preserved Thinking 接口支持，都应在实际引用或实施前对照一手资料与当前服务重新核验。

原文中的档位是实验建议，不是已经确认可用的本地模板参数。若本地服务只支持思考开关，不人为添加 `high/max` 参数。原始 27B 继续作为质量对照，当前训练与数据采集不因归档而自动变更。
