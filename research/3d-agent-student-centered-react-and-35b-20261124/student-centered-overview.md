本文汇总本目录四份调研及其落地复核，便于后续统一任务范围、数据采集和训练口径。它不是新的实验报告，不代表已经启动 correction SFT、DPO、RL 或更换学生基座；实际执行以最新项目决定和验收记录为准。

## 一、任务范围

组内目标是：训练一个能够在沙盒中，通过多轮执行、观察和返修，交付高质量 2D／3D 可执行视觉内容的 Agent。

只包含三条任务轨：

| 任务轨 | 主要工作 | 核心验收 |
|---|---|---|
| 3D 动画 | Three.js 场景、机构、时间、相机、交互和视觉返修 | 离线交付、时间一致性、机构约束、交互、关键动作可见 |
| 3D 打印 | CadQuery／OpenSCAD 参数化建模、几何检查和导出 | 尺寸、特征、有效实体、拓扑、壁厚、GLB/3MF 回读 |
| 2D 动画 | 2D 绘制、时间编排、播放暂停、拖动和视觉返修 | 确定性时钟、循环、交互、关键帧和视觉质量 |

PR、前端、后端不进入组内训练数据配比、采样优先级、验证器、RL 奖励、checkpoint 选择和质量看板。通用代码只作为能力底座和防遗忘回放。

三轨分别报告 `Accepted@1`：一次完整、独立、无人工接管的 Agent episode，最终通过该轨全部必要验收。共享 episode 定义，不共享具体验收项。没有冻结题集的轨道记 `N/A`，不能记 0，也不能纳入综合平均；任一轨退化必须单列，不能被其他轨提升抵消。

当前成熟度不同：

- 3D 动画：已有首版训练、249 条 ReAct 和 60 题配对评测，需补完整请求、快照、真实纠偏和 mutation。
- 3D 打印：已有 CadQuery、GLB/3MF 回读和少量真实案例，可演示，尚未形成稳定 benchmark。
- 2D 动画：当前工作区未找到独立 Agent 项目或题集，需要新建 runner、任务规格、确定性时钟、验收和基线。

## 二、为什么从教师轨迹转向学生中心纠偏

首版方法是“万级 Aodi 代码数据 + 249 条 Kimi 完整 ReAct”的混合 SFT。它提供代码和工具使用冷启动，但训练与部署存在状态分布不匹配。

教师轨迹通常覆盖：教师写出基本正确的代码→得到基本正常的画面→少量抛光→成功交付。

学生实际面对：学生写错机构或相机→工作区已有错误代码→画面出现遮挡、残影或错误运动→可能已经做过失败修改→上下文中充满自身错误和工具反馈。

因此需要专门学习“已经把事情弄坏以后，下一步如何恢复”。首版实测也支持这一方向：dev 为原版 0/12、学生 2/12；test 为原版 1/48、学生 3/48，生成无净增，修复和局部编辑各仅 1/12。学生 test 观察 token 约为原版两倍，说明训练完成不等于质量或效率已经达标。

## 三、学生做、教师教的数据采集流程

核心链路：

```text
当前学生独立执行任务
→ 每轮保存动作、观察和沙盒快照
→ 学生继续，直到成功、失败、循环或预算耗尽
→ 独立验收并分类失败
→ 定位首个关键错误
→ 恢复错误前快照
→ 教师只纠正关键动作或最小恢复片段
→ 学生从该状态继续
→ 必要时教师再次介入
→ 最终独立验收
→ 转成 correction SFT、RFT 或分支偏好数据
```

关键约束：

1. 教师不是从头重做，而是在学生真实状态上示范下一步。
2. 首个关键错误不一定是第一个编译错误，也可能是该看图时盲改、该回拖时只看静帧、该局部编辑时重写整个场景、证据不足就交付等决策错误。
3. 错误分析员可以回看后续失败来定位介入点；介入点和理由冻结后，纠偏执行者只能读取错误前 manifest，不能读取后续答案、隐藏断言或最终验收。
4. 教师介入后的成功必须标为 `assisted success`，不计学生 `Accepted@1`。后续学生独立重跑才能证明独立恢复能力。
5. 第一条独立 episode 永远单独保留；其余预定试次用于失败挖掘、稳定性和分支研究。`pass@K` 不替代 `Accepted@1`，同前缀分支不冒充独立 case。
6. 先用 K=2 做工程 canary，快照、身份和验收稳定后再按预定 K=4 正式采集；高价值边界题才考虑 K=8。

例如，学生只检查静帧便准备交付时，教师不应重写整个场景，而应示范：执行乱序 `renderAt` 和回拖检查→发现同一时刻画面不一致→定位历史状态未重置→修改对应代码→用同一检查复验。学生随后继续完成剩余任务。

## 四、数据怎样用于训练

### 1. 冷启动与真实修复

保留 Aodi 代码底座和 249 条完整教师 ReAct，补真实修复、局部编辑、健康保持和正确停止轨迹。完整保留推理、工具调用、日志、状态、原始截图、裁剪、交互、修改、复验和最终交付，不再把轨迹压缩成“题目→最终代码”。

最终成功不表示所有中间动作都值得模仿。逐 turn 标签包括：

- `productive`：有效推进；
- `recovery`：从错误状态恢复；
- `neutral`：可接受但非必要；
- `invalid`：格式错误或无效命令；
- `stale`：使用旧截图或旧证据；
- `regressive`：引入回归或破坏非目标状态；
- `premature`：证据不足提前交付。

错误动作可屏蔽正例损失或留作偏好负例，后续真实恢复过程仍保留。标签指南需经过校准，不能由教师自己标自己为正确。

环境日志、工具返回和图片观察不算生成目标。工具选择、控制参数、长代码、assistant 正文和思考分别统计损失，不再用统一“工具调用权重 2”同时放大工具决策和大段 `Write.content`。

### 2. 学生中心 correction SFT

教师纠偏动作作为正例，学生原错误动作可留作负例。主对照为：

```text
同一学生基座、相同预算：
完整教师轨迹冷启动
vs
完整教师轨迹冷启动 + 学生真实状态教师纠偏
```

只有新 dev 上的 `Accepted@1`、真实修复、视觉修复、非目标保持等指标改善，才能证明学生中心数据的增量。

### 3. 共享前缀分支偏好

从同一学生快照分出：

```text
相同任务、代码、截图和消息历史
├─ rejected：学生原动作，后续失败或引入回归
└─ chosen：教师纠偏动作，后续独立验证改善或成功
```

这比完整教师答案与完整学生答案的比较更接近局部信用归因。例子包括：看当前新图优于使用旧图、先回拖复现优于盲改、局部修改优于重写整个场景、复验后交付优于自称完成、健康场景正确停止优于继续抛光。

### 4. 完整多轮 Agent RL

只有在 correction SFT 已证明有效、验证器能抓注入缺陷、奖励存在方差、快照与工具协议稳定后，才扩大 RL。

学生从同一题独立采样多个完整 episode，每条都允许执行、观察、修改和复验，最终由独立验收计算奖励。主奖励来自正式交付、离线冷加载、语义与几何、视觉可读性、非目标保持及版本一致性。

第一阶段不设置统一的轮数、token 或时间惩罚，成本只记录。不得奖励工具调用次数、看图次数或自检数量，只给独立确认的真实状态改善。基础设施失败单列，不惩罚学生。

后续可从共享前缀做短程 RL，把信用集中到关键决策；视觉过程奖励或视觉偏好单独消融，不与首次 RL 同时引入。

## 五、实施前必须补齐的基础设施

### A. 完整请求、快照与分支账本

每轮保存真实 system、工具 schemas、messages、图片字节及顺序、采样参数、输出、剩余预算和 compaction 后请求；同时保存文件、浏览器、场景、相机、时间轴、代码、证据、验证器和运行时哈希，以及 `parent_snapshot_id`、`branch_id`、`assisted` 身份。

快照不是简单复制目录。采用“内容寻址工作区 + 新浏览器 + 固定种子/虚拟时钟 + 确定性事件重放”，不假设可直接序列化 GPU/WebGL 内存。

首轮建议至少 20 个前缀做双重恢复验收：恢复后注入同一条已记录动作，要求文件、工具结果、数值状态和固定条件下的定帧截图一致。未通过的前缀不得用于分支训练。这个数量是工程门槛建议，不是普适常数。

### B. 新评测集与完整验证器

旧 dev/test 已用于首版评测和复盘，降为历史回归、失败诊断和工程调试，不再作为下一版“全新 unseen”终验。新 dev/test 需要新题族和完整场景故障谱系，并按 parent case、同源 fixture 和派生分支整体隔离。

验证器至少覆盖静止、回拖残影、机构漂移、错误接触与释放、遮挡、相机错位、外置 JS、未交付、非目标修改、陈旧证据和提前交付。先用 golden、单缺陷 mutation、健康近邻和合理替代实现校准。视觉无法判断记 `unknown`，不能硬转成成功或奖励。

### C. 35B-A3B 技术准入

Qwen3.6-35B-A3B MoE 只是候选学生，27B 保留质量对照。A3B 主要可能提高 rollout、失败采集和 RL 吞吐，不表示全参数训练只按 3B 成本运行。

35B 必须使用：

```text
架构注册：qwen3_5_moe
训练模板：qwen3_5
```

不能照搬 27B 的 Ready、启动命令、并行配置或导出结论。必须重新完成模板 golden、零更新 HF→Megatron→HF 往返、全参数 MoE 更新、专家路由与辅助损失、长样本多图工具轨迹、checkpoint 恢复、导出回载和完整 Agent episode smoke。

学生配置统一为：

```text
enable_thinking = true
preserve_thinking = true
```

失败采集、纠偏、RL、评测和目标部署尽量保持同一思考保留和上下文压缩协议。教师 `high/max` 只是教师 API 请求字段，不能映射成学生档位；服务端是否实际采用所请求档位仍需核验。

## 六、最终路线与晋级条件

长期路线：

```text
代码底座和完整教师 ReAct 冷启动
→ 真实修复、局部编辑和动作选择性屏蔽
→ 学生真实状态上的教师局部纠偏 SFT
→ 成功学生轨迹 RFT + 同前缀分支偏好
→ 完整多轮 episode 的终局结果 RL
→ 共享前缀短程 RL
→ 独立视觉过程奖励消融
```

当前实际顺序：

```text
补请求捕获 / 快照 / assisted 账本
+ 35B 推理与 MoE SFT smoke
+ 新 dev/test / mutation / 学生失败分类
→ 小规模学生纠偏试点
→ 新 dev 证明 correction SFT 的 Accepted@1 增量
→ 分支 DPO
→ 完整 episode RL
```

如果 correction SFT 不能改善真实修复，或训练 reward 上升而新 dev `Accepted@1` 不升，就不进入下一阶段。

一句话概括：首版是教师“做给学生看”；下一版是学生先做，教师在学生真正走错的位置教它如何恢复，最后通过独立重跑检验学生是否学会。
