# 三轨视觉范围与 35B MoE smoke｜联合审查结论

> 公开整理版 · 2026-11-25。保留成文时点的记录；计划、文献结果和本地实测请分别理解。 环境路径已泛化，未收录的附件已标注；发布范围见 [整理说明](../../PROVENANCE.md)。

2026-11-24 · 主 Agent + Opus 5.5。第四份用户方案已原样归档；本页记录本地资产核查、Opus 补充与最终取舍。未启动新训练或采集。

## 一、范围已明确，但三轨不能按同一成熟度规划

用户确定只做 **3D 动画、3D 打印、2D 动画**。PR、前端和后端不进入组内配比、验证器、奖励、checkpoint 和质量看板；通用代码只作底座与防遗忘回放。

| 任务轨 | 本地已有资产 | 当前准确定位 | 主要缺口 |
|---|---|---|---|
| 3D 动画 | 首版训练、249 ReAct、60 题配对评测 | 可评测，需补基础设施 | 新 dev/test、完整请求、快照、真实纠偏、完整 mutation |
| 3D 打印 | V1、CadQuery、GLB/3MF 回读、两个单次真实 case | 可演示，尚未形成稳定 benchmark | OpenSCAD 正式导出、OS 沙箱、浏览器验收、独立题集和校准；无切片/实物/材料验证 |
| 2D 动画 | 当前工作区未找到独立 Agent 项目或题集 | 新建设轨 | runner、任务规格、确定性时钟、独立验收、种子题、基线与数据 |

“未找到 2D 项目”是对当前工作区和研究索引的核查，不推断其他归档或他人目录绝对不存在。

## 二、组内指标的正确用法

主报始终是：

```text
Accepted@1（3D 动画）
Accepted@1（3D 打印）
Accepted@1（2D 动画）
```

- 共享的是 episode 定义：一次完整、独立、无人工接管运行最终通过该轨全部必要验收。
- 不共享必要验收项：3D 查机构/时间/交互与可见性；打印查尺寸/实体/拓扑/壁厚和导出回读；2D 查关键帧/循环/播放暂停/拖动与视觉质量。
- 2D 尚无题集时写 **N/A（无题集）**，不能写 0，也不能纳入等权平均。
- 等权汇总只作组内二级指标，不与其他组混算；任一轨退化必须单列，不能被其他轨提升抵消。
- Opus 提议“每轨至少 60 题、人工一致率至少 90%、连续两个 checkpoint 可复现、请求快照完整”作为汇总门槛参考，不是已验证的通用常数。实际题量和阈值应在看结果前按轨预注册。

**统计边界。** 缺失必要成果证据、预算耗尽和模型导致的崩溃是失败；基础设施故障记 `infra_unknown`；人工接管记 assisted，均不计 Accepted@1，但不能混成同一种学生失败。每题多次运行的 `pass^k` 只作稳定性诊断，主指标仍取预先定义的第一次独立 episode。

## 三、35B 工程口径与 27B 对照的例外

35B 学生固定：

```text
enable_thinking = true
preserve_thinking = true
架构注册 = qwen3_5_moe
训练模板 = qwen3_5
```

27B 对照继续使用自己的 qwen3_8 模板和历史 medium 协议。所谓“发现 qwen3_8 即停止”**只针对 35B 的训练、导出和推理链路**，不能误改 27B 对照。两臂应分别绑定：

```text
model_revision
architecture_registration
template_version + hash
tokenizer_revision
ready_dataset_path + hash
runtime/export config
```

教师 `high/max` 只记录为教师 API 请求字段，不映射到学生。学生只比较实际可实现的思考开关和历史保留机制，不再使用 high/max 名称。

## 四、修正后的 smoke 硬门槛

### G0：配置、数据和路径绑定

35B 的训练、导出、推理均明确显示 `qwen3_5_moe/qwen3_5`。每个 Ready 文件带架构和模板 manifest，loader 拒绝混用 27B qwen3_8 编码。记录 EP/TP/PP/CP、视觉冻结、代码与模型 revision。

### G1：共享协议 golden + 分轨 golden

共享 golden 覆盖文本、完整代码、工具调用/结果、图片、历史思考、压缩消息、并行工具结果和最长真实轨迹，逐 token/字段检查 EOS、思考边界、调用配对、图片数、observation mask、loss_scale 及训练/在线渲染一致。

分轨 golden 至少包括：

- 3D：多帧截图、定帧、拖动、局部编辑和非目标保持；
- 打印：CadQuery 参数变化、GLB/3MF 回读、尺寸/水密/壁厚；OpenSCAD 在支持前明确 N/A；
- 2D：确定性时钟、播放暂停、循环接缝、拖动与关键帧。

### G2：先做零更新往返，隔离转换问题

在任何参数更新前执行：

```text
原始 HF
→ Megatron/分布式格式
→ 零更新导出 HF
→ 推理服务
```

逐层比较结构、权重数量、专家与 MTP 组件、模板和固定输入输出。先定义数值容差与允许的内核差异，避免把后续训练造成的正常变化与导出错误混淆。零更新往返不过，不进入更新 smoke。

### G3：短样本全参数 MoE 更新

确认有限 loss/梯度、专家路由与 EP 通信、辅助负载指标、参数分组、视觉冻结和 checkpoint。保存实际 trainable/frozen 名称，尤其检查 MoE 命名变化没有让视觉组件误训练或语言组件误冻结。

小数据过拟合只用 train-only golden，验证可学习性；不能拿隐藏 dev/test 做过拟合，也不能仅凭进程退出或 loss 下降判全链路通过。

### G4：真实长样本与导出回载

使用近最长真实轨迹、多图多工具、压缩消息、长代码与局部编辑，完成前后向、恢复、导出和服务回载，记录峰值显存、吞吐和截断。

导出检查全部专家、MTP 和视觉权重，核对 tensor 数/形状/索引、BF16 路径和模板；固定输入比较原始 HF、导出 HF 与服务的结构及数值差异。MTP 可先关闭建立基线，再单独验证启用后的正确性与收益，不把加速组件默认为无损。

### G5：三轨各自的完整 Agent episode

| 轨道 | 最小闭环与独立验收 |
|---|---|
| 3D | 连杆或已有机制初版→多帧/定帧→修改→新帧证明周期/机构变化→单文件冷加载与交互验收 |
| 打印 | 参数化支架→几何检查→改参数重建→尺寸随参数变化→GLB/3MF 回读和实体/拓扑/壁厚验收 |
| 2D | 确定时钟的短循环→暂停/拖动→修改缓动→新关键帧证明变化→循环与交互验收 |

每轨都必须出现“修改后的新证据”，不能拿旧截图或旧日志完成交付。打印只能声明数字几何和导出检查，不能据此声称可切片、实物打印、材料强度或实物公差合格。

## 五、Opus 补充与最终修正

Opus 原文：[三轨验收范围审稿](opus-visual-scope-review.md)。成功 session `5cecbcbf-a431-4ce9-80e6-a907ba6ab25c`，`is_error=false`，`modelUsage=claude-opus-5-5`。前两次含完整训练/MoE 细节的任务被风控拒绝，原始结果保留；最终联合范围仅限其成功完成的视觉软件验收部分，MoE 细节由本地源码核查支撑。

采纳：

- 三轨成熟度分别为可评测、可演示、未开建；2D 为 N/A 而非 0。
- 共享 runner、审计、证据归档、断网/浏览器错误和统计；按轨独立语义验证器。
- 每轨都需要修改后新证据、负例和人工校准，单次 smoke 只证明可运行。
- 打印声明严格限定在数字几何和导出；2D 先建确定性时钟与种子题集。

修正：

1. Opus 将缺证据/崩溃全部列失败，联合口径细分为模型失败、budget_exhausted、infra_unknown 和 assisted，避免基础设施问题惩罚学生。
2. `pass^k`、每题 3 次只用于稳定性，不替代第一次独立 Accepted@1。
3. Opus 给出的 60 题、90% 一致率、0.1mm、2px 和 5pp 都是候选起点，不能跨任务直接当通用阈值；尺寸/像素容差按题面、单位和视口预注册。
4. OpenSCAD 未支持时，OpenSCAD 专项任务为 N/A；CadQuery 任务仍可在自身独立验收完善后评价，不因另一种技术栈缺失全部冻结。

## 六、执行顺序

```text
G0/G1 配置与 golden
→ G2 零更新往返
→ G3 MoE 更新
→ G4 长样本与导出回载
→ G5 三轨 episode
→ 27B/35B 短 SFT 配对
→ 学生中心纠偏证明增量
→ DPO/RL
```

3D 打印先补 OS 隔离和独立几何验收，2D 先建最小 runner/时钟/题集/验收；在三轨各自有冻结题集和配对基线之前，不发布组内综合分。
