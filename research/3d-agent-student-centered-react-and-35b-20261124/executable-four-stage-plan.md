# 一、先明确训练任务

## 1. 任务定义

你要训练的不是 one-shot 代码生成器，而是**多模态、多轮、可使用工具的 3D 编程 Agent**：

```text
理解需求
→ 编写或修改完整代码
→ 调用沙盒执行
→ 阅读日志、数值状态和真实截图
→ 拖动时间轴、切换视角、裁剪和检查交互
→ 定位问题并修改
→ 重新构建和复验
→ 在证据充分时正式交付
```

模型负责推理和发出动作，环境负责实际执行并返回观察。

## 2. 优化目标

主指标只有一个：

> **Accepted@1：一次完整、独立、无人工接管的 Agent episode，最终交付通过全部必要验收。**

必须同时满足：

- 正式交付；
- 离线重建和冷加载成功；
- 动画、机构、几何和交互语义通过；
- 修复／编辑任务非目标状态保持；
- 关键动作实际可见，视觉质量达标；
- 交付代码、截图和检查报告版本一致。

辅助指标包括：

- 真实缺陷修复成功率；
- 视觉缺陷修复成功率；
- 健康场景误改率；
- 非目标保持率；
- 陈旧证据使用率；
- 证据不足提前交付率；
- 无意义循环和模型原因超时率。

**轮数、token、耗时先只记录，不进入主要惩罚项。**

# 二、模型与思考档位

## 1. 学生架构

优先试验 **35B‑A3B**，但保留 27B 作为质量基线。

切换条件应是：

```text
相同 Harness、相同数据、相同评测预算下
35B‑A3B 的 Accepted@1 不明显下降
并且完整 episode 吞吐明显提高
```

不要只看 token/s，还要看：

- 每 GPU 小时完成的完整 episode 数；
- 每个 Accepted 成果的总墙钟时间；
- 长上下文后半段的决策质量；
- 工具格式错误、空响应和截断率。

注意：A3B 主要降低推理激活量，**不代表全参数训练只占 3B 的显存和优化器成本**。

## 2. 教师档位

| 教师工作 | 推荐档位 |
|---|---|
| 常规完整轨迹采集 | `high` |
| 学生全失败难题救援 | `max` |
| 首个关键错误归因 | `max` |
| 复杂视觉返修 | `max` |
| 最终独立审核 | `max` |

如果教师只能选一个档位，选 `max`。

## 3. 学生档位

正式推荐：

```text
思考开启
Preserved Thinking 开启
若服务支持 low／medium／high：使用 high
medium 只用于工程联调
max／xhigh 用于质量上限对照
```

以下环节必须尽量保持一致：

```text
正式学生失败采集
学生中心纠偏
多轮 RL rollout
模型评测
最终部署
```

不要在 `medium` 下采集失败，却默认它能代表 `high` 下的学生错误分布。

# 三、训练方法：按四个阶段推进

## 阶段一：完整轨迹 SFT 冷启动

### 数据组成

保留三类数据：

1. 万级 answer-only 代码数据：负责代码底座和能力保持；
2. 教师完整 ReAct 轨迹：负责工具使用、观察和交付；
3. 真实修复、局部编辑、健康保持和正确停止轨迹：补当前能力缺口。

不要只保留最终代码，完整保留：

- 推理；
- 工具调用；
- 日志和状态观察；
- 原始截图及裁剪；
- 时间轴和交互操作；
- 修改及复验；
- 最终交付。

### 损失屏蔽

建议按内容类型分别监督：

| 内容 | 初始处理 |
|---|---|
| 环境日志、工具返回、图片观察 | 不计算生成损失 |
| assistant 正文和代码 | 权重 1.0 |
| 工具选择、工具名和控制参数 | 权重 1.0 左右 |
| 教师原始思考 | 比较 0、0.25、0.5 三档 |
| 格式错误、无意义重复动作 | 屏蔽正例损失 |
| 真实错误后的有效恢复动作 | 保留，可适度加权 |

不要再用“工具调用统一权重 2”，因为它会同时放大工具决策和大段 `Write.content`，让真实梯度贡献难以解释。

### 首轮训练参数

为了和首版形成可比对照，可以从：

```text
全参数训练
学习率：5e-7～1e-6
epoch：1
warmup：约 3%
调度：cosine
```

开始。

首版 `global batch＝1` 可以作为历史对照，但不建议继续把它当默认。下一轮应通过梯度累积让每次更新覆盖多条轨迹，并按**有效监督 token**统计数据配比，而不是只看样本条数。

Agent 数据曝光可以从当前的约 12％逐步提高到约 30％，再与 50％档位做消融；新增 Agent 数据中，真实修复和学生纠偏应占至少一半。保留一定通用代码回放，监控能力遗忘。

## 阶段二：学生中心纠偏，作为主要数据引擎

这是下一轮最重要的工作。

### 每轮流程

```text
当前学生对每题运行 K 个完整 episode
→ 保存每轮动作、观察和沙盒快照
→ 独立验收并分类失败
→ 定位首个关键错误
→ 恢复错误前快照
→ 教师只纠正关键动作或最小恢复片段
→ 学生继续执行
→ 必要时再次介入
→ 最终独立验收
→ 转成 correction SFT、RFT 或分支偏好数据
```

首轮可以：

```text
每题 K＝4
边界题或高价值题增加到 K＝8
```

分流规则：

| 学生表现 | 数据用途 |
|---|---|
| 全部成功 | 少量 RFT 和通用回放，降低采样频率 |
| 有成功有失败 | 偏好对、后续多轮 RL 的重点题 |
| 全部失败 | 教师纠偏、简化课程或补充基础能力 |
| 沙盒基础设施失败 | 标记 `unknown`，不作为学生负例 |

### 教师介入原则

- 教师不是从头重做，而是教学生“在这个真实状态下下一步怎么走”；
- 首个关键错误不一定是编译错误，也可能是该看图时盲改、该拖动时只看静帧；
- 学生错误动作留作负例，教师纠偏动作作为正例；
- 教师介入后的成功标记为 **assisted success**，不能计为学生 Accepted@1；
- 记录教师介入次数和学生独立完成动作比例。

## 阶段三：共享前缀的分支偏好训练

当学生已经具备基本修复能力，但关键决策仍不稳定时，加入分支 DPO 或类似偏好优化。

最好的偏好对是：

```text
相同任务、相同代码版本、相同截图和消息历史
├─ rejected：学生原始动作，后续失败或引入回归
└─ chosen：教师纠偏动作，后续独立验证改善或成功
```

例如：

- 看当前版本新截图，优于拿旧截图判断；
- 先拖动复现残影，优于直接盲改；
- 局部修改目标函数，优于重写整个场景；
- 复验后交付，优于自称完成；
- 健康场景正确停止，优于继续抛光。

首轮搜索起点可以是：

```text
DPO 学习率：1e-7～5e-7
β：0.05～0.1
epoch：1
```

保留 chosen 动作的 SFT 损失或一定比例的 correction SFT 回放，避免长代码 DPO 带来风格和长度漂移。

## 阶段四：完整多轮 Agent RL

只有满足以下条件后再扩大 RL：

- correction SFT 已证明能提升真实修复率；
- 验证器能识别已知注入缺陷；
- 学生在一批任务上有成功、有失败，奖励存在方差；
- 快照、工具协议、解码参数和证据哈希已经稳定。

### 首轮配置

```text
算法：轨迹级 GRPO／DAPO 类方法
每题完整 episode 数：先 4，稳定后可增至 8
rollout temperature：可从 1.0 起步
折扣：终局奖励基线可使用 γ＝1
奖励：最终 Accepted 占主导
长度／轮数惩罚：不设置
```

解码配置必须固定并记录，不要训练中途中途切换 `top_p`、`top_k` 等参数，避免 rollout 分布和训练假设不一致。

### 奖励建议

第一版采用：

```text
最终独立 Accepted：主奖励，占总信号至少约 80%
独立验证的真实进展：辅助信号，不超过约 20%
无意义循环、陈旧证据、提前交付：负例或零奖励
基础设施失败：剔除，不惩罚学生
正常观察和认真复验：不惩罚
```

过程奖励只能给独立确认的状态改善，例如：

- 首次可运行；
- 关键语义断言新增通过；
- 已知视觉缺陷在新截图中消失；
- 非目标保持且目标缺陷修复。

不要给“调用工具、查看图片、编写自检”本身奖励。

先跑完整 episode 的终局奖励基线，再利用共享前缀做短程 RL，把信用集中到关键决策上；不要一开始就引入复杂的逐步价值模型。

# 四、验证器和数据细节

## 1. 验证器必须独立

不能采用：

```text
模型自己写代码
→ 模型自己写测试
→ 模型自称全部通过
→ 直接作为高奖励或训练正例
```

需要：

- 独立测试作者或独立生成流程；
- 隐藏语义和视觉检查；
- 非目标状态差分；
- 多帧、多视角和交互检查；
- mutation testing：主动注入残影、杆长变化、错误释放、遮挡、非目标修改，确认验证器能抓住。

## 2. 快照是核心基础设施

每个关键节点保存：

- 文件和代码版本；
- 浏览器、场景、相机、时间轴和交互状态；
- 完整消息历史及图片引用；
- 当前证据哈希；
- 模型和解码配置；
- 工具及依赖版本。

没有快照，就无法高质量完成教师接管、共享前缀偏好和短程 RL。

## 3. 上下文协议要训练、评测一致

首版的训练上下文、评测上下文和自动压缩窗口可以作为对照起点，但必须检查：

- 训练是否见过压缩后的消息形态；
- 历史 `reasoning_content` 是否按协议保留；
- 图片到达顺序是否与真实在线 episode 一致；
- 压缩后工具调用与工具结果是否仍然配对；
- 单轮输出是否经常因 token 上限截断。

若截断明显，应提高输出上限并重新评估，而不是让模型学习在截断状态下仓促交付。

# 五、实验顺序与停止条件

建议严格按以下顺序：

```text
E0：27B 与 35B‑A3B 基座配对测试
E1：确定学生 high 与 max／xhigh 的质量差异
E2：完整真实修复轨迹 SFT
E3：学生真实状态上的教师纠偏 SFT
E4：成功学生轨迹 RFT＋共享前缀分支偏好
E5：完整多轮 episode 的结果 RL
E6：共享前缀短程 RL
E7：视觉过程奖励或视觉偏好的独立消融
```

每一步都保留上一阶段最佳 checkpoint 作为对照。

出现以下情况时，不要继续加 RL：

- 训练 reward 上升但隐藏 Accepted@1 不升；
- 模型增加工具调用却没有提高修复率；
- 验证器抓不到人工注入的已知缺陷；
- 教师介入后的成功被误当成学生独立成功；
- 视觉裁判与人工盲评持续不一致；
- 学生失败几乎全为零奖励且没有可学习的部分进展。

# 最终推荐配置

如果现在要定一版执行配置，我会写：

```text
学生：35B‑A3B 候选，27B 保留质量对照
教师：常规 high；救援、关键错误归因和终验 max
学生档位：high＋Preserved Thinking，正式链路统一
冷启动：完整轨迹 SFT＋选择性动作屏蔽＋通用代码回放
主攻方法：学生真实状态上的教师纠偏 SFT＋成功轨迹 RFT
偏好阶段：同前缀的教师纠偏动作优于学生错误动作
RL 阶段：完整多轮 episode 的终局质量奖励，之后做共享前缀短程 RL
首轮 K：4，边界题增至 8
SFT 学习率：5e-7～1e-6，1 epoch
DPO 起点：1e-7～5e-7，β 0.05～0.1
RL：temperature 1.0 起步，不设置轮数惩罚
主指标：Accepted@1
成本指标：只记录，质量稳定后再优化
```

最核心的一句话是：**先用完整轨迹教会学生“会做 Agent”，再用学生真实状态上的教师纠偏教会它“失败后会恢复”，最后用多轮 RL 提高独立交付质量。**
