# 交互式 Three.js Agent 实验基础设施审稿

> 公开整理版 · 2026-11-25。保留成文时点的记录；计划、文献结果和本地实测请分别理解。 环境路径已泛化，未收录的附件已标注；发布范围见 [整理说明](../../PROVENANCE.md)。

标注：【实】题述已核实；【推】审稿人推断；【议】建议。

## 0 总评
【实】test 1/48→3/48，大量轨迹在 3600s 截断，学生侧观察 token 约为对照的 2.07 倍。【推】只差 2 题，配对检验不显著；预算不对等，提升无法归因。【议】下文 P0 通过前，只做工程，不扩大采集。

## 1 P0 一致性要求
- **只快照文件不够。**【推】可恢复状态应包括：工作区字节；进程状态（dev server、端口、环境变量、种子）；浏览器状态（URL、DOM、JS 堆、WebGL 上下文、相机、动画时钟、拖动中的指针）；消息前缀；剩余 token/轮次/墙钟预算。
- **浏览器靠确定性重放来重建，不做内存快照。**【议】冷加载同一版本页面，固定种子，用虚拟时钟接管 `performance.now`/rAF/Date，按事件日志（指针、键盘、时间推进）重放到目标帧。然后比对数值状态和定帧截图哈希；不一致就标 `restore_failed`，禁止从这里分支。浏览器版本、软件渲染（SwiftShader）、视口和 DPR 都固定。
- **内容寻址。**【议】每个 turn 生成一份 manifest，记录 `workspace_tree_hash`、`replay_log_hash`、`message_prefix_hash`（含完整 system、schemas、采样参数）、图片 sha256、验证器 hash 和镜像 digest；`turn_id = hash(manifest)`。每条证据都带上它产生时的 tree hash，和交付 hash 对不上就作废。
- 【实】旧轨迹缺 system、schemas 和逐次请求。【推】它们只能近似恢复，应标 `legacy_approx`，不进主分析。

## 2 最小 restore 验收
取 ≥20 个前缀，覆盖三类任务，并包含拖动中途、server 运行中两种情形。每个前缀恢复两次（R1、R2），与原始记录 O 比较。
- **必须字节一致**：tree hash、待发请求体 hash（消息、图片字节、schemas、参数）、预算计数、虚拟时钟下的定帧截图（软件渲染下像素差=0）、数值状态 JSON。
- **允许差异（走白名单）**：时间戳、PID、临时路径、异步日志交织、模型采样输出。
- **后续结果**：不要求模型续写一致。改为在 R1、R2 上注入同一条已记录的动作，要求工具结果和截图一致。这一步测的是基础设施，不是模型。
- **记录**：`restore_report.json` 逐字段写 diff 和白名单命中；出现非白名单差异即失败。通过线为 100%；另外重复 10 次，统计漂移率。

## 3 介入与分支记账
- **身份**：`case_id → root_run → branch(parent_turn_id, intervention∈{none,teacher}, actor)`。Accepted@1 只取每个 case 的 root 独立运行。`assisted=true` 写入后不可改；统计脚本按 schema 拒绝 assisted 结果混入主指标。
- **防泄漏**：纠偏方只能读取 `parent_turn` 及之前的 manifest，读不到原始后续轨迹、验收结果和隐藏断言。纠偏文本存档，并自动扫描是否含验收数值或答案代码。
- **非独立样本**：同一 case 的分支属于同一聚类，按 case 聚合后做配对比较或聚类 bootstrap。同前缀"原动作 vs 纠偏"作为配对比较，每个前缀续跑 ≥3 次以估计方差。分支点规则预先登记（如"首次验证失败处"），防止事后挑选。
- **结局四分**：pass / fail / infra_unknown / budget_exhausted。infra_unknown 重跑，不计失败，但要上报比例；超过 5% 就阻断分析。

## 4 验证器
- **缺的测试**：①把 18 个数值植入扩展到完整浏览器链路，并补视觉/交付类 mutant：静止、闪烁、相机错位、遮挡、回拖残影、杆长漂移、外置 JS、未交付、改动非目标对象。报告杀死率和存活清单。②对 golden 解重复验收 10 次，结论不得翻转（同时测假阴性和 flaky）。③验证器对 agent 工作区无写权限，agent 可见的检查与隐藏验收分开。
- **冲突裁决**【议】，规则须在看结果前写定：
  - 硬数值失败直接判 fail，盲评不能推翻。
  - 数值通过但视觉为 unknown（空白截图、超时）：重跑；仍 unknown 则单列，并交人工仲裁。
  - 盲评与数值通过冲突：双人盲评后仲裁，报告 κ。

## 5 新栈与数据隔离
- 【实】旧 test 已用于上一版评测。【推】其失败模式已反馈到工程改进中，不再是未见集。
- **新 dev/test**：冻结前与旧题做近重复检测（文本和参考解两方面）。test 由不参与迭代的人保管，只在冻结版本上运行一次。
- **公平配对**：新旧栈用同一批题，固定 token、墙钟、轮次上限和验证器版本；每题每栈重复 ≥3 次。
- **旧 test 可以用于**：回归测试、restore 验收、mutation 底座、分支流程调试。
- **旧 test 不能用于**：宣称泛化提升；在它上面调完阈值后又在它上面报告结果。
