按你本地核查，这两处需要立即改正：**学生 `high vs max` 的对照设计作废，27B 的启动、模板和 Ready 编码也不能迁移到 35B MoE。**是我前面把不同模型和模板的能力泛化了，以下以你的本地实现为准。

# 一、最终范围：只做三个视觉内容任务

你们组的准确目标是：

> **训练一个能够在沙盒中，通过多轮执行、观察和返修，交付高质量 2D／3D 可执行视觉内容的 Agent。**

只包括：

| 任务轨 | 主要能力 | 核心验收 |
|---|---|---|
| 3D 动画 | Three.js 场景、机构、时间、相机、交互和视觉返修 | 离线交付、时间语义、机构约束、交互、关键动作可见 |
| 3D 打印 | CadQuery／OpenSCAD 参数化建模、几何检查和导出 | 尺寸与特征、有效实体、拓扑、壁厚与可制造性 |
| 2D 动画 | 2D 绘制、时间编排、播放暂停、拖动和视觉返修 | 时间一致性、循环与交互、关键帧和视觉质量 |

PR、前端和后端不进入你们组的：

- 训练数据配比；
- 采样优先级；
- 验证器建设；
- RL 奖励；
- checkpoint 选择；
- 组内质量看板。

上一条里的六域总分公式不再适用于你们。组内主报：

```text
Accepted@1（3D 动画）
Accepted@1（3D 打印）
Accepted@1（2D 动画）
```

如果内部必须有一个汇总分，可以暂时三轨等权，但要注明这是组内指标，不与其他组混算。通用代码数据只作为能力底座和防遗忘回放，不承担其他组的目标。

# 二、学生思考配置：不再使用档位概念

35B 学生的主配置统一为：

```text
enable_thinking = true
preserve_thinking = true
```

以下环节全部保持一致：

```text
学生失败采集
教师介入前的学生轨迹
SFT 数据转换
DAgger／学生中心纠偏
多轮 RL rollout
模型评测
最终部署
```

可以做的对照不再是 `high／max`，而是：

| 实验 | 配置 | 目的 |
|---|---|---|
| 主配置 | `enable_thinking=true`＋`preserve_thinking=true` | 目标部署配置 |
| 保留机制消融 | `enable_thinking=true`，不保留历史思考 | 检查长 episode 中历史思考的实际作用 |
| 思考开关消融 | `enable_thinking=false` | 只作基础能力和速度对照 |

教师的 `high／max` 仍然保持不变，因为它属于 Kimi API；不要再把教师档位名称映射到学生。

教师使用 `max` 也不意味着学生存在一个对应的 `max`。学生数据仍按自己的目标模板渲染，并单独记录：

```text
teacher_reasoning_effort
student_enable_thinking
student_preserve_thinking
template_version
tokenizer_revision
```

# 三、35B MoE 的正确工程基线

按你的核查，35B 应使用：

```text
模型／架构注册：qwen3_5_moe
训练模板：qwen3_5
```

不能复用 27B 的：

- `qwen3_5 + qwen3_8` 组合；
- 原启动命令；
- Ready／注册编码；
- TP／PP 等并行配置的默认假设；
- 原导出和加载检查；
- 原长样本训练通过结论。

尤其是首版的 `TP＝4、PP＝4` 只能作为 dense 27B 的历史配置，不能因为 35B 激活参数少，就默认相同并行方式适合 MoE。

# 四、全量实验前必须通过的 smoke 顺序

不要先跑完整 SFT，再发现问题。建议按下面顺序设硬门槛。

## 1. 配置与注册 smoke

确认训练、导出和推理日志都明确显示：

```text
qwen3_5_moe
qwen3_5 template
```

同时记录：

- 代码和模型 revision；
- tokenizer／template 哈希；
- EP、TP、PP、CP 配置；
- 视觉编码器与对齐层冻结策略；
- Ready／注册编码。

任何一环仍显示 `qwen3_8`，都先停止后续实验。

## 2. 模板 golden case

准备几条固定样本，覆盖：

- 普通文本；
- 完整代码写入；
- 工具调用与工具结果；
- 图片观察；
- 带历史思考的多轮轨迹；
- 自动压缩后的消息形态；
- 最长真实 ReAct 样本。

逐项检查：

- 特殊 token 和 EOS；
- `reasoning_content` 边界；
- 工具调用与 `tool_call_id` 对应关系；
- 图片占位和实际图片数量；
- assistant 与 observation 的 loss mask；
- 训练渲染结果与推理渲染结果是否一致；
- 是否意外把教师 API 字段名当成学生模板字段。

## 3. 全参数 MoE 训练 smoke

用少量短样本做前向、反向和优化器更新，确认：

- loss 和梯度为有限值；
- 专家路由与 EP 通信正常；
- 无静默 fallback 到错误模型类型；
- checkpoint 能保存；
- 训练日志中的参数分组符合预期；
- 视觉冻结策略没有因 MoE 参数命名变化而失效。

随后再做一个小数据过拟合测试，验证模型确实在学习，而不只是训练脚本正常退出。

## 4. 导出与回载 smoke

完整走一遍：

```text
checkpoint
→ 重分片／导出
→ BF16 产物
→ 推理服务回载
→ 固定输入回归
```

不能只验证“文件存在、服务能启动”。还要检查：

- 固定输入下的输出或 logits 是否在可接受差异内；
- 工具调用结构是否完整；
- 思考开始、结束和 EOS 是否正确；
- 专家权重是否全部导出；
- Ready 编码是否指向新产物而不是旧 27B；
- 导出后模板是否仍为学生模板。

## 5. 长样本 smoke

必须使用真实长轨迹，不只是合成文本。至少覆盖：

- 接近首版最长样本的真实轨迹；
- 多图片、多工具调用轨迹；
- 压缩后的长上下文；
- 长代码写入与后续局部编辑；
- 前向、反向、导出和回载完整链路。

记录峰值显存、吞吐和截断情况。长样本 smoke 未通过前，不启动全量数据训练。

## 6. 端到端 Agent smoke

最后跑一个最小但完整的 episode：

```text
生成初版
→ 沙盒执行
→ 返回日志和截图
→ 学生根据反馈修改
→ 重新构建
→ 查看当前版本证据
→ 正式交付
→ 独立冷加载和验收
```

这一步主要捕获单步训练 smoke 看不到的问题：历史思考丢失、图片顺序错位、工具结果错配、旧截图引用和导出后行为变化。

# 五、修正后的执行方案

```text
范围：3D 动画、3D 打印、2D 动画
目标：质量优先的多轮视觉内容 Agent
学生候选：35B MoE，27B 保留质量基线
学生配置：enable_thinking=true＋preserve_thinking=true
教师配置：常规 high；救援、关键错误归因和终验 max
Swift：qwen3_5_moe＋qwen3_5 template
前置门槛：配置、模板、训练、导出、长样本和端到端 smoke 全通过
训练主线：完整轨迹 SFT→学生中心纠偏／RFT→同前缀偏好→多轮 Agent RL
评测：三轨分别报告 Accepted@1，不与其他组混算
```

在这些 smoke 完成之前，35B 只能称为**候选学生架构**；通过之后，再进行 27B 与 35B 的短 SFT 配对比较，最后决定是否正式切换。这样不会因为模板或导出问题，把一次本可有效的 MoE 训练误判成方法失败。
