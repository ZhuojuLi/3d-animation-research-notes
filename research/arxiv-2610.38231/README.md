## 1. 核心问题与作者发现的真实痛点

真实 3D 生产流高度依赖在既有复杂程序上做局部或结构修改（兼顾速度与非目标部件无损保留）。作者构建首个面向完整程序化 3D 资产（108 个源程序，**均值 613 行 / 中位 440 行**，远超 `BlenderGym` 的 40 行与 `CADBench` 的 36 行，Table 7）的编辑基准 **`3DCodeEdit`（2,592 题，12,528 条人工复核 Checklist）**，横评 **17 款主力模型 + 44 款历史模型（共 76 组配置）** 揭示三大核心痛点：

1. **结构级与开放式编辑全线吃紧**：17 款模型单轮平均全通率（All-Pass Rate）仅 **`37.1%`**，从单参数微调 `G1`（`82.9%`）断崖跌至部件重构 `G2`（`43.5%`）与全局结构重组 `G4`（`24.6%`）；连最强 `Claude Opus 5.5`（`69.9%`）与 `GPT-6.1-sol`（`69.1%`）在 `G4` 与风格重塑 `S` 上通过率也**不足 `60%`**。
2. **能力跃迁伴随死因转移——`~40%–55%` 失败集中于“几何前瞻缺失（Geometric Foresight）”**（Table 4 & Table 17）：
   - 弱模型（`<20%` 档）`82%` 死在读错指令 `I`（11%）、误读源程序 `P`（34%）与代码报错 `K`（37%），几何前瞻 `G` 仅占 `18%`；
   - 强模型（`≥40%` 档）代码几乎不崩（`Opus 5.5` 可执行率 **`99.3%`**），**头号死因转向几何前瞻 `G`（占强模型失败 `39%–42%`，在 `Claude Opus 5 / 5.5` 上高达 `50%–55%`！）**——代码跑通且改对了变量，但**算不出三维组合后的真实形状**。

## 2. 方法论、数学公式与沙盒/验证器工程细节（含 Appendix 关键配置与 Prompt 要点）

### 2.1 模块化 `OpenSCAD → bpy` 重建与 `G1–G4 / S / C` 六级任务定义（Sec 3.2–3.3 & Appendix A.1）
- **108 个源程序**：55 个源自 `3DCodeBench`（中位 365 行）+ **53 个从参数化 `OpenSCAD` 经 `GPT-5.5` Generator + 盲审 Evaluator 平均迭代 5.5 轮重建的建筑(16)/家具(19)/机械件(18)（均值 703 行 / 中位 538 行）**，强制拆分为 `primitive_spec.py`（底层原语）+ `procedural_construction.py`（高层参数化装配）+ `render_entry.py`（Prompts 1–2）。
- **六级编辑范围（Table 2，每程序每类 4 题 = `2,592` 题）**：`G1`（单部件/族改 1 项可见参数）、`G2`（重构 1 个零件形态+尺寸+1 项特征）、`G3`（独立重构缩放 2 个零件）、`G4`（协同重组 $\ge 3$ 个区域的连接/跨越/支撑拓扑，固定 5 子句）、`S`（整体风格重塑：改主体+加 4 处几何风格特征）、`C`（功能场景组合：1 支撑面 + 3 工作道具 + 1 大型环境结构）。

### 2.2 无参考六视角共享取景全通公式与“看渲染图 vs 看源码”实证对照（Eq. 1 & Appendix A.2–E）

### 2.3 独立怀疑论 Reviewer 三步挑刺 Prompt 架构（Appendix F Prompts 11–12，零真值泄漏！）
```text
Step (a) 任务级自建清单（仅看指令 + 6 张原图，1 次/题）：提取含保持项的 {"requirement_id", "task_span", "criterion"}，禁编造数值公差。
Step (b) 怀疑论修饰词拆解核查（Prompt 11b，1 次/项/轮）：
  "You are a skeptical visual inspector of 3D edits... Your job is to find out whether the requirement FAILS."
  1. 将要求拆成显式修饰词（目标部件 / 数量 / 相对稳定参照物尺寸比 / 形状 / 朝向 / 接触或悬空缝隙 / 保持项）；
  2. 对每个修饰词选最佳匹配视图对，陈述 MODIFIED 相比 ORIGINAL 的直接像素观测；
  3. 仅当所有修饰词均有明确可见证据支持时答 yes，任一相悖或不确定即答 no！
Step (c) 纯文本修复建议（Prompt 11c & Editor Prompt 12）：仅对失败项给出具体视觉偏差与修复动作（严禁代写代码！），要求保护已过项；
  Editor 同时接收 ORIGINAL CODE + CURRENT CODE + CRITIC JSON，并设定 "Treat critic feedback as fallible observations, not new requirements."
```

## 4. 作者踩坑复盘与对我们 Qwen3.8-27B 三轨项目的落地启发（明确标注工程推论）

1. **【论文实证精准画像 → `Qwen3.8-27B` 单参已强（`84.3%`），真正缺口在 `G4/S/C` 结构组合与几何前瞻】**：
   - 论文事实：Table 3 揭示 `Qwen3.8-27B` 在 `G4`（`17.1%`）、`S`（`3.5%`）、`C`（`1.6%`）断崖下跌，且分析集（Table 17）显示其失败构成为 `I:14% / P:33% / K:27% / G:26%`；一旦配独立视觉差描述，5 轮修订直接冲上 **`50.3%` 反超 2.8T `Kimi K3`**！
   - *【我方工程推论】*：完全印证我方砍掉简单单参玩具题的决策——`kimi-k3.1-pro` 长程造数必须全力主攻 **多模块协同重构（`G4`）、整体视觉换肤（`S`）与多部件功能装配体（`C`）**，并将多轮“看图识穿模/悬空 → 外科手术修复”内化进 27B 权重。
2. **【论文实证大坑 → 单会话自审必犯 `<0.6` 轮早停惰性，裸 Agent Harness 自决 `DONE` 甚至负优化】**：
   - 论文事实：让 Editor 在同一上下文自己看图判停，连旗舰模型都改不到半轮就偷懒交卷；只有**独立会话 + 怀疑论逐修饰词挑刺（Prompt 11b）**才能逼出 3–5 轮有效精修。
   - *【我方工程推论】*：在我方教师长程轨迹采集尾声与高难题阶梯重采样中，应接入**独立会话怀疑论视觉审计员（只找茬不代写代码，且同时把 `ORIGINAL + CURRENT` 双版本喂回 Editor 防 `P-REWRITE` 误伤）**把守最终 EOS 退出闸！
3. **【论文实证防静默 Bug → 严查 `K-SILENT`（5.0% 布尔空操作）与 `G-INTERACT / G-SUPPORT`】**：
   - *【我方工程推论】*：直接对应我方 Track 3 `cad_inspect.py` 的核心防线——每次布尔切割/打孔后必须校验体积/面数实变（防 `K-SILENT`），并对装配体做连通域悬空检测（防 `G-SUPPORT`）与两两布尔交集干涉检测（防 `G-INTERACT`）。
