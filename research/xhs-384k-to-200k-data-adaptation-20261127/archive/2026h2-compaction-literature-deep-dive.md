## 0. 从 2025 启发式裁剪到 2026 下半年可证伪压缩工程的范式演进

2025 年下半年的早期探索奠定了三条基础经验：
1. **确定性观测掩码优于朴素 LLM 摘要**：JetBrains Research 的 *The Complexity Trap*（`arXiv:2508.21433`）在 `SWE-bench Verified` 上实测证明，仅保留最近 $M=10$ 轮原始工具输出、将更早观测替换为单行占位符（同时 100% 保留 `<think>` 与动作调用），在 `Qwen3-Coder-480B` 上不仅成本降低 **`-52%`**，解决率反而高于 LLM 滚动摘要（**`54.8%` vs `53.8%`**）——因为自由文本摘要会抹平报错细节（Failure Masking），导致轨迹变长 **`~15%`** 并在同一死胡同反复打转。
2. **多模态 GUI 视觉滑窗**：`OpenCUA`（`arXiv:2508.09123`）与 `UI-TARS-2`（`README.md`（本地附件未发布））证明，在百轮操作中保留全历史 `<think>` 但仅保留最近 $K=3\text{–}5$ 张截图，可避免 ViT 视觉 Token 爆炸且不损精度。
3. **早期折叠 RL 的梯度稀释困境**：`AgentDiet`（`arXiv:2509.23586`）、`FoldGRPO`（`arXiv:2510.11967`）与 `FoldAct`（`arXiv:2512.22733`）暴露出摘要 Token 仅占全轨迹 `<2%–5%` 导致的梯度淹没与非平稳自条件崩塌。

进入 **2026 下半年（`2026.06–2026.11`）**，随着百万 Token 级编码与三维多模态任务（`3DCodeFactory`、`KernelBench`、`DeNovoSWE`）普及，学术界与一线实验室完成了从经验拍脑袋到**通信复杂度下界、行为失真 KL 分解、非递归状态溯源与干净相位切分**的系统闭环。以下按五大技术专题拆解一手机制与定量证据。

## 1. 为什么 `~200K` 有界压缩窗口优于裸跑超长上下文？（一线旗舰与可训压缩实证）

### 1.1 `Kimi K3`（`arXiv:2607.24653`, 2026-07/08, Moonshot AI）
- **实证结论**：即便基座原生支持 `1M` 上下文，在 `BrowseComp` 等超长程多步工具评测中，**在 `200K–300K` 水位主动触发上下文压缩（`91.2%`）反超直跑 `1M` 全上下文不压缩（`90.4%`）**。
- **机制根因**：长程代码/探索任务中段积累大量已废弃的报错日志、旧版本代码切片与试探分支，留在注意力窗口内会稀释首轮硬约束与当前工作区状态的注意力权重（Context Rot）；但**当前活跃段内部的 `reasoning_content`（`<think>`）与 `tool_calls` 必须逐字保留**，跨轮剥离活跃段 `<think>` 会造成显著的分布外退化。

### 1.2 `CompactionRL`（`arXiv:2607.05378`, 2026-07, 清华 & 智谱 `GLM-5.2` 管线）
- **实验矩阵（事实）**：在相同峰值上下文预算下对比训练窗口与压缩次数：
  - `GLM-4.5-Air`（106B MoE）：`SWE-bench Verified` 从基座推理压缩 `~59.8%` 跃升至 **`66.4%–66.8%`（`+6.6 ~ +7.0 pp`）**，且 **`80K × 4` 可训压缩段（`66.4%`）显著击败 `160K` 不压缩长窗基线（`62.8%`, `+3.6 pp`）**；`Terminal-Bench 2.0` 提升至 **`24.5%–26.2%`**。
  - `GLM-4.7-Flash`（30B 级，与我方 27B 同量级）：`SWE-bench Verified` `50.5% → 56.0%`（`+5.5 pp`），`Terminal-Bench 2.0` `13.4% → 20.2%`（`+6.8 pp`）；该技术随后直接并入智谱 `GLM-5.2` 主力训练管线。
- **两条不可违背的 SFT / RL 工程铁律**：
  1. **全批次有效可训 Token 归一化（Global Trainable-Token Loss Normalization）**：当一条长轨迹被拆分为多个子段 $s=1 \dots K$ 时，若按“每段先求平均再跨段求平均”，短短几百 Token 的末段或摘要段梯度会被放大十余倍，论文消融实测**直接暴跌 `-6.4 pp`**；必须按全局有效 `loss=True` Token 总数 $\sum_{s,t} \mathbb{I}[\text{loss}_{s,t}=1]$ 统一归一化，使每个可训 Token 权重严格恒等。
  2. **联合训练摘要生成段（Joint `<summary>` Supervision）**：屏蔽压缩摘要段的 Loss（只训执行段）会导致 `Terminal-Bench` **暴跌 `-7.8 pp`**——模型若未在自身目标窗口水位（如 `150K–185K`）训过 `<analysis> + 9 节 <summary>`，线上撞窗交接就会漏掉关键文件路径与待修项。

### 1.3 `RECAP`（`arXiv:2611.31258`, 2026-11, EPFL & ETH Zurich）
- **核心数学刻画**：将上下文压缩建模为最小化压缩前后未来动作策略的 **行为失真（Behavior Distortion）**：
  $$\mathcal{L}_{\mathrm{dist}}(z_t) = \mathbb{E}_{k \ge 1}\Big[ D_{\mathrm{KL}}\big( \pi_\theta(\cdot \mid h_t, \tau_{t+1:t+k}) \,\big\|\, \pi_\theta(\cdot \mid \tilde{h}_t(z_t), \tau_{t+1:t+k}) \big) \Big]$$
  论文严格证明该目标的梯度自然分解为两项：① 对压缩器 $z_t$ 的**失真奖励**（衡量压缩后后继真实动作的对数似然保留度）；② 对压缩后续接动作的**在线自蒸馏**。
- **定量增益**：在 `Qwen3.5` 系列上以 `32K × 4` 单窗口有界预算训练，`BrowseComp-Plus` 从 `58.2%` 涨至 **`62.8% (+4.6 pp)`**，`SWE-bench Verified` 从 `46.8%` 涨至 **`51.1% (+4.3 pp)`**，且训出模型零样本迁移到 `16K × 8` 更窄窗口时仍反超 `128K` 原生无压缩模型。
- **离线数据改造直接用法**：验证任何前缀折叠方案（如我方 `HCPF-200K`）是否丢失关键信息时，无需主观盲猜——只需检查真实后继动作 $a_{t_k : t_k+8}$ 在折叠上下文下的 NLL 是否与原 `384K` 上下文一致；保留 `K_tail = 12` 轮完整近端滑窗 + 结构化文件脊柱可使边界处局部失真趋近于零。

## 2. 递归摘要悬崖与非递归确定性折叠（为什么绝不能对多段连续调 LLM 写散文摘要？）

### 2.1 `The Compaction Cliff`（`arXiv:2608.22752`, 2026-08, University of Passau）
- **惊人实测数字**：系统评测包括生产级 `Claude Code` `/compact` 在内的 **20 套主流 Agent 配置**，发现统一自由文本摘要会导致“压缩悬崖（Compaction Cliff）”——**仅经过 1 次自动压缩，硬性规格与安全约束的精确保留率就跌至 `53%`；经过 5 次连续压缩后直接崩盘至 `10%`**！
- **根因与解法（Knowledge Triage）**：普通执行流水账容忍概括，但**交付路径契约、禁止项、参考图锚点与硬性接口规格**一旦被散文改写就会失真。当我们将一条 `1.09M` 轨迹从 `3` 段（`384K`）拆细为 `6–7` 段（`200K`）时，若采用递归 LLM 摘要，到第 5 段时首轮题面硬约束将丢失殆尽；**必须采用 Knowledge Triage 将首轮系统提示词、原始需求规格与参考图 `I_ref` 作为不可压缩常量永久钉死在每个子段开头**。

### 2.2 `CliffCompaction`（`arXiv:2609.26779`, 2026-09, CMU Tim Dettmers 组 & Bosch）
- **两大核心设计准则**：
  1. **只做确定性截断/丢弃，绝不语义改写（Fidelity via Truncation, Never Rewriting）**：系统提示词、初始任务描述与最近若干轮交互逐字节原样透传；远端超长工具返回（`result-max-chars`）、过期内部思考块（`thought-max-chars`）与冗长参数体按确定性字符/Token 预算截断。
  2. **绝不递归压缩旧摘要（"Never compact a compaction"）**：每次构造新窗口的压缩前缀时，**彻底丢弃上一次生成的旧压缩块，直接从原始历史轮次重新确定性折叠**，从根源上切断多轮摘要误差累积。
- **硬核实证结果**：
  - 在有界窗口下将端到端 Token 与 API 成本砍半（**`-50%`**），在 `Terminal-Bench 2.1` 上达到 **`76.69%`**（超越 `200K` 不压缩基线与 LLM 自动摘要，并在并行 Test-Time Scaling 下使开源模型追平 `Opus 4.7`、超越 `Opus 4.6`）；
  - 在单会话超 **`1,000,000` tokens** 的 `KernelBench` CUDA 算子持续优化任务中，跑满 200 步实现 **`2.23×`** 加速、400 步实现 **`3.58×`** 加速，击败专门强化学习搜索框架。

### 2.3 `Context Compaction Theory`（`arXiv:2608.01326`, 2026-08, Harvard Mitzenmacher 等）与 `Scroll` / `PRO-LONG`
- **信息论下界**：通过双人通信复杂度博弈严格证明，在大状态空间（多文件代码库、多部件三维场景）存在精确集合/属性查询需求时，**自由散文生成式摘要的信息损失下界显著劣于结构化键值/文件选择索引**，并在 Anthropic 官方 Compaction API 实测中复现自由摘要退化近随机猜测的现象。
- **外部化与程序化日志佐证**：`Scroll`（`arXiv:2608.21690`, 2026-08）与 `PRO-LONG`（`arXiv:2607.20064`, 2026-07/10）及 Cursor 2026 *Dynamic Context Discovery* 工程实践共同印证：文件系统本身就是持久化工作记忆，远端历史只需保留**精确文件路径、行号范围与命令退出状态账本**，需要细节时模型可随时按路径 `Read`，无需把过期旧版全文死塞在前缀里。

## 3. 代码与多模态状态一致性：消灭孤立文件幻觉与“失明监督”

### 3.1 `DAG-SFT`（`arXiv:2609.18417`, 2026-09, ACL Findings）—— 为什么严禁无脊柱硬切窗？
- **关键反面消融**：对比“直接把超长轨迹按固定窗口切成互不重叠且无前序历史脊柱的独立片段”（即 `[System + User] + [Turns 50..90]`）与保留轮间依赖链的裁剪：
  - **无历史脊柱硬切窗导致下游任务成功率直接倒退 `-4.0 pp`**！因为第 50 轮的 `Edit(file_path="js/scene.js", old_string=...)` 依赖第 12 轮 `Write` 创建的文件结构，前文凭空消失迫使模型在 SFT 中强行拟合“不先看文件就凭空臆造代码行”的幻觉先验；
  - 反之，保留因果依赖链仅裁剪零出度死胡同轮次可省 `48%` Token 且反涨 **`+1.7 pp`**。

### 3.2 `MemTrace`（`arXiv:2610.04838`, 2026-10）—— 溯源锚点替代被覆盖的过期源码
- **痛点发现**：长程编码中最隐蔽的幻觉源不是“记不住”，而是**状态-记忆失配（State-Memory Misalignment）**——第 10 轮 `Write` 的初版 `scene.py`（`3,000` tokens）留在上下文里，第 45 轮其实已重构该文件，但模型在 `180K` 长窗注意力模糊时误抄了第 10 轮已被废弃的变量名！
- **解法与实证**：将已被后续编辑覆盖失效的远端大体积源码折叠为紧凑的 **带溯源记忆锚点（Memory Anchors，仅保留文件路径、操作类型与“已在后续轮次更新”标记）**；在同基座 Codex CLI 上实测：
  - `DeepSWE` Pass@1 从 `35.4%` 飙升至 **`56.6% (+21.2 pp)`**；
  - `SWE-Milestone` 提升 **`+17.8` 分**，`SWE-EVO` 提升 **`+4.4 pp`**。

### 3.3 `ScaleCUA`（`arXiv:2607.11185`, 2026-07, 清华 THUDM）与 `3DCodeEdit`（`arXiv:2610.38231`, 2026-10）—— 视觉上下文分段铁律
- **单序列删图的因果失明陷阱**：在多模态 `binpack` SFT 中，一条序列内会同时包含第 $1 \dots T$ 轮的多个 `loss=True` 助手回复。如果为了省 Token 直接把该序列第 10 轮的工具截图 `<image>` 删掉，而第 11 轮助手的 `<think>`（`loss=True`）正在逐像素分析第 10 轮截图的穿模位置，模型就会受到**“没有输入图像却要硬编视觉诊断”的毒化梯度**！
- **`Visual Context Segmentation` 正解**：
  - 将长轨迹切分为子段后，**每个子段内所有 `loss=True` 活跃轮次及其紧邻近端滑窗（`K_tail`）保留 `100%` 原始视口渲染图**；
  - **仅在该子段 `loss=False` 的远端历史前缀中归档旧视口图**（因为远端旧图的几何缺陷早已被转写进后续保留的助手文字结论中，正如 `3DCodeEdit` 8 轮视觉文本诊断达 `85.6%` 所示），但**永远置顶保留首轮参考图 `I_ref`**。`ScaleCUA` 实测该机制带来 **`2.83×` 训练提速** 并在 `OSWorld` 取得 **`68.7%`**。

## 4. 干净相位切点、近端滑窗与环境 Token 掩码策略

1. **在子阶段收敛边界而非报错中途切分（`AutoCompact` `arXiv:2610.02163`, 2026-10 & `SelfCompact` `arXiv:2606.23525`, 2026-06）**：
   - 固定在字数上限硬切经常把一轮完整的“运行报错 $\to$ 定位行号 $\to$ 修复重跑”劈成两半；`AutoCompact` 在子目标完成的干净相位点主动切分并按前缀重写边界构造单调训练段，使 `SWE-bench Verified` 从 **`30.4%` 跃升至 `39.6% (+9.2 pp)`**；`SelfCompact` 元认知准则（排错推导中途抑制切分、模块验收通过后切分）同样较固定比例切分高出 **`+5 ~ +9 pp`**。
2. **反事实边界风险高度稀疏，近端滑窗即可熨平（`PAIR` `arXiv:2609.36526`, 2026-09）**：
   - 对 82 条长轨迹的 197 个压缩边界做 $m=9$ 反事实同态续写测试发现：绝大多数历史块的折叠对后续成功率完全中性（零危害），**严重退化高度集中在紧邻切点前局部工作态被截断的少数边界**。在切点前保留 `K_tail = 12` 轮 `100%` 逐字含图完整滑窗（置 `loss=False`），即可彻底消除局部边界断层。
3. **SFT 阶段严格保持环境与前缀 `loss=False`（`ActObs` `arXiv:2609.20715`, 2026-09 & `DeNovoSWE` `arXiv:2606.10728`, 2026-06）**：
   - `ActObs` 揭示：对环境观测开 Loss（$\lambda=1$）虽增加后续 RL `pass@16` 探索多样性，但会分走策略容量、降低纯 SFT 直接部署的 `pass@1`；
   - `DeNovoSWE`（小红书原论文引文 `[36]`）直接用 **`131,072`（128K）SFT 窗口** 承接 `256K / 500 轮` 从零建仓轨迹，并对工具报错轮与冗余 heredoc 轮置 `loss=False`，使 `Qwen3-30B-A3B` 从零建仓率从 **`5.8%` 暴涨至 `47.2%`**、`Qwen3.5-35B-A3B` 升至 **`50.0%`**。

## 5. 基座原生 RoPE 与 `Claude Code` 线上自动压缩参数精准对齐

1. **为什么 `200K` 下必须关掉 `YaRN 1.5×`？（`Qwen3.8-Next` `arXiv:2608.30320`, 2026-08）**：
   - `Qwen3.8-27B` 预训练原生满血位置编码上限即为 **`max_position_embeddings = 262,144`（256K，`rope_theta = 10,000,000`，`partial_rotary_factor = 0.25`，交错 `mRoPE`）**。
   - 小红书使用 `384K`（`393,216 > 262,144`）超出原生上限才不得不套 `YaRN factor = 1.5`；而在 `max_length = 204,800`（`200K < 262,144`）下继续套 `YaRN 1.5×` 会白白把整段高频旋转波长压缩 `1.5` 倍，不仅损失视口坐标与代码行号分辨率，还易诱发 `Qwen3.8-Next` 报告指出的长程 RoPE 相位漂移与不吐 `EOS` 风险。**直接使用原生 `262K` 基座是零成本的纯正向升级**。
2. **`Claude Code` + 本地 `vLLM` 自动压缩水位双保险配置**：
   - 在 `vLLM` 以原生权重启动 `--max-model-len 212992` 时，`Claude Code` 支持通过环境变量控制自动压缩触发点：
     - 显式窗口上限：`CLAUDE_CODE_AUTO_COMPACT_WINDOW=185000`；
     - 百分比覆盖（注：`Claude Code` 内部使用 `Math.min` 钳位，`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` 仅支持**下调**触发水位）：在 `~/.claude/settings.json` 的 `"env"` 块或主进程环境中设置 `"CLAUDE_AUTOCOMPACT_PCT_OVERRIDE": "85"`（`212,992 × 85% ≈ 181,043` tokens）。
   - 这使线上推理恰好在 **`~175K–185K`** 处触发 `<analysis> + <summary>` 自动压缩，与我方离线 `ct_diet` 摘要训练样本分布（P50 = `151.1K`，P90 = `174.6K`）及 `HCPF-200K` 执行子段上限（`≤198K`）实现严丝合缝的 **1:1 训推分布同构**。
