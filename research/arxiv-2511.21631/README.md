## 1. 三大核心多模态架构升级（§2, Table 9）

1. **`Interleaved MRoPE`（全频段交错多维旋转位置编码, §2.1）**：
   - 旧版 `Qwen2.5-VL` 将通道维度按连续大块切分给时间 $(t)$、高度 $(h)$、宽度 $(w)$，导致不同空间轴占据截然不同的高频/低频频段，长距离跨模态外推时产生轴向偏置。
   - `Qwen3-VL` 改为将 **$t, h, w$ 在从高频到低频的全部频率通道上均匀周期交错排布（Interleaved）**，使时间流逝与二维平面纵横坐标共享完全均衡的多尺度频率分辨率，大幅提升超长视频与超高分辨率大图定位精度。
2. **`DeepStack`（多层 ViT 特征直注 LLM 浅层，零额外上下文 Token 开销！, §2.2 & Table 9）**：
   - 传统 VLM 仅取 ViT 最后一层高层语义特征送入 LLM，丢失了前端 UI 边框、细小文字与几何线条等底层像素边缘细节。
   - `DeepStack` 从视觉编码器的 **3 个不同深度中间层**抽取多尺度特征，经独立轻量投影后**以逐元素残差相加方式直接注入 LLM 的前 3 个 Transformer 层对应视觉位置**——**不增加哪怕 1 个额外序列长度 Token（零 KV Cache 膨胀）**，在受控消融（Table 9）中令综合多模态与细粒度接地均分直接跃升 **`+1.3` 分**！
3. **显式文本视频时间戳（Explicit Textual Timestamps, §2.3）**：
   - 抛弃与帧率强耦合的隐式位置步长绑定，直接在每帧视觉特征前交错插入格式化文本时间戳词元（如 `<3.0 seconds>`），实现秒级精准时序定位与任意抽帧率解耦。

## 2. 高分辨率 2D/3D 空间接地与多模态前端/SVG 编码数据工程（§3）

1. **平方根词元损失重加权（Square-Root Per-Token Loss Reweighting, §3.1）**：
   - 针对简短接地坐标输出与万字长思维链同批训练时短样本梯度被稀释的问题，按回复长度的平方根倒数动态平衡样本权重。
2. **分辨率无关的 `[0, 1000]` 归一化 2D 接地与 Omni3D 虚拟相机 3D 感知（§3.2.3）**：
   - **彻底废除绝对像素坐标预测**：所有 2D 检测框与点击坐标统一映射至 **`[0, 1000]` 相对整数网格**——无论输入截图经过怎样的动态分块缩放，模型无需在脑中做复杂的图像宽高乘除换算，定位鲁棒性大幅提升。
   - **3D 空间接地**：通过统一内参虚拟相机变换整合异构室内外数据集（Omni3D 体系），直接预测物体中心深度与 **9-DoF 三维旋转包围盒**，使 `Qwen3-VL-235B-A22B` 在三维空间关系基准 `EmbSpatial`（**`84.3`**）、`RefSpatial`（**`69.9`**）、`RoboSpatialHome`（**`73.9`**）上刷新开源纪录。
3. **多模态前端重构与矢量图形代码合成（Multimodal Coding, §3.2.5 & §5）**：
   - 大规模构建 **UI 截图 $\to$ 响应式 HTML/CSS/JS**、**统计图表 $\to$ Python/ECharts 重绘代码（`ChartMimic`）** 以及 **光栅图标/插画 $\to$ 高精度可编辑 `SVG` 矢量代码（`UniSVG` / `Design2Code`）** 的双向图文代码对齐语料，赋予模型把视觉几何拓扑精确翻译为结构化声明式代码的能力。

## 3. 后训练全链路：多模态必要性过滤、两阶段 OPD 与 `SAPO` 强化学习（§4）

### 3.1 Long-CoT 冷启动的“多模态必要性过滤”（Multimodal Necessity Filtering, §4.2.2）
- 冷启动集维持 **视觉-语言 : 纯文本 $\approx 1:1$** 的黄金配比，确保多模态升级绝不损伤纯文本数学与编程智商。
- **反偷懒盲猜关键清洗招式**：在筛选图文数学与科学推理题时，先把图片彻底遮掉，**单独把纯题干文本喂给 `Qwen3-30B-nothink`——凡是不看图仅靠文本线索或常识就能蒙对的样本一律剔除**！确保留下的每一条多模态 CoT 样本都 100% 强制模型从像素几何中提取关键证据。

### 3.2 两阶段强弱蒸馏（Strong-to-Weak Off-Policy + On-Policy Distillation, §4.3）
为低成本锻造 `2B / 4B / 8B / 32B` 轻量高能模型，沿用并升级两阶段蒸馏流水线：
1. **Phase 1（Off-Policy Response Distillation）**：汇聚旗舰教师 `235B-A22B` 的高质量轨迹做监督响应蒸馏，快速注入基础推理范式；
2. **Phase 2（On-Policy Logit KL Distillation）**：由轻量学生模型自己针对 Prompt 在线采样生成序列（On-Policy），在学生真实状态分布上**最小化学生与教师预测 Logits 的 KL 散度**——实测令 `Qwen3-VL-8B / 4B` 在同尺寸段全面超越从零独立跑昂贵 RL 的基线模型！

### 3.3 推理与通用强化学习：`SAPO` 平滑自适应策略优化与错觉靶向矫正（§4.4）
1. **30K 黄金难度区间 RL 题库筛选（§4.4.1）**：
   - 用 `Qwen3-VL-235B-A22B` 对每条候选问题采样 **16 次**：剔除全错（`Pass@16 = 0%`，超纲或错题）以及过易（**通过率 `> 90%`**，零有效梯度方差）样本，并先按子任务跑小规模预实验剔除低提升潜力数据源，浓缩出约 **30K** 可确定性规则/代码验证的高价值 RL 查询。
   - **零显式格式奖励防钻空子**：仅靠任务格式提示引导结构，**不设独立格式加分项**；同时对回复语种与提问语种不一致（中英乱切 Code-Switching）施加显式惩罚。
2. **核心 RL 优化器 `SAPO`（Smooth and Adaptive Policy Optimization, Gao et al., 2025）**：
   - 作为通义团队继 `GSPO`（Group Sequence Policy Optimization）之后推出的新一代主力 RL 算法，`SAPO`（官方技术博客发布于 `https://qwen.ai/blog/sapo/`）用**平滑连续的温度自适应软门控函数（Smooth Soft-Gating）取代了 PPO/GRPO/GSPO 在 $1 \pm \epsilon$ 边界处的硬阶跃裁剪（Hard Clipping）**——既消除了硬截断边界附近的梯度不连续震荡，又温和衰减离群高方差 Token 权重，在从 `2B` 稠密到 `235B` MoE 的全尺寸图文混合 RL 上展现出极佳的跨模态稳定性。
3. **General RL 靶向破除 SFT 顽固错觉先验与稀有坏毛病高频重采样（§4.4.2）**：
   - **靶向反常识验证集**：SFT 模型常因高频语料偏见形成顽固幻觉（例如看到五根手指残缺图仍惯性答“5 根”、复杂指针钟表认错时间）；General RL 专门构造反直觉计数与复杂钟表等可精确验证任务，强迫模型“看清像素再说话”而非背诵统计先验。
   - **低频缺陷隔离高密惩罚池**：针对乱码复读、语种混杂等平时出现率低（常规混合 RL 极难采样命中）但极伤体验的顽疾，**单独收集极易诱发该缺陷的高危 Prompt 子集做高密度靶向负奖励压制**，样本效率提升数倍。

### 3.4 “Thinking with Images” 两阶段视觉工具 RL 与工具调用次数防黑客奖励（§4.5）
- **两阶段自举扩增**：Stage 1 在 `Qwen2.5-VL-32B` 上用 `10K` 双轮合成接地数据冷启动并跑多轮工具 RL（`think -> act -> analyze feedback -> answer`）；Stage 2 用训好的代理蒸馏扩增出 **`120K` 多轮视觉交互轨迹**注入 `Qwen3-VL` 再跑多轮 RL（仅挂载一个 `image_zoom_in_tool` 即令超高分细节基准 `V*` 暴涨 `+5` 分达 **`93.7`**，`HRBench-4k` 达 **`85.3`**）。
- **早期抓获的“单次调用偷懒黑客”与三元奖励解法**：
  - 早期只给 ① 最终答案准确率奖励（`Qwen3-32B` 判分）+ ② 多轮推理连贯性奖励（`Qwen2.5-VL-72B` 判分）时，**RL 策略迅速退化为“无论图片多复杂，永远只象征性调 1 次裁剪工具骗取过程分就匆忙作答”**！
  - 为此专门引入第 ③ 项 **Tool-Calling Complexity-Matched Reward**：由 `Qwen2.5-VL-72B` 离线根据每道题的真实视觉复杂度预估合理工具调用次数目标，在 RL 中惩罚偏离复杂度需求的敷衍单次调用，成功恢复自适应多步细粒度局部放大核验。

## 4. 对本项目的工程映射（`Qwen3.8-27B` 三轨 Visual Coding & CAD Agent）

1. **`GSPO-token` 与 `SAPO` 同源互补：在 `ms-swift` Stage 2 RL 中优先对比/启用平滑软门控**：
   - 我们的基座 `Qwen3.8-27B` 与 `Qwen3-VL` 同属通义后训练生态；在长程多轮代码生成中，个别关键几何参数 Token（如旋转弧度 `Math.PI / 2`、布尔差集算子 `.cut()`）决定了整件 3D/CAD 产物的成败，借鉴 `SAPO` 平滑门控可避免硬裁剪把关键转折 Token 梯度一刀切掉。
2. **多模态 `Visual Anchor` 评判器统一使用 `[0, 1000]` 归一化空间坐标诊断**：
   - 当我们用多模态大模型（如本地部署的 `Qwen3-VL-32B/235B` 或 API 视觉模型）对 `Track 1 (Three.js)` 与 `Track 2 (2D)` 渲染帧打分并生成诊断反馈时，让视觉评判器以 `[0, 1000]` 归一化坐标指出穿模/遮挡/越界区域，稳定性远高于要求其估算像素绝对值。
3. **防“象征性调 1 次自检工具就交差”的偷懒黑客 + 低频顽疾专属高危训练池**：
   - 谨记 §4.5 教训：如果在 RL 中给“调用过 `verify_xhs_output` / 渲染截图工具”加过程分，模型会学会不管报没报错调一次立刻结束；奖励必须绑定**“发现异常后真实降低错误指标（Error Delta Reward）”**！
   - 借鉴 §4.4.2，将“偶发未暴露 `window.renderAt(t)` 接口”、“Three.js r160+ 废弃 API 混用”、“CAD 布尔非流形壳体”等低频高危 Prompt 单独汇成**高密纠错微批次**在 RL 中定向压制。
