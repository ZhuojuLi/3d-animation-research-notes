# 3D Animation Agent 评估体系：主调研方独立报告

> 公开整理版 · 2026-11-25。保留成文时点的记录；计划、文献结果和本地实测请分别理解。 环境路径已泛化，未收录的附件已标注；发布范围见 [整理说明](../../PROVENANCE.md)。

2026-11-22。研究对象为 3d-animation-agent（本地附件未发布），共享问题与范围见 research-brief.md（本地附件未发布）。本报告在读取 Astra 报告、最终回复或汇总草稿之前完成。

## 1. 结论速览

**建议把评估体系做成“一张题族地图、三类运行轨道、六道证据层、一个主指标”，而不是继续加零散检查或合成一个审美总分。**

- **一张题族地图。** 先按原始场景、资产、源码、任务模板和教师轨迹划分 train/dev/test，再派生缺陷、编辑和不同初始条件。已有采集题、历史 Kimi 案例和反复调试过的旧六题只能做训练或公开回归，不能改称隐藏测试。
- **三类运行轨道。** 单轮代码能力回归、完整 Agent 能力测试、外部 OOD 参照分开报告。answer-only 的 812 条 validation 记录可以测代码能力回归，但不能自动提供动画语义或 Agent 返修成绩。
- **六道证据层。** 评估器校准 → 交付完整性 → 任务语义及不变量 → 屏幕可读性与视觉质量 → Agent 观察/返修过程 → 成本与可靠性。跨场景泛化由题族划分与外测提供，不是一个可以叠加在单题上的分数。
- **一个主指标。** 最终主指标是完整题集上的 **`Accepted@1`：单次运行同时通过正式交付、全部必要任务断言、非目标保持和最低可视质量验收的运行比例**。无交付的运行进入分母，不能靠成功子集的高画质抵消。自动开发指标 `Functional@1` 不含开放视觉门槛；审美配对偏好另报，不能替代前者。
- **先校准评估器。** 每个关键题族至少有一个已知好版、能被目标检查抓住的单缺陷版、合理替代实现；修复/编辑另留健康控制。坏版通过是假阳性，好版失败是假阴性，题目或检查器有缺陷时先修题，不能把它记为模型能力结论。
- **小样本只做配对的、带区间的结论。** 草案中的 Agent test 是 12 题簇、48 个 case。单次运行 24/48 通过的 Wilson 95% 区间约为 **36.4%–63.6%**。真正有效的对照必须同题、同沙盒、同预算、同时间窗口、相同 trial 政策；不能把重复 trial 当作新增独立题族。
- **首轮最值得投入的并不是审美模型，而是独立测量和返修题。** 现有代码已经具备部分交付核验和 trial 汇总，但最新任务检查仍主要读取模型自己填写的状态字段，旧题还有“转动即通过”“相机变化未检查”的漏洞。先用真实对象、时钟、像素和交互读数修这些基础，再扩大模型矩阵。

这不是训练配方或项目生效决定。它兼容已经对齐的 one-shot/多轮双学生对照，也兼容“先做一个混合 SFT”的草案；两条路线可以共用题包、验收和统计底座。

## 2. 项目现状：已经有什么，缺的是什么

### 2.1 三套口径不应混为一谈

| 现有入口 | 已具备的证据 | 不能直接回答什么 |
|---|---|---|
| evals/cases.json（本地附件未发布） + check_case.py（本地附件未发布） | 通用 Agent 六题；发布文件哈希、源码重建、浏览器报告绑定；包含一个应阻断的缺输入题 | 艺术质量、真实任务语义；`review.json` 是作者自审，不能当独立视觉通过。首轮六题是开发联调，不是冻结测试 |
| collection-v1/cases.json（本地附件未发布） + check_claude_case.mjs（本地附件未发布） | 通用 Claude Code 沙盒的 12 个生成/修复/编辑题；采样、重复渲染、循环像素、部分暂停操作和状态表达式 | 复杂动作是否真的对、镜头是否看清、非目标是否保持；这 12 项 JSON 全部标为 `split: train`，不能拿来当隐藏 test |
| 外层 replay.py（本地附件未发布） + metrics.py（本地附件未发布） | 同题多版本、多 trial、原始结果；已有 `pass@k`、`pass^k` 估计与含失败试验的每次成功成本 | 不自动理解 Claude Code 的题包、会话与证据格式；没有项目级语义门槛、视觉盲评、题族隔离和 paired model comparison |

因此不应推倒已有系统。应该**复用产物哈希/构建、浏览器执行和原始轨迹，在上方统一 case manifest、独立 grader、run record 和 scorecard**。两个 Agent 沙盒可以分别评分，但不直接横向合并分数；跨沙盒只是另一个实验因素。

### 2.2 本地已经暴露的评估漏洞

1. **自报状态不等于实际状态。** 当前 `check_claude_case.mjs:70–105` 从 `window.__getSceneState?.() || window.__3D_STATE__` 读对象，再执行断言表达式。这个接口可以是任务明确要求的可观测接口，但 `arch_stable`、`camera_margin`、`supported` 等作者自己计算的布尔量不是独立测量。应由评测器从真实场景节点、矩阵、材质、相机、时钟或像素派生，或至少将自报字段与这些测量交叉验证。（Opus 复核后修正了本处的接口名笔误。）
2. **“会动”不能覆盖目标。** 摩天轮题当前只断言 `abs(wheel_angle) > .001`。实际 fixture 在末段将角度固定为 `2π`，所以角度非零不等于速度连续。`edit-watermill-camera` 检查轮子仍在转，却没有检查要求的新机位；`edit-conveyor-arm` 检查包裹数，没有检查臂反转及料箱保持。
3. **公开 schema 与 fixture 契约也可能不一致。** `edit-solar-material` 的题面明确要求 `panel_count`，但 fixture 未提供该字段，说明 fixture 本身不满足公开观测契约；仅补这个字段也不能证明材质改对。一般而言，隐藏测试若依赖题面未公开的名字或实现方式，会把任务问题错记为模型失败，但本例不能作为这种误拒的证据。所有必要 schema 都要公开给被测者；隐藏的是预期行为与阈值，不是未说明的编程接口。（Opus 复核后修正了此前“题面没要求 panel_count”的错误表述。）
4. **少量截图会漏掉关键时间窗。** Neon Street 独立评审（本地附件未发布）记录证据漏掉晚段不可读画面、镜头名与实际画面不符；并明确每个配置只有一个样本、静帧不能证明运动、SwiftShader 不能证明真实 GPU 帧率。初版六题也有技术通过但裁切仍未解决的结果，不能解读为 5/6 艺术质量通过（本地附件未发布）。
5. **候选通过不等于教师轨迹值得学习。** 结果正确但一路空转、依据旧截图或无图宣称视觉通过，仍是过程失败。反过来，轨迹长、看图多或工具调用多也不能当作质量好。

## 4. 建议的评估架构

### 4.1 第零层：先给评估器出成绩

每个 case manifest 必须回答：用户承诺是什么、哪些条件是必需的、哪些实现被允许、初始状态是否满足/违反承诺、怎样观测、证据属于哪个版本。

每题保留以下校准产物；复杂开放生成题可用同一题族的最小可验收版本承载：

| 校准件 | 必须观察到的结果 | 能发现的错误 |
|---|---|---|
| 已知好版 | 必需断言通过，所有相关状态确实可测 | 不可能任务、接口缺字段、探针假阴性 |
| 单缺陷坏版 | 目标断言拒绝，且其他检查尽可能保持有效 | 探针过松、检查错对象/时段、只查“存在/会动” |
| 合理替代实现 | 不采用参考代码路径也能通过 | 过窄测试、强求特定变量名或技术路线 |
| 健康控制 | 原本满足条件的场景检查后仍满足，无目标外回归 | 把“总要修改”当好事、误改与无意义抛光 |
| 运行环境复验 | 同产物、同环境重放得到同结论；失败有错误类型 | 浏览器波动、状态残留、版本错绑 |

对于 `repair-ferris-seam`，好版应该是匀速轮转，坏版在 `T−0.2s` 前速度非零但接缝附近停住，合理修复可改时间函数或相位映射，不能只要求一个源码 diff。验收器要读取**实际轮轴世界变换**，在接缝两侧估计姿态与速度，并检查座舱、相机和周期保持。

对于 `edit-rocket-ignition`，题面应明确是“点火绝对时刻 4→3 秒，点火后的相对轨迹保持”，还是“所有事件绝对时刻都提前”。随后分别测实际尾焰可见时刻、火箭相对点火时的位移、相机和非目标状态；读 `ignition_time` 字段只能作为辅助证据。

### 4.2 三层主结果与不允许补偿的门槛

对一次有效 trial 定义：

- `D`（delivered）：独立读回正式交付；源码可重建且与 HTML 哈希一致；离线、无运行错误；时钟/重复渲染/真实交互满足公开契约。作者自审状态可记录，但不给独立 `D` 加分。
- `F`（functional）：`D=1`，所有必需目标断言和必要不变量均通过。修复、编辑题的非目标保持包含在这里。
- `V_min`：在任务关键时间窗与真实交互路径中，主体和动作可辨，没有空白、严重裁切、遮挡等最低可用性失败；不是“惊艳”评分。
- **`A = D ∧ F_semantics ∧ V_min`，即最终 Accepted。** `F_semantics` 表示 `F` 中除 `D` 外的要求。

主报告同时给 `Delivered@1`、`Functional@1` 和 **`Accepted@1`**，不能只报其中一个“通过率”。自动开发阶段先看 `Functional@1`；最终选型必须完成 `Accepted@1` 的独立可视验收。

若 `N` 个冻结 case、第 `i` 题有 `n_i` 个有效 trial，则：

```text
Accepted@1(model) = (1/N) Σ_i [ (1/n_i) Σ_r Accepted(i,r) ]
```

这使每题等权，重复试验估计该题的单次成功概率。另报按场景 family 等权的结果，防止某个多case家族主导。生成/修复/编辑、难度、能力标签和每个 family 均给分子/分母。

`assertion_coverage = 通过的必需断言数 / 必需断言总数` 仅用于诊断，**不能补偿必要门槛**。例如“代码可运行但全程没拍到抓取”不能靠其他项平均成 Accepted。

### 4.3 未交付、unknown 和 infra 的分母规则

| 情形 | 模型质量结果 | 运营/评估记录 |
|---|---|---|
| 无正式 output、超时、主动交付失败候选 | `D=0`，因此 `F=A=0` | 保留 stop_reason、已用预算、是否有 diagnostic candidate |
| 题面要求的状态接口没有提供，导致必要行为不可验 | 若接口已公开则候选不合格；不得自动判视觉通过 | `missing_observability`，并检查是否强求了不合理 schema |
| 人尚未审片、证据缺失或裁判服务未返回 | `unknown`，不能算通过；最终 Accepted 尚不可发布 | 完成评审前保持 pending，不把未审片伪装成视觉失败 |
| 题面/fixture/checker 有缺陷 | 不作为模型失败证据；先修题并全组同版重评分 | `invalid_case`，保留旧结果但不悄悄替换历史 |
| 已确认的网关、浏览器或 runner 基础设施失败 | 原 trial 不当作能力失败；按预先规则允许一次同配置补跑 | `infra_error`，单独报发生率；所有原始 trial 与补跑均留档 |

在最终已冻结的有效题集上，`unknown` 永远不计成功。无效题与 infra 不悄悄从运营报表删除，也不通过挑补跑把失败变成成功。模型能力分母、可评视觉分母和基础设施分母必须分别列出。

### 4.4 任务语义层：按任务类型取证

| 类型 | 必要成功条件 | 关键辅助指标 |
|---|---|---|
| 生成 | 指定对象/几何、绝对或相对时序、事件顺序、镜头及离线运行均满足 | 首个可运行/首个功能合格/正式交付的时间和版本；静止率 |
| 修复 | 初始缺陷确实复现；修后目标通过；原有正确行为保持；正式交付 | 定向返修成功率、修复后回归率、从证据到修改的版本链 |
| 局部编辑 | 目标属性按要求变化；非目标对象在相同时间/相位保持；不是整题重做后碰巧相似 | 目标成功率、non-target preservation、误改范围 |
| 健康控制 | 用户只要求检查/交付时，已有合格状态不被人为破坏 | 误改率、无依据视觉结论率、及时交付率 |
| 缺输入阻断 | 不伪造参考或成品，指出缺失输入，不产生正式 output | 正确阻断率；与真正可完成任务的过度阻断率配对报告 |
| 交互/机制（仅题面要求时） | 真实点击/拖动/恢复或改变初态后，状态和画面按契约响应 | 操作成功率、状态-画面一致性、干预前后差分 |

动画的时间验收至少覆盖首帧、关键事件前后、晚段、循环两侧与操作后状态。先均匀采样找风险，再在接触、切镜、最小间距、接缝附近加密。有限采样只声明覆盖范围，不声称逐帧证明。包围盒适合定位风险，复杂接触还需实际形状/关节/人工复核。

### 4.5 屏幕与人评：最低可用性和审美偏好分开

**最低可视质量 `V_min`。** 根据 brief 中的关键事件，逐项判断“没看到/部分看到/清楚看到”，附时间点与原因。VibePrevisBench 的先盲复述再读 brief 可用于开放生成：防止裁判把题面中不存在的故事脑补进画面。对 `camera_margin` 等需要测量的条件，应看实际相机投影、遮挡和屏幕尺寸，而非只看“有相机”。

**开放审美偏好。** 同题匿名、随机左右、连续视频而非只给海报帧；允许平局。分开记录任务表达、运动/镜头、材质光照、总体偏好及具体缺陷时刻。起步两名独立评审，门槛项冲突由第三人或复核解决；报告原始一致率、分歧率与按题族的区间，而不只报 Elo。

- 若双方都有可评产物，报告 pairwise 胜/平/负，且交换左右位置检查位置偏差。
- 一方无交付时在总体交付结果中已记失败，不从“可评配对”中悄悄删除；另给无交付率。
- 用另一模型辅助筛片或预标时，先在按题族隔离的人工标注集上测一致率、故障检出和误报，再决定自动化范围。教师或其同族模型不得未经校准成为最终唯一裁判。
- 不把多个开放维度加权成单一“艺术质量硬门槛”。最低可用性可设必要项，艺术优劣保留为偏好与证据。
- 交互题给评审同一操作脚本和可运行 HTML；性能只在声明的目标设备测。软件渲染的截图耗时、静态页 FPS 字段都不能当实际流畅度。

### 4.6 Agent 过程：诊断“为什么提升”，不作为刷工具数的奖励

每个关键事件链保存 `initial_state → observed_evidence → edit → rebuilt_version → same_check_repeated → delivery`。从实际可见输入验证图片/文字观察属于当前版本。

建议报告：

- **证据暴露率**：相关故障窗口进入模型实际可用观察的比例；工具被调用不等于相关证据已被读取。
- **暴露后的识别率**：已暴露故障中，模型正确区分原因并提出对应下一步的比例；不能仅凭“Looks good”文字判定。
- **有效返修率**：确有目标缺陷的初始状态中，最终 `F=1` 的比例；另报目标修好但非目标破坏的比例。
- **证据支撑率**：视觉/物理结论有当轮真实证据支持的比例，截图哈希与源码/候选版本一致。
- **首个可用、首次合格、最终交付**的步数、时间和 token，区分“初稿更强”与“反馈后更能修”。
- 重复错误、无变化重写、盲重试、无效抛光、预算耗尽与错误阻断；外层 metrics 已有其中一部分，可复用而不是重造。

这些是行为诊断，不要求固定工具调用次数，也不假设更长轨迹更好。没有实际看到图片的回合不能得视觉观察分；私有思考是否可读不是判断动作是否有证据的前提。

### 4.7 成本、可靠性与泛化

- 主部署口径是单次自主完成：**`pass@1`**，trial 间取平均。若部署允许多个候选并用独立验收选一个，才另报 `pass@k`；它不能和单次主结果混用。
- 每题运行 `n` 次、成功 `c` 次时，`pass^k = C(c,k)/C(n,k)`，表示连续 `k` 次都成功的估计。`n=3` 只能给很粗的稳定性信号；它不是多采样择优。
- **每次 Accepted 的 token/时间 = 全部 trial（含失败）消耗 / Accepted 数**。另报每次 trial 的中位数/P90、超时率和成功子集耗时，不掩盖失败成本。API 累计上下文 token、实际训练监督 token 和 GPU 成本分开。
- answer-only 的 812 validation 是**记录数而非已证实的独立题族数**。保留原 split，按源码来源和近重复去重报告；以编译/运行/基础画面检查做代码回归，并从独立题族补动态语义验收。不能用参考源码 exact match 代表合理代码能力。
- 外部 OOD 只作补充：WorldCoder/GameASG 测相应交互行为，3DCodeVerse 测执行与保真，Animation2Code 测视频到 Web 动画。输入、输出和分母不同，不与主分合并。公开 dev 或训练中出现过的材料只能称外部分布参照，不能称无污染隐藏测试。

## 5. 题集和实验设计

### 5.1 一张题族地图

`family_id` 至少绑定原始场景/程序、资产、reference、任务模板、教师来源和派生关系。先分 family，再派生故障、编辑、扰动与教师轨迹。回答“同源变体在哪一侧”时，以原始程序/资产/模板而不以文件名判断。

| 套件 | 建议用途 | 是否可用于模型选型 |
|---|---|---|
| evaluator calibration | 好版、坏版、替代实现、健康控制、探针单元测试 | 否，只验收评估器 |
| public smoke / regression | 旧六题、历史已看过案例、每次 harness 改动的少量回归 | 只作开发回归，不能宣称隐藏泛化 |
| Agent dev | 草案 6 个新题簇 × 2 = 12 case；用于沙盒、prompt、训练配置和 checkpoint 选择 | 是，但反复查看后需轮换新 dev family |
| Agent test | 草案 12 个新题簇 × 4 = 48 case；冻结后最终配对比较 | 原则上只跑一次最终选型；看过结果再调就转 dev，另留新 test |
| answer-only regression | 原 812 validation + 另建有动态语义的独立代码题族 | 代码保持指标，不与 Agent 通过率合并 |
| external OOD | 合适的外部任务、真实新用户 brief、跨沙盒或新设备 | 补充泛化，不混入主分 |

建议 test 的 12 family 按生成、修复、编辑各 4 family 组织；每 family 4 个变体。修复族可含 3 个单缺陷状态 + 1 个健康控制，编辑族的变体要求目标变化与非目标保持。难度按实际状态转移和证据难度，而不是只按场景名词标注。以上分布是覆盖建议，尚未得到用户作为项目决定确认。

### 5.2 对照组怎样才公平

所有模型/学生共享：同一 case 和初始工作区、工具 schema、系统/Skill、真实视觉输入、浏览器、推理档、上下文和压缩策略、单题预算、收尾预算、trial 数、重试政策、运行时间窗口和 grader 版本。记录实际模型 ID、checkpoint、模板、解码种子与服务配置。

- **原生 27B vs SFT。** 同一原生 checkpoint 起点，主要终点是 Accepted@1 的配对差；报告按类型/难度的变化、代码回归和每次成功成本。
- **one-shot vs 多轮 SFT。** 按当前已对齐实验，两者评测时都拥有同一完整工具和迭代预算；训练数据是否同任务、最终成品、监督 token 与优化步数需记录，避免数据量差成为未说明变量。
- **单混合 SFT 草案。** 直接复用原生 vs 学生的同一题包和统计，不必等双学生路线决定后再建评估。
- **Kimi。** 是同沙盒参照，不是学生必须复刻的唯一答案。教师若用了学生看不到的像素、子 Agent 或更大预算，要单独标记，不能将差异全归因于模型权重。
- **基础设施。** 并发和网关负载影响墙钟，模型版本交错运行；原始失败和允许的一次 infra 补跑都保存。评测器与预期状态位于工作区外，不能把隐藏断言喂给 Agent。

### 5.3 小样本与重复试验：能说什么

本次按标准正态 95% 的 Wilson 公式和精确二项 McNemar 计算：

| 示例，不是实测结果 | 数值 | 含义 |
|---|---:|---|
| 48 个单次 case 中 24 个通过 | 50.0%，Wilson 95% CI **[36.4%, 63.6%]** | 单组比例本身很宽，且未考虑 family 聚集 |
| 两模型有 20 个不一致 case，15:5 | 差 **20.8pp**，McNemar 精确双侧 p≈**0.0414** | 描述性算术，不是通用的 20pp 阈值；存在 family 簇内相关时不得作为主推断 |
| 两模型有 10 个不一致 case，8:2 | 差 **12.5pp**，p=**0.1094** | 不一致对比例更悬殊，但分母更小；原文“点差更大”系表述错误。同样不得忽略 family 簇内相关作主推断 |
| 单题单次成功率若为 .75，独立 3 次全成功 | `.75³ = .421875` | 说明 `pass^3` 与 `pass@1` 回答不同问题 |

这些示例只说明计算，不预测本项目结果。本报告原始建议是 family paired cluster bootstrap，并允许单次 McNemar 补充。**Opus 审查后的最新修订**是：主区间采用题族配对差的 t 区间或满足交换性假设时的符号翻转区间，bootstrap 与逐一删族只作敏感性；普通 McNemar 不再作 family 内的推断依据。详见[Opus 证据复核与最终取舍](opus-synthesis.md)。不能把 48×3=144 次运行直接当 144 个独立 case。

48 case × 3 trials × 4 个系统是 **576 次 Agent 运行**，12 个 dev case × 3 trials 是每系统 **36 次**。（校对修正：本句此前误写为 24 个 dev case / 72 次，与上文 `6×2=12` 不一致，现按草案数量改正。）因此先用小规模重复试验估计运行波动，再冻结最终 trial 数；**优先保住新题族覆盖，不用大量重复同题替代泛化**。若预算只能每题一次，就诚实报告单次结果及宽区间，而不是以 `pass@k` 美化。

### 5.4 预先写死的选型规则

1. **有效性门槛。** 所有进入结论的 case 有校准记录；关键探针坏版能拒、好版能过；若发现题 bug，该题全组同版重跑/重评分，不悄悄改一个模型的结果。
2. **主要比较。** 学生相对原生的 Accepted@1 配对差及区间；双学生路线再比较多轮相对 one-shot。Kimi 只作参照。
3. **保持门槛。** 简单生成、健康控制、正确阻断和 answer-only 代码回归单列。非劣界值须在看最终 test 前依据开发波动和业务容忍度确定，不能事后把退步改称可接受。
4. **成本门槛。** 同样预先确定预算；超预算即失败。达到质量相近的候选才比较每次 Accepted 的 token 和时间，不能用更多预算买主分。
5. **三种结论。** 区间与预设实际意义门槛都支持时才说“优选”；没有足够证据时标“未分出”，不是强行排名；若目标题改善但简单/健康/代码保持越过非劣界值，则判定有回归，需要修数据而非只报主分。
6. **test 一次性。** 看过 test 后再改 prompt、数据、checker、checkpoint 或 trial 规则，原 test 就已成为 dev；应换未见过的新 family 做确认。多 checkpoint 的 dev 选择次数和最终比较数都记录。

## 7. 建议立即优先做的四件事

1. **把四个代表题做成可信样板**：摩天轮接缝、机械臂接触、火箭取景、局部材质/点火编辑。先证明测量能抓错，再扩 200 个采集题。
2. **建立 family registry 和冻结 manifest**，给现有全部 train 题、旧案例、answer-only validation 标清来源和用途；新 dev/test 在教师运行前就隔离。
3. **统一 scorecard，先跑小基线而非大矩阵**：得到实际交付率、目标通过率、unknown/infra 和方差后，再定 trial 数与业务非劣界值。
4. **建立最低可视质量审核**，保存真实连续片段和交互证据；等本地人工校准集足够后，再决定 LLM 视觉裁判自动化多少。

## 8. 未知项与证据边界

- 本轮是代码、已有归档和公开一手资料研究，没有启动新模型、训练、收费批量运行或新浏览器测试；没有声称新的 27B/SFT 成绩。
- 12 dev case、48 test case、各类型分布和三次 trial 是基于现有草案的建议，不是已验证最优规模，也不是项目生效决定。
- 现有 answer-only validation 的独立近重复题族数、语义可执行覆盖和与新 dev/test 的重叠仍需实测；812 不是无污染证明。
- 通用 harness 与 Claude Code 会话/题包的接入程度需通过一条真实 canary 验证；本报告没有假定 schema 已实现。
- 人类最低可视质量的可重复性、LLM 裁判对本项目的校准、合理非劣界值及成本预算尚无本地数据，不能用公开论文的数字代替。
- 自动状态探针仍受可观测接口和场景结构限制；对于恶意生成代码，它不是安全边界。当前目标是可信本地生成代码的正确性验收。
