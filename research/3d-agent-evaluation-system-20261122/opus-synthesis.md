## 2. 最重要修正：先做题目有效性审计，再校准检查器

Opus 的“5/8 通过”拆分比此前更精确。主调研方对关键源码的复核结果如下；它不是全数据集坏题率。

| case | 复核后的问题归属 | 正确处置 |
|---|---|---|
| `repair-ferris-seam` | 缺陷真实存在：5.8 秒跳到 2π 后停住；旧断言只看角度非零，属于已证实的检查器假阳性 | 测接缝两侧实际轮轴姿态与速度，不能只查首末像素或非零角度 |
| `repair-arm-contact` | 臂杆底端在包裹内部，但题面说“末端”位置不对；没有真实抓取窗口和包裹随动结构 | 先重建符合题意的好坏 fixture，不能只放宽/收紧检查器 |
| `repair-rocket-framing` | 火箭没有出画，既有实测与 Opus 投影复算一致；负例不成立 | `invalid_case`，先修 fixture；通过不是检查器假阳性 |
| `edit-watermill-camera` | 初始方位约 36.9°，题面“约30°”的方向与容差不明确；不能武断判为已完成或有缺陷 | 明确方向、目标区间及是否允许等价构图，再判断初始状态 |
| `edit-conveyor-arm` | 没有题面要求的两个料箱，臂和包裹不接触；现有断言只查包裹数 | 题面/fixture 无效，重建起始状态与目标断言 |
| `repair-solar-pause` | 暂停后仍 draw 的缺陷真实，旧拒绝原因正确 | 补恢复连续性；不能把“完全不运行 rAF”当成所有暂停题的唯一实现 |
| `edit-rocket-ignition` | 初始 4 秒是真实待改目标，旧拒绝方向正确，但只读自报常量 | 测真实尾焰出现和相对点火轨迹，不只改 `ignition_time` 字段 |
| `edit-solar-material` | fixture 未提供**题面明确公开要求**的 `panel_count`，材质是否改变没有被测 | 先修 fixture 的公开契约，再独立测材质和非目标保持；仅补字段不算完成 |

因此，首轮顺序应改为：

```text
T0 题目/资产/公开契约有效性
  → 独立测量与 checker 校准
  → 教师候选验收
  → 训练准入
```

T0 至少确认：题面涉及的对象存在；声称的缺陷可复现；公开 observation schema 已满足；编辑/修复的未编辑状态会被目标检查拒绝。坏版本来就不坏时，不能把它记录成检查器漏检。

### 主报告中的两处事实修正

已在[主报告](main-report.md)中明确标注：

1. 接口名修正为 `window.__getSceneState?.()`，不是此前误写的 `__getSceneState__`。
2. `panel_count` 在题面中已公开要求，此前将它解释成“隐藏测试强求未公开字段”是错误的；实际问题是 fixture 不满足公开契约，而且材质目标未测。

水车的“约30°”具有歧义，不能将 Opus 的“可能已满足”进一步夸大成确定的坏版。

## 3. 当前采集检查器的结构证据

主调研方对 `agent-runs/astra-scale-collection-20261122-Y3WaVO/cases.json` 做了独立计数：

- **320** 个 train case，**1,312/1,312** 条断言引用 `s.*`；这包括名为 `independent_witness` 的断言，其输入仍是 Agent 自己写的 `s.witness`，不是独立测量。
- **64 个 case、128 条断言**含 `if(i<0)return true`，采样时刻不匹配时直接放行；全部 **48 个健康控制**也在此类风险范围内。
- 这 48 个健康控制的 `task_type` 都是 `repair`，与将它们混入修复主指标的提议冲突。
- **256 个 case**有 `browser_probe`，`generate.py:70` 显示它是写进题面的操作说明，不是评估器自己执行的探针。
- `generate.py:14` 还把全部“公开采样表达式”写进任务 prompt。用于训练时可以是公开反馈，但**不能将同一表达式当成隐藏 test**。
- `collection-planned.json` 中计划为 **960 trials**。最新只读快照有 34 行 progress，其中 33 行 finished；这是运行进度，不是质量合格数，也不应把 Opus 当时的 21 条快照当成当前固定值。

这些证明的是**当前验收结构有系统性风险**，并不证明 320 题全坏、960 条轨迹有多少错误正例，或某一具体已完成产物内容不合格。

### 对采集和训练的取舍

- 原始采集可以保留供重新评分，但现有 `check_ok` 只能称**技术候选标记**，不能直接称独立验收通过。
- `best-of-3` 是教师采集预算，不是独立模型评测通过率。它会放大弱 checker 的假阳性，不能用来计算 Kimi 的 `pass@3`。
- 训练准入前必须补独立测量与伪造状态变异：自报正确、真实场景错误时，检查器必须拒绝。
- 可让公开接口暴露真实对象引用，评测器从 scene/camera 的矩阵、材质和时钟派生量，再与真实画布交叉验证。这个是建议的实现方向，不是已有能力。
- 删除 `if(i<0)return true`；固定采样之外增加关键窗口加密和随机审计；断言区分 `pass/fail/unknown`。公开字段缺失与 grader 自身错误也要分开。
- 首轮不自动停止或修改现有队列；**SFT 准入和最终三次采样选优应等独立验收**。Opus 另建议不要在此基础上继续扩量，是否执行由项目决策人决定。

## 4. 主指标和适用性规则的修订

### 4.1 健康控制和缺输入阻断移出 Accepted 主指标

此前曾建议修复族中“3 个单缺陷 + 1 个健康控制”一起进入 family 宏平均。这会给“检查后原样交付”的策略在每个修复族中固定 1/4 的得分，同时人为固定 25% 的患病率，混淆了敏感性和特异性。

修订为：

- `Accepted@1` 只统计应交付的生成、真实缺陷修复、局部编辑任务。
- 健康控制作为**无误改/保持特异性护栏**单列，和真实缺陷修复敏感性配对呈现。
- 缺输入阻断作为**正确阻断率**单列，和可完成题误阻断率配对呈现。
- 健康 fixture 必须重新通过 T0 与独立验收，不能因为旧 `check_ok` 就认定健康；否则会奖励保留旧缺陷。

第二份外部报告中的“评估器健康控制”用于发现误报，也有意义，不应因名称相同而丢掉。后续建议明确区分：

- `agent_no_change_control`：无缺陷输入，检查后不误改；
- `grader_healthy_control`：健康产物应不被误报；
- `interaction_health`：暂停、降低动态效果、频闪等其他需求。

### 4.2 增加需求覆盖矩阵

`unknown 不算成功`仍不够，因为当前很多必需项根本没有进入检查。每个 case 必须登记：

```text
brief requirement
→ assertion / applicable grader / time window / evidence
→ 或 not_measured（原因）
```

必要项 `not_measured` 时，`Functional` 不能判通过，也不能静默省略该门。生成题的非目标保持可标 `not_applicable`；缺输入阻断的 HTML 交付可标 `not_applicable`。

### 4.3 family 宏平均与 case 微平均不再作为争论重点

在每族 case 数相同、每题有效 trial 数相同且适用性一致时，两者数值相等。真正要冻结的是：

- 推断按 family 聚类；
- test 保持均衡设计；
- `primary_eligible`、unknown、infra 和 `not_applicable` 造成不均衡时的权重；
- 逐族原始分子/分母与配对差 `d_f`，而不是只报一个总分。

dev 选型也要完成 `V_min`，不能只优化不含视觉最低门的 `Functional@1`，再到 test 才换目标。开放审美仍可延后。

## 5. 谱系、封存和系统对照

### 5.1 谱系边必须分类

将 `collection-v1` 的 12 个 family 标签与源码对照可发现约 6 个同源组，某些编辑 fixture 恰好是另一道修复题的答案，跨 split 会直接泄漏。

对新的 320 case 的全部 `lineage_ids` 直接做并查集，主调研方也复算出 **1 个连通分量**。原因是 `protocol:sweep`、`mechanism:*`、`template:*` 等分类标签把所有题连起来，而不是所有题都共享答案。

因此改为：

- **泄漏边**：源码、fixture、资产、参考解、教师轨迹、缺陷注入器；仅对这些边求连通分量。
- **分类标签**：机制、协议、模板风格；用来描述 OOD 轴，不用于合并题族。
- 增加显式检查：“某题 fixture 是否等于另一题的答案或合理修复版”。

### 5.2 test 在协议冻结前不跑任何系统

采纳 Opus 的更严格建议：**协议冻结前不在 test 上跑任何系统**。理由不是单纯保密，而是当前公开 observation schema、题目和 harness 都会因 P0 修改，提前跑的 native 已不再是最终受控对照。

- native 的基线先在 dev/pilot 上跑；test 冻结后与学生同窗口交错执行。
- 如果已有 test 运行，只能保留作诊断；最终 native 仍需在冻结后重跑，不能拿旧配置当最终基线。
- 难度标签不得来自最终比较那一次运行，否则按失败选题会引入均值回归偏差。
- dev/test 输出、判官标签、隐藏 contract 与训练谱系隔离；采集台账显式标 `purpose=collection`，评测表不得读取它当模型成绩。

## 6. 统计方案的最终修订

### 6.1 主区间与 MDE

采纳 Opus 的方向：

- 主区间使用**题族配对差的 t 区间**，或满足交换性假设时的符号翻转区间；
- paired cluster bootstrap 与逐一删族作为敏感性分析，不再把 12 簇 percentile bootstrap 当作唯一主区间；
- 不把 48 case 的普通 McNemar 作为推断方法，因为忽略簇内相关。此前的 15:5、8:2 算术保留为描述，但主报告中的“点差更大”已明确修正为“不一致对比例更悬殊”；
- 头条不能只给 48 独立 Bernoulli 的 Wilson 区间。若仅作 12 个独立单元的直观比较，50% 的 Wilson 区间约为 **25.4%–74.6%**；最终应给 family 层配对区间。

MDE 使用 t/非中心 t，而非只追求正态分位数的小数精度。主调研方用 scipy 对目标 80% power 的非中心 t 求根，得到：

| F | σΔ | α | 80% power 的 MDE |
|---|---:|---:|---:|
| 6 | 0.10 | .05 | **14.345pp** |
| 12 | 0.10 | .05 | **8.887pp** |
| 12 | 0.30 | .05 | **26.660pp** |
| 6 | 0.10 | .025（Holm 第一项） | **17.053pp** |
| 12 | 0.10 | .025（Holm 第一项） | **10.082pp** |

这些仍然只是给定 σΔ、目标和分布假设的规划计算。实际 `σΔ` 必须在 dev 上由 native 与现有 Aodi one-shot 或其他同协议系统估计。只有 native 时，可在 `ρ≥0` 假设下使用 `σΔ²≤σA²+σB²` 的上界，但不能假装已经测得配对方差。

### 6.2 功效示例的含义

Opus 假设两系统成功率都约 50%、每族 4 个二元 case、case 间相关 `ρ=0–0.5`、R=1，则 `σΔ≈0.25–0.35`。这不是本项目实测，而是用于警示数量级的情景。

在 `σΔ=0.30、F=12、双侧α=.05` 下，主调研方用非中心 t 复算：

- 真实提升 **10pp**，检出概率约 **18.4%**；
- 真实提升 **20pp**，约 **55.8%**。

所以首轮 test 很可能只能回答“有没有大幅变化或关键回归”，不能承诺分辨 one-shot 与多轮的细微优劣。δ_min=10pp 若再要求区间下界超过它，在该情景下更不应被当成理所当然的放行线。

### 6.3 trial 策略

- dev R=3 可用于分解族间、case 间、trial 间方差。
- 最终 R 在 dev 后、test 揭盲前冻结，**不能因 test 临界而追加**。
- 采纳更节省的首轮策略：**全集 R=1，不默认设重复子面板**；只有当 dev 表明 trial 内方差占总方差主要部分时，才在冻结时将全集统一改为 R=3。新增独立题族优先。
- 教师采集的三次采样与最终评测 trial 分开命名和分账，任何采集 best-of-3 都不能变成模型 `pass@3`。

## 7. 其他采纳的修正

1. **外层 harness 的 unknown 分母。** `metrics.py:145–149` 在任一 trial `pass=None` 时跳过整题聚合，会形成 complete-case 偏差；正式表必须从计划 manifest 左连接全部 trial。usage 缺失要有 coverage，不能当免费。
2. **重跑与重评分改名。** `replay.py` 会重新运行 Agent 并产生真实模型调用；对冻结产物重评分应称 `rescore`，不增加 Agent 动作。`check_ok=False` 的超时也不能未经归因全算模型失败。
3. **真实输出校准。** 四族起步时不能仅把 2+2 个 family 的 holdout 当成统计证明。至少让未读 checker 的人/AI 盲写变异，或从真实 Qwen/Kimi 输出分层抽样做人工混淆矩阵。
4. **视觉门槛。** 可测的投影、遮挡和边距优先程序化；人工 `V_min` 聚焦“动作能否看懂”。首轮可一人覆盖全部，边界样本加第二人，开放审美 A/B 和 LLM 自动化后延。
5. **判官相关不等于正确性。** 本次已核原文的 0.73–0.76 是不同 VLM judge 的单 run 一致性范围；人评对照在 agent 汇总层。它不能证明逐 case 二元 `V_min` 的正确性，必须由本项目按 prevalence 校准。
6. **资源。** 记录并发、CPU/GPU、负载和超时，以步数/token 为主要预算，墙钟作宽松安全上限；首轮不必做 1x–3x 资源矩阵。
7. **作者自审。** `check_case.py` 的 `review.verdict=pass` 只能作作者行为诊断，不能当独立质量证据，避免筛出“总会说过”的教师。
8. **P0 收敛。** 首轮真正需要的是 manifest、计划台账、scorecard、一个分析脚本和人工 `V_min` 表；六层产物、两张系统表、资源矩阵、外部 OOD、LLM 裁判及复杂层级模型不应一起上。

## 8. 修订后的最小放行顺序

1. 将当前 `check_ok` 降为技术候选标记，推迟训练准入与最终采样选优。
2. 完成 T0 题目有效性审计，先修/作废不合格 fixture，包括公开 schema 和健康 fixture。
3. 在 4 个代表题族实现独立测量与伪造状态变异，并确保未编辑状态也会被拒绝。
4. 删除静默放行，补真实播放、关键窗口加密、随机审计和三态 verdict。
5. 冻结主指标：适用性掩码、需求覆盖矩阵、健康/阻断护栏、unknown 与计划 trial 分母。
6. 用分类型谱系建立并封存 dev/test，检查 fixture 是否泄漏另一题答案。
7. 冻结前不跑 test；在 dev 上让 native 与现有学生各 R=3，估计配对方差与 MDE。
8. 冻结 R、主比较、Holm（若两个学生臂）和判定规则后，再执行最终对照。

Opus 原报告与本复核均未启动训练、修改生产 checker、改变队列或写入项目 `decisions.md`。是否停止扩量、何时开始 SFT 仍需项目决策人确认。
