# 3D Animation Agent 评估体系独立调研

2026-11-22

## 1. 结论速览

1. **先校准题，再评模型。** 现有 8 个修复或编辑起始 fixture 全部构建成功，其中 5 个在尚未完成目标修改时就通过检查。另有 1 个被拒绝的太阳能板材质题，失败项是面板数量断言。仅凭 `check_ok` 采集训练正例或选择 checkpoint，会同时引入漏判和错误归因。预检原始记录（本地附件未发布）
2. **主指标采用题族等权的端到端任务成功率。** 交付题要求正式提交、离线可重建、核心动画语义和必要保持项全部通过，并通过题目预先定义的最低画面可读性门槛。缺输入题单独判定正确阻断。美感偏好、工具行为和成本分别报告，不加权凑总分。
3. **主对照可以共用一套底座。** 原生 27B 与每个实际训练的学生都在同题、同工具、同预算下运行。只训一个混合学生时，能估计整套 SFT 相对原生模型的变化。要识别多轮轨迹相对最终答案监督的增益，需要同一批教师任务和成品派生的 one-shot 与多轮学生。
4. **6 个 dev 簇适合排错和有限选型，12 个 test 簇只能支持小规模配对结论。** 计划里的 12 道 dev、48 道 test，以及每题重复运行，分别增加簇内覆盖和随机性信息。新增独立题族才直接增加对新题族泛化的证据。置信区间宽时保留“未决”。
5. **最小版本无需大评审系统。** 先实现逐题校准包、独立交付回读、1–3 个关键语义断言、完整周期的标准化视频、盲评表和覆盖全部计划 trial 的台账。薄弱题可以继续用于检查器开发，待校准后再进入正式计分。

### 3.2 指标树与分母

| 层 | 硬门槛或主要输出 | 分母与辅助诊断 |
|---|---|---|
| 交付 | 期望交付时正式提交最终候选，发布源码可在冻结工具链重建，离线冷加载成功，禁止的外部请求为零，无致命运行错误，时间契约成立。阻断题须准确说明缺失输入、停止且无虚构产物。 | 正常交付率以全部应交付 trial 为分母；正确阻断率以全部应阻断 trial 为分母。另报错误阻断数、fallback 发布数和证据缺失数。 |
| 动画语义 | 每题预先冻结 1–3 项可观察的必要条件。修复题须“已知缺陷消失且保持项通过”，编辑题须“目标变化发生且保持项通过”。 | 分别以全部该类 trial 报联合成功率；另报各条断言命中数。单项平均分不能抵消一个必要条件失败。 |
| 视觉 | 明确要求的主体可见、关键镜头可读、无非预期长时间黑屏等可设门槛。灯光、材质、构图、运动可读性与整体偏好通过连续视频盲评。 | 同报全分配对的端到端胜/平/负、双方都交付且可评的条件偏好及覆盖数。单方合格交付胜无交付；双方均未交付单列，若偏好汇总计平须显式声明。 |
| Agent 行为 | 仅把任务明示的行为及证据诚信设为必要条件，例如缺图时正确阻断、要求复验时复验最终候选。 | 在有对应机会的题上报识别缺陷、目标修复、复验、健康工程无有害修改。工具失败、原样重试、反复写同一文件、图像实际到达率用于解释。健康控制允许正确地不编辑。 |
| 成本 | 固定预算下首先报告成功率。另报每次成功成本 `所有已花成本之和 / 成功数`。 | 计入失败、超时及允许的补跑。分列墙钟、调用数、输入/缓存/输出 token、GPU 秒或已知费用、评审成本；零成功给出总花费和分母 0，缺 usage 标未知。 |
| 泛化 | 新题族宏平均为主，按生成/修复/编辑/阻断、简单/中等/困难、素材来源分层。跨沙盒、跨渲染器和外部任务各自成表。 | 每层给题族数、case 数、计划和实际 trial 数。帧、评审票、assistant 回合分别是观察单位，均不能充当独立题数。 |

**计分约定。** 为每个计划 trial 先登记 `pass / fail / unknown`。到期未交付、模型超预算、提交损坏都属于端到端失败。独立录像损坏、评分器失效等造成事实不可判时标 `unknown` 并记录原因。若共有 \(N\) 个计划 trial、确认成功 \(S\)、未知 \(U\)，报告确认成功率 \(S/N\)、可识别范围 \([S/N,(S+U)/N]\) 及未知原因。必需层未知不能放行为成功。先在 case 内平均 trial，再在族内平均 case，最后等权平均族；上下界按相同顺序聚合。另列按服务故障归因的敏感性结果。纯开放美感缺票只影响偏好统计，除非缺证据恰好妨碍判定必要视觉门槛。

### 3.3 先验证评估器

每个正式 case 配四种控制。**已知好版**给出预期通过的证据；**单缺陷版**只破坏一项必要性质并标出事件时间；**合理替代实现**改变对象命名、层级、实例化或动画实现但保持可观察行为；**健康控制**将完好工程交给诊断或修复流程，并允许模型报告无需修改。好版检验 grader，健康控制还检验 Agent 的误修倾向。缺输入题成对准备“确实缺输入”和“给足输入”版本。

| 题 | 应冻结的测量 | 交叉检查 |
|---|---|---|
| 摩天轮接缝 | 接缝两侧按固定步长采样，用相邻帧角位移计算单侧速度，同时检查跨缝位移和速度大小。以好版及合理替代版定容差。 | 追踪可见轮缘标记或吊舱；覆盖“首尾同图但末端停顿”的坏版。 |
| 机械臂接触 | 在预定接触窗口逐帧测末端与物体的距离、开始随动的时刻和释放后的轨迹。 | 核对遮挡与像素上的实际接触；允许不同关节解。 |
| 火箭取景与点火 | 横向、窄屏分别测主体投影边界及安全边距；在 \(3s-\epsilon,3s,3s+\epsilon\) 检查可见火焰和升空时序。 | 取景与点火分属两题，分别保留原任务未要求变化的镜头或运动。 |
| 水车镜头、太阳能板材质、传送带反转 | 分别测指定视角变化与水轮运动保持；面板目标区域颜色变化与非目标区域保持；机械臂角速度方向与包裹落箱结果。 | 状态回读与独立像素、投影或轨迹对应；不要用整图逐像素相等裁决开放材质实现。 |
| 暂停/恢复与交互 | 用真实按钮触发；暂停期间核对题目要求的画布、时间和 draw 数，恢复后核对连续前进。拖拽和滚轮测试先固定时间。 | 对操作前后记录同一模式、时间、镜头与输入事件，排除时间自行推进造成的假阳性。 |

每个断言的校准表记录 `应判结果、实判结果、命中断言、实际测量、容差、证据哈希`。按断言报告坏版检出数/坏版数、好版和替代版误拒数/对应版本数；另记录“拒绝但错因”。同一固定版本冷启动和乱序 seek 后若翻判，先定位渲染与时钟。关键坏版漏过、合理实现误拒、证据无法绑定到最终 HTML，均暂停该题计分。少数控制全过只证明已覆盖的失效模式。

**盲评最低协议。** 由独立 harness 从冻结的最终 HTML 生成全周期定步长视频；有多模式则各录一次，加录必要的切换、暂停和窄屏片段。记录逻辑时间与录制时间，验证帧数、镜头和模式。统一分辨率、编码、播放速度和展示说明，隐藏模型、路径、作者评语及成本。两名评审独立判 `A/B/平/无法判断`，附量规项、时间码和具体理由；分歧由第三人仲裁，保留原票。先用相同视频 A/A、显著单缺陷对、左右交换和风格不同但都合格的样本校准。报原始一致率、平局率、不可判率、位置效应及人机分歧。模型评委可用于筛查；没有独立人工校准时，结果标明评委模型和协议。

### 3.4 题族、重复与区间

**先建谱系，再封 split。** 给原始任务、模板、素材、起始工程、参考代码、教师成品、缺陷注入器和派生轨迹登记来源 ID 与内容哈希。同源改写、翻译、参数变化、同一工程的生成/修复/编辑进入同一连通分量。`watermill-v1` 和 `watermill-edit-v1` 这样的标签不同不能证明独立。通用 Three.js 库先剔除，再以规范化文本、去样板代码 token/AST、素材近似哈希发现疑似跨 split 对，人工核实共享的是任务解法还是公共依赖。保存每个冲突的处理结果。

对 10,697 条 train、812 条 validation、旧 Kimi 参考与恢复案例、历史失败及反馈回归、新 Agent 题包统一查重。保留现有代码数据的原 split 和原始统计；与新隐藏题冲突时优先替换隐藏题族，无法确认来源的题隔离。历史案例进入训练或已见回归账，不能进入新题族泛化分母。dev 用于调阈值、调 prompt 和选 checkpoint。test 封存题面、素材、断言和控制版本；若提前跑原生基线，逐题产物和成绩由评测侧封存，到选型冻结后统一揭盲。

**外测。** GameASG 的公开 `checks.json` 可用于游戏交互迁移，例如 Penalty King 明确列出 HTML 结构检查及相应要求。公开题和公开断言均可能已见，须单列暴露风险和原生输入、运行环境、适配改动。Animation2Code 更适合作有参考视频的运动保真探针。更直接的外测是在训练和选型冻结后，由未参与造题者提供新场景、新素材和交互要求，独立运行同一交付协议。若同时换浏览器或 GPU，保留同一 HTML 跨环境复测，区分作品差异和执行环境差异。GameASG 实例（本地附件未发布）

**规模与重复。** 草案的题包条款写 dev 为 \(6×2=12\) 题、test 为 \(12×4=48\) 题，但执行顺序又写“6 个 Agent dev、12 个 Agent test”。正式开跑应冻结列有全部 case ID 的 manifest，明确是否指簇或子样本。按每题每配置一次，最终 test 每个完整对照臂有 48 个 trial；首次同题通过率是主读数。若需可靠性估计，预先选择覆盖各类型的固定子面板，每臂每题例如 3 次独立新工作区运行，纳入所有试验，禁止仅重跑失败题。它估计同一题对采样和服务变化的敏感度。[草案](../../3d-animation-agent/docs/plans/2026-11-21-simple-first-sft.md)

若某题有 \(n\) 次可计分独立同分布尝试、\(c\) 次成功，统一 \(k\le n\)，则
\[
\widehat{pass@k}=1-\binom{n-c}{k}/\binom nk,\qquad
\widehat{pass^k}=\binom ck/\binom nk .
\]
分子取不到组合时为零。先逐题算，再按族聚合。`n=1` 只报一次结果；基础设施补跑有条件触发，不得当作额外独立采样。现有 `metrics.py` 已有两式及全花费除成功数，但含未知 verdict 的题会跳过聚合，缺 usage 的计数也可能归零。正式表从计划 manifest 左连接所有结果，并加上下界和 usage 覆盖率。项目 `scripts/replay.py` 是外层模板入口；模板以 `.agent/result.json`、`.agent/events.jsonl` 和检查命令退出码为基础，Claude stream 需要显式适配及样例对账。metrics.py（本地附件未发布） · replay.py（本地附件未发布）

**可复算区间。** 对两个系统，在每题计算成功率差，同族求平均得到 \(d_f\)，报告全部 \(d_f\) 及其均值 \(\Delta\)。以固定种子 `20261122` 从 \(F\) 个题族有放回抽 \(F\) 个、重复 10,000 次，每次保留该族的配对 case 和 trial，一起算 \(\Delta\)，取 2.5% 与 97.5% 分位点。补报逐一删族的 \(\Delta\) 范围。小簇数时 bootstrap 也可能退化，例如全簇同向同幅；必须展示原始计数。若问题只是“有多少簇得到改善”，对预定义的二值簇结果可另报 Wilson 95% 区间：即使 dev 为 6/6 改善，下界也只有约 61%；test 为 12/12，下界约 76%。这两个区间针对改善簇比例，不能解释成平均成功率差的区间。便利选择的题族也不能仅凭区间外推至所有需求。[Wilson 原文](https://doi.org/10.1080/01621459.1927.10502953)

### 3.5 公平对照与回归

- **主对照锁定运行条件。** 记录基座/checkpoint 摘要、实际 serving 与精度、系统提示、工具 schema、工具权限、图像可见性、初始工程、上下文与压缩策略、输入输出上限、推理档、温度/采样默认值、步数、墙钟、重试和最终提交规则。两组学生评测时都用完整工具和相同迭代预算。按草案可冻结 256K、medium、3600 秒；同时明确总 token 和每响应上限及后端实际生效值。按 case/trial 分块交错运行，各臂随机顺序，独立工作区、无跨题记忆。
- **两种训练安排共用 arm 表。** 正式对表记录 `base / oneshot_sft / trajectory_sft / kimi`；简单草案记录 `base / mixed_sft`，Kimi 如运行则另列。未训练的臂保留 `not_run`。比较监督形式时，同一教师任务与最终产物成对派生，记录训练源占比、有效监督 token、步数、图像和思考处理。若计算量、输入模态或数据组成变化，明确差异。混合学生对原生的一项对照无法分离代码底座、Agent 数据和训练计算各自的贡献。已对齐决定（本地附件未发布） · [蒸馏草案](../../3d-animation-agent/docs/plans/2026-11-21-sandbox-distillation-pilot.md)
- **Kimi 为同协议系统参照。** 固定当次可用模型 ID、日期、服务可见参数、显示给模型的观察、工具、预算和 retry。相同的 `medium` 字符串不能证明内部计算相同；服务隐藏推理、图像预处理、tokenizer、计费和缓存差异均列出。旧 Kimi 示例有曝光、反馈和环境差异，只作历史回归。不能从教师参照结果推导学生模型的理论上限。
- **两条回归线。** 812 条代码 validation 单列 teacher-forced loss、有效监督 token 分母；对可合法执行的固定子集，同 prompt 和解码条件实测构建/执行，报覆盖数及缺规范的原因。Agent 回归另列简单从零生成、已知缺陷修复、局部编辑保持、健康工程和缺输入阻断。简单生成退化不能被困难题改善掩盖。推理档敏感性只在预先选定的 dev 子集做成对比较，锁定后不从 test 挑档。
- **补跑。** 主表保留首次尝试。预注册可证实的基础设施故障码，例如服务未接收请求或评测机中断，允许原配置一次替代运行，保留原 run ID 与全部成本，另报替代后的敏感性表。模型反复改错、生成超时或自行耗尽预算均按首次结果计入。

### 3.6 最小产物和阶段规则

每条记录带 `schema_version`。以下四张表凭稳定 ID 连接，证据路径带 SHA-256。字段可直接映射 JSONL；金额、usage、seed 等不可得项使用 `null` 加原因。

| 表及粒度 | 必需字段 |
|---|---|
| `case`，每个冻结版本一条 | `case_id, version, family_id, lineage_ids, split, task_type, difficulty, source, exposure, prompt_hash, asset_hashes, fixture_hash, expected_terminal, required_assertions[], preservation_assertions[], controls[], capture_protocol, grader_hash`。每个 assertion 含观察量、单位、时间窗、容差、适用条件。 |
| `run`，每次实际尝试一条 | `run_id, planned_trial_id, case_version, arm, checkpoint_hash, harness_hash, environment_hash, model_id, reasoning_effort, sampling, budgets, seed, attempt, retry_of, start_time, terminal, stop_reason, submitted_candidate, html_hash, source_hash, request_trace_ref, media_delivery_refs, usage_by_kind, usage_coverage, wall_s, cost`。另保存计划 trial 清单，避免进程未启动就从分母消失。 |
| `scorecard`，每 run/断言一行，另有联合结果 | `run_id, grader_version, assertion_id, required, applicable, verdict, measured, expected, tolerance, timestamp_or_span, evidence_hashes, failure_owner, unknown_reason, adjudication_version`。枚举 `pass/fail/unknown/na`；`na` 由题包提前决定。总表保留 `delivery, semantic_joint, preservation_joint, visual_floor, correct_block, primary`。 |
| `visual_review`，每匿名对、每位评委一条 | `pair_id, case_version, blind_a, blind_b, display_order, clip_hashes, html_hashes, mode, viewport, renderer, logical_time_range, fps, rubric_version, reviewer_type, reviewer_id, criterion_votes, preference, severity, evidence_timecodes, rationale, unjudgeable_reason, adjudication_id`。模型身份映射单独保管。 |

| 阶段 | 放行条件 | 停止或降级条件 |
|---|---|---|
| 采集前 | 冻结题面、族谱、断言、预算和证据协议；每个必要断言的好版/坏版/替代版达到预期；健康控制和缺输入对照可判；完整录制能辨认已知坏段。 | 坏版全绿、错因拒绝、合理实现失败、可见输入不足以判断、评分依赖未承诺的内部字段，暂停该题。若存在共用检查器问题，暂停相关整批。 |
| 训练前 | 教师轨迹只从 train 取；独立验收最终成品；清点所有采集尝试和剔除原因。文本和双图 canary 对账实际 system、工具 schema、压缩后可见前缀、图像哈希和到达轮次；校验导出、loader 回读、标签、EOS 和监督范围。记录 10,697/812 原始规模及实际入选量。 | 跨 split 同源未解、图片错轮、训练目标依赖不可见反馈、成品与轨迹哈希不符，隔离相关样本；共性问题阻断整批。约 200 个采集 case、约 150 条合格轨迹是草案目标，不能倒逼降低准入条件。 |
| dev 选型 | 跑前登记有限候选 checkpoint、主指标、不可退化项、实际有意义的最小差值和成本上限。先筛硬门槛与严重回归，再比较题族配对差和删族敏感性。同档且差异不清，按预登记次序选更低成本或更早 checkpoint；标明工程性选择。 | 关键回归、未知足以逆转排序、仅一族贡献全部提升，或连续调参已针对特定题过拟合，停止宣称优胜；保留原生或已有可用候选，优先增补独立 dev 族。 |
| 最终 test | 冻结唯一候选及所有对照配置、case ID、预算、评审与统计脚本后统一揭盲。全计划分母、配对差、区间、逐族计数、成本和外测分别交付。 | 发现污染或共性 grader 错误，保留原结果并标无效范围，使用新版本和新的封存题族复验。若区间跨过预定实用门槛或回归界，结论为“尚未证明达到放行标准”；不回到同一 test 继续选模型。 |

## 4. 风险、分歧与未知项

- **证据最强的是评估器存在具体漏判。** 8 个 fixture 的检查结果来自原始 JSON。实际训练集是否已经吸收这些错误正例、其他题上漏判多普遍，尚无全量审计，不能从 5/8 外推。
- **现有盲评能力待建。** 历史材料支持“作者自审和稀疏截图会漏错”，没有给出经匿名、随机顺序、多个独立评委校准后的偏好信度。动画测量容差、合理风格差异、渲染设备差异仍需好版及替代实现实测。
- **两份训练材料的实验问题不同。** 正式对表关心多轮监督的相对增益；单混合 SFT 能先回答整套方案有无端到端收益。共用题包和 scorecard 可使结果兼容，因果解释必须按实际运行的臂书写。
- **泄漏审计尚未完成。** 本次没有逐条读取万级训练记录或审查全部资产来源；10,697/812 为指定项目计划基线。新 dev/test 的实际 ID、各难度分布、跨族独立性、测试预算和最低实用效应仍待冻结。
- **公开证据覆盖不全。** 3DCodeVerse 与 Animation2Code 的上述具体内容可离线复核；OpenAI、Anthropic、统计论文和三项新动画工作存在不同程度的联网核验缺口。没有把未取得正文解释为研究不存在，也没有采用未经核实的前沿榜单数字。
