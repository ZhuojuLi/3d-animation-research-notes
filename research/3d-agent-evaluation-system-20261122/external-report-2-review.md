# 第二份外部独立报告：研读与校对记录

> 公开整理版 · 2026-11-25。保留成文时点的记录；计划、文献结果和本地实测请分别理解。 环境路径已泛化，未收录的附件已标注；发布范围见 [整理说明](../../PROVENANCE.md)。

2026-11-22。研读对象为[第二份外部独立报告](external-report-2.md)。该报告无法访问本地项目，模型及运行日志未提供；其本地审计条目按待核验假设处理。本文是与[多方汇总](README.md)配套的校对记录，不表示项目已采纳所有建议。

## 1. 总体判断

这份报告与前述研究在最重要的结构上高度一致：

- **题簇宏平均严格成功率**是主指标，未交付、必需语义、关键可读性和诚信不能被平均分掩盖。
- **评估器先校准**，包括好版、单缺陷版、合理替代实现和健康控制。
- **先按源码/资产/任务谱系分组，再派生变体和轨迹**；dev/test 轨迹、评审和隐藏 contract 也不能进入训练。
- **结果与过程分开**，除公开合同和诚信要求外，不强迫唯一工具路径。
- **小样本做配对题簇比较**，重复 trial 只估计同题波动，不能充当独立新题。
- **通用代码保持和困难动画提升需要双向成立**，不能只看困难题收益。

其最有价值的新增内容是：把校准集再拆成设计/冻结验收两部分，引入事前 MDE/power 估算，明确两个学生臂的多重比较政策，并提出独立于 Three.js 的通用代码保持套件。

## 2. 采纳的校准与统计补充

### 2.1 校准集本身也要防止过拟合

将校准样本分成：

- `calibration_design`：用于发现漏洞、调阈值和改 checker；
- `calibration_holdout`：冻结后验证已知好版、合理替代、单缺陷和健康控制。

每次 checker、容差、rubric 或判官提示改变，生成版本并对冻结验收集重跑。不能让同一批 mutant 反复参与调参后，又被用来证明 checker 泛化有效。按 family 隔离校准设计/验收集，避免同源变体泄漏。

配套字段：`mutation_id`、`target_assertion`、`expected_non_target_effects`、`calibration_split`、`known_limitations`、checker/grader 版本与证据 hash。准入时记录“本轮已测控制全过”，不能推断所有可能实现的真阳性率或真阴性率为 100%。

### 2.2 用 MDE 讨论“能发现多大差异”

第二份报告引入 [Miller《Adding Error Bars to Evals》](https://arxiv.org/html/2411.00640)。原文 §3.1 说明重复回答只降低条件方差，§4.2 推荐同题配对差，§5 和 Appendix B/C 给出样本量、MDE 与 cluster 调整公式。

若 `σΔ` 是配对题簇差的标准差，使用双侧 `α=0.05`、80% power 的粗略正态近似：

```text
MDE ≈ (z0.975 + z0.80) × σΔ / √F
```

本地 Python 复算使用精确分位数 `z0.975=1.9599639845`、`z0.80=0.8416212336`，而不是先把系数截断为 2.80。结果为：

| F | σΔ=0.10 | σΔ=0.20 | σΔ=0.30 |
|---|---:|---:|---:|
| 6（dev） | 11.437pp | 22.875pp | 34.312pp |
| 12（test） | 8.087pp | 16.175pp | 24.262pp |

按一位小数显示为 11.4/22.9/34.3pp 和 8.1/16.2/24.3pp。若先使用近似系数 `1.96+0.84=2.80`，最后一格会因截断产生 24.249pp，不应据此误判原报告的 24.3pp 为计算错误。

这是**规划近似，不是实测功效、不是通用最小提升阈值**。它要求对目标题族生成过程和方差结构有明确假设；F=12 时正态近似本身也可能粗糙。实际规划须用 dev 估计 `σΔ`、同题方差和必要的 ICC，并保留 paired bootstrap、留一族和符号翻转等敏感性分析。

注意：**只有 native 的 R=3 不能估计跨系统配对 `σΔ`**。native 可以估计同题方差、infra 率和难度；至少还需要一个同协议学生或参照系统，才能在 dev 上形成配对差。不得为了得到有利方差而挑选参照。

符号检验的小样本界限复算无误：

- 6 个 dev 题簇需 6/6 同向，精确双侧 `p=0.03125`；5/6 为 `0.21875`。
- 12 个 test 题簇至少 10/12 同向，精确双侧 `p=0.038574219`。

它只说明符号分辨极限，丢弃效应大小，不能替代配对差与区间。

### 2.3 多重比较可以更具体

与多方已有方向一致，建议在协议中明确：

- 两个学生臂时，主要确认族是 `one-shot vs native`、`multi-turn vs native`，预先采用 Holm 校正；
- `multi-turn vs one-shot` 是次要配方比较，解释训练形式差异；
- Kimi 是同协议系统参照，不混入“SFT 是否有效”的因果问题；
- 只有一个混合学生时，仅一个预注册 student-vs-native 主比较，不假装有另外两个学生成绩；未运行臂标 `not_run`；
- 类型、难度和视觉维度切片主要作诊断，不在跑完后挑选显著格子。

多重比较应使用与校正一致的区间或校正后 p 值，不能用未校正 95% CI 绕过 Holm。

### 2.4 通用代码保持应有两条回归线

现有 answer-only 812 validation 主要回答 **Three.js 领域代码保持**。第二份报告提醒还应建立 **非 Three.js 通用代码套件**：

- 简短 JavaScript 算法、字符串/数组、异步控制、小型缺陷修复；
- 确定性单元测试，允许多种合理实现；
- answer-only 与固定缺陷修复两种模式；
- 禁用动画专用工具，避免专用 harness 给学生额外优势；
- native 与学生同输入、推理预算和测试，报告配对差、非劣区间与新增失败。

这两类回归不能互相替代。若只有几十题，也不能承诺 ±5pp 的保持精度；应扩题、降低结论精度或明确“未证明保持”。[LiveCodeBench](https://arxiv.org/html/2403.07974) 的发布时间窗口可作公开代码任务的辅助污染控制，但时间窗口不能保证所有模型和后续训练都未见过任务。

### 2.5 困难标签需要实测，而不是 prompt 看起来复杂

采纳以下规则：已知好版能稳定通过，native27B 在同预算下在 dev/pilot 上达到预注册低成功率，才将题标为困难；同时记录状态链、交互、对象关系、时间窗和保留复杂度。不能根据 test 上哪个学生赢来事后划困难集。

没有 baseline 的任务只能标 `prompt_complexity_only`。这与项目当前[规模化草案](../../3d-animation-agent/docs/plans/2026-11-22-scale-to-1000-react-trajectories.md)中“Qwen 实败可重放”的要求一致。

## 3. 明确修正：健康控制的含义

第二份外部报告在 §1.2 将“健康控制”暂按暂停/继续、降低动态效果、频闪限制、资源清理理解，同时正确标为【未知项】。

**本项目现有计划已经明确：健康控制是初始 fixture 已合格，Agent 检查后保持并交付，不能误改。**

直接证据：

- [夜间采集计划](../../3d-animation-agent/docs/plans/2026-11-22-overnight-react-collection.md)：健康控制“初始已合格，检查后保持并交付，验证最终哈希未变”；首批 6 个健康控制要求检查后原样交付。
- [规模化计划](../../3d-animation-agent/docs/plans/2026-11-22-scale-to-1000-react-trajectories.md)：健康控制“检查后保持并交付，不能误改”。
- [既有无缺陷校准研究](../3d-agent-openai-anthropic-reading-notes-20261121.md)：健康的初始场景可用于“检查是否需要返修”，真实检查、证据成立后及时结束。

暂停/恢复、降低动态效果、频闪限制和资源清理可以作为**交互/可访问性/资源健康的独立任务类型**，但不能替代“无缺陷时不误改”的 Agent 行为健康控制。第二份报告 §4.1 的**评估器健康控制**用于发现误报，也有独立价值，不应因名称相同而被当成误解。后续分别称 `agent_no_change_control`、`grader_healthy_control` 和 `interaction_health`。基础设施健康控制另列。

## 4. 重复 trial 策略：保留分歧并收紧时点

第二份报告建议 pilot/dev R=3，最终 test 至少 R=3，波动大时全体统一 R=5。Opus 复核后的方案进一步收敛为：**全集 R=1 起步，不默认设重复子面板；只有 dev 表明 trial 内方差占主导时才在 test 冻结前统一改为 R=3**。

最终取舍：

1. **dev 可先用 R=3 估计同题方差和 infra**；每系统是 `6×2×3=36 trial`。
2. 最终 R=1、R=3 或 R=5 都应是**在 dev 后、test 揭盲前**根据预算、波动、MDE 和业务目标冻结的协议，不存在公开研究证明 R=3 是普遍最低要求。
3. **test 结果接近决策边界时不能追加到 R=5 继续筛选**。这时应报告“未分出”，或在新的封存题族/新确认实验上验证；所有系统必须始终同政策。
4. test 若计划 R=3，每系统 `12×4×3=144 trial`，四系统共 576；三系统共 432。dev R=3 每系统 36，四系统共 144。数字只用于预算，不是独立题数。
5. 多次 trial 只降低条件方差，不能消除题族选择方差；新增独立题族优先于同题从 R=3 增至 R=20。
6. `pass@k` 和 `pass^k` 先在每题内计算再聚合，不能把整体平均成功率直接取 k 次方。

校对时发现我方[主报告](main-report.md)曾将 dev 误写为“24 case / 每系统 72 trial”，已在原文明确修正为 **12 case / 36 trial**，未隐藏该算术修正。

## 5. 分母、封存与产物的可复用补充

- 适用性：`requires_html`、`requires_browser_evidence`、`expected_abstention`、`not_applicable` 分开；故意缺输入与 fixture 损坏不混淆。
- 严格成功：必需 assertion unknown 时 `verified_success=false`，未评审 run 不得被默认视觉通过；开放审美抽样不影响严格门。
- 诊断上下界：`pass/(pass+fail+unknown)` 与 `(pass+unknown)/(pass+fail+unknown)`；`pass/(pass+fail)` 只称可判定通过率，不能作为主分。
- 全分母：保留 `N_families`、`N_cases`、`N_scheduled`、`N_valid_agent_attempts`、`N_scored`、`N_infra`、`N_unknown`、`N_expected_abstention`。另做未解决 infra slot 全部视为失败的敏感性分析，但主分析不拿基础设施失败惩罚模型。
- 封存：public case 与 private contract 分目录分权限；`access.log` 记录访问；blind A/B 与真实 system 映射分开保管；分析脚本、multiplicity 和 unknown 政策在揭盲前冻结。
- 重放：同一冻结产物的 evaluator replay 不给模型新增动作；只有审计后的 infra error 可按预注册槽位替换；`retry.original_run_id` 保留血缘。
- 成本：`null` 表示未知，不写成 0；GPU 秒、USD、wall seconds、token 分开；seed 同时记录 `supported_by_endpoint`，不假装各端点支持相同 seed 语义。
- 限制：每题维护 `known_limitations` 和未覆盖需求，不能用“其他检查全过”掩盖未测条件。

## 6. 一手证据复核与数字解释

- **Miller 的 MDE 表格**是按其公式和第二份报告的假设做的规划计算，不是 Miller 对本项目的实测样本量建议。
- **Animation2Code**原文 §3.1 确有 600 个成对比较、65 名有效标注者、每个比较 3–4 人；overall/appearance 的 Krippendorff α=0.81，temporal=0.73。65 是经过其附录所述筛选后获得全额补偿的人数，不与最初招募的 93 人混淆。
- **VibePrevisBench**第二份报告引用的单 run 0.76 落在原文两个判官比较的 **0.73–0.76** 范围内，与前一份外部报告的“0.73–0.79”不同。多方汇总采用本次在线原文范围 0.73–0.76。单 run 数值与其声明的 2,628 runs、绝对分差等表格细节未纳入最终主结论，不额外扩展未经复核的表格数字。
- **PhysCodeGym**的恢复和选择协议属于作者特定设定，不能直接变成我们的 retry/选版规则。我们按预登记单次自主交付与独立验收执行，不搬“最新有渲染序列的 run”作为通用选择逻辑。
- **WorldCoder**官方页面仍只公开 205 core tasks/74 shared GLB，未提供 StateProbe 实现；任何本地复现声明都不能据此编造。
- **3DCodeVerse**的 29/40→37/40 是 Three.js 执行率，不是动画语义或 Agent 返修成功率，也不是本项目 SFT 的预期收益。

## 7. 不自动上升为项目规则的内容

- R=3 作为最终 test 的普遍最低配置；
- infra 5% 或任何未实测的固定停止比例；
- 健康控制等于暂停/频闪/降低动态效果；
- 用 MDE 表格中的数值直接充当项目最小实用提升阈值；
- 只有 native 的 pilot 就能估计跨系统配对方差；
- 时间窗口、canary 或公开 benchmark 名称能证明绝对无污染；
- 多名评审高度一致就代表评审正确，或不同判官的原始分可以直接混用。

这些项目仍需通过 dev、冻结校准集和真实运行记录决定。本笔记未修改训练配方、项目决定或生产数据。
