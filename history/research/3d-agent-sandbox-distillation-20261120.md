## 建议

先在最终要用的 Claude Code 沙盒里，做一轮**带执行反馈的行为 SFT**。保留已有 one-shot 模型作为对照和可选起点。新数据优先补齐它较少见的决策，例如首次构建失败后怎么定位、看到画面缺陷后改哪里、修复后怎样复验，以及何时提交或说明阻塞。

让开放权重的 Kimi-K3 在固定任务、工具和预算下产出真实轨迹。第一轮用学生在部署时也能拿到的观察训练工具选择、代码编辑和交付。图片进入训练需要单独通过端到端验证。教师思考原样归档，第一版 SFT 只监督动作和有用正文，之后再测短决策说明的增益。

## 教师与学生用什么沙盒

月之暗面公开了原生支持图像和视频的 2.8T Kimi-K3 权重，采用 Kimi K3 License。第 4 条规定了第 2、3 条的内部使用豁免。团队历史确实在 Claude Code 中跑过 `kimi-k3`。新额度使用前核对实际 API 对应的模型版本、轨迹留存及训练条款。该体量下优先验证现有额度，公开权重提供可固定版本的来源。[Kimi-K3 模型卡](https://huggingface.co/moonshotai/Kimi-K3/blob/1f5d44f794ef598de7b6f529ef7923729b7e5408/README.md) · [Kimi-K3 权重许可](https://huggingface.co/moonshotai/Kimi-K3/blob/1f5d44f794ef598de7b6f529ef7923729b7e5408/LICENSE) · 本地 Claude Code 对照（本地附件未发布）

- **让采集和部署用同一个策略接口。** 固定 CLI 版本、system/Skill、真实发送的工具 schema、任务挂载、模板和依赖、浏览器、输出协议、压缩和预算。在 Claude Code 用 `--tools` 限定工具面。历史排查中 27 个工具 schema 约 19K tokens，`--allowedTools` 控权限，schema 仍进入模型请求。固定教师的版本和思考档位，也固定学生各对照组的 tokenizer、模板、适配器和推理预算。区分累计请求 token 与一条训练序列的 token 长度。Qwen 沙盒协议诊断（本地附件未发布）
- **记录每次决策前真正可见的输入。** 保存实际送给模型的消息与工具版本、工具 ID/参数、结果、请求停止原因、工作区快照、产物哈希和图像交付记录。捕获位置选在客户端完成压缩与消息拼装之后，区分排队、发送成功及后续历史中的占位。恢复使用同一工作区和明确的工具结果序列。重放优先核对编译、渲染、哈希、断言及交付，由宿主写证据。保留有效返修中的失败反馈。无产物、中途候选和基础设施失败各自留档。
- **先把看图当成显式工具。** 需要子 Agent 时，固定它的模型、提示、可见图像和结构化返回。记录父调用及子会话 ID，父模型训练前缀只包含它真正收到的返回。子 Agent 私有上下文和像素仍留在其自己的轨迹。父模型可以学到何时请求、如何用返回去修复和复验。

历史 Claude Code 的一条 Kimi Skill 轨迹含 130 个工具结果、37 个嵌套图像块和 60 个 thinking 块。本地夜跑的 7 份原始会话含 128 条非空 `reasoning_content`，严格导出移除了这些字段，7 条也全部只剩文本。追查原会话 27 次图像附件，发现 4 次记录中的路径和会话保存的最终哈希对不上。其余匹配的是最终记录，复用历史帧仍须以当轮哈希为凭。旧版运行时把图像在成功请求后改成占位，预算提示也在请求时动态拼入。只读最终会话不足以精确重放每一轮。导出报告（本地附件未发布） · 原会话索引（本地附件未发布） · 运行时代码（本地附件未发布）

## 图片放在哪一轮

统一**观察记录和资产标识**，消息角色按来源保留。

| 输入 | 放在模型第一次真正拿到它的地方 |
| --- | --- |
| 用户 reference 图或视频 | 首轮就给模型时作为该轮 user 附件。通过文件按需读取时，挂在相应的工具结果。视频先从带时间戳的关键帧开始。题目注明 reference 是外观方向、动作目标还是精确还原 |
| 执行后候选截图或裁图 | 对应本次渲染/查看工具的结果，出现在下一次模型决策之前。版本、时间点、视口和裁剪随图保留 |
| 固定视觉工具或子 Agent 的文字观察 | 对应同一工具调用的文本结果，给出画面来源、可见事实、缺陷位置、时间点和不确定性。后续独立盲评作为筛选标签保存在轨迹外 |

每份像素记录保留原图与发送版本的哈希、候选 HTML/源码哈希、时间点、视口、裁剪、工具 ID 和实际到达的模型请求 ID。部署按视觉 token 预算保留当轮必要证据，旧图要回看就重新请求。训练用同样的图像窗口。更晚生成的图或最终评语不得提前出现在前缀。

Opus 的回放审查建议在**最后一层适配器序列化后**记录每次尝试的图序、消息位置、工具 ID、实际编码字节对应的哈希，以及被丢弃的图和原因。运行时现在记的是发送前的 `image_count`，而 provider 读取文件后校验，再读一次进行编码。采集时可一次读入，用同一份字节计算哈希和发送。给 reference 放一张带文字的红色图，令工具回一张带不同文字的蓝色图，验证最终请求的两张图和模型读到的顺序，再交换、隐藏、混入旧版本及模拟重试。恢复还需要核对工具提交状态。当前专用运行时会将中断的工具标为副作用未知并要求先检查文件，而 Claude Code 路线应按实际宿主单独验收。Opus 会话回放审查（本地附件未发布） · 本地 provider（本地附件未发布） · 本地恢复代码（本地附件未发布）

**先跑通文本闭环。** 让教师和学生看到相同的文本观察，例如编译日志、浏览器状态、带时间的几何测量，以及按需要由同一个固定视觉工具给出的带证据文字评审。视觉工具可把「4.1 秒蓝色摆球贴近另一球」和相应来源交给父模型，父模型再用探针定位并修复。图像缺失或版本对不上时，工具明确返回不可用或请求重开，训练同时覆盖这种分支。若教师动作依赖学生拿不到的像素，应在共享文本观察下重跑或重标注该决策。单独遮掉看图评语的 loss，仍会留下可能依赖缺失像素的补丁及后续上下文。

**再验证原生图像进训练。** 本机 Qwen3.8-27B 基座配置含视觉编码器。历史修正后的 Claude Code shim 已验证两次实际 Read PNG，工具结果内图像到达模型并得到一致的描述。本轮只在 CPU 上验证了基座 Jinja 对用户 reference 与 tool 回图分别保留视觉占位。上游 Swift v4.5.2 文档已有 OpenAI 和 Anthropic 多模态工具调用示例。当前严格导出器只接受纯文本，自定义 `swift-normalize` 也会合并 user/tool 并把工具结果拼成字符串，因此图像分支走原始记录到独立适配器。对锁定的训练镜像，用一条「reference → tool 回另一张图 → 下一轮工具动作」样本验证 loader 和真实视觉张量、图序、消息边界、代码/工具调用 loss、观察 mask、EOS、一次反向及推理同轨回读。再用互换图、无图、旧候选图测试。当前核验尚覆盖不到镜像里的图片反向和最长视觉序列。基座配置（本地附件未发布） · 历史实际送图（本地附件未发布） · [Swift v4.5.2 数据规范](https://github.com/modelscope/ms-swift/blob/v4.5.2/docs/source_en/Customization/Custom-dataset.md#standard-dataset-format) · 本地文本适配器（本地附件未发布）

## 如何量化动画质量

| 层 | 怎么测 | 报什么 |
| --- | --- | --- |
| 正式交付与可运行性 | 用同一冻结浏览器重新加载最终 HTML，复核从源码重建、离线性、报错、时长、时间轴、正常播放及预算 | 正式交付率、技术通过率、错误分类、每次成功的 token 和时间 |
| 动画要求 | 用任务专属的少量断言检查真实对象和运动，例如主体位移、接触顺序、相机投影边界、循环接缝和控件状态。给每条断言配一个已知好样例和一个故意破坏该要求的反例 | 必需断言通过率、失败项、观测不到的比例。必需项观测不到时记为待复核 |
| 成片观感 | 同题随机左右顺序、匿名对比真实连续视频及 brief/reference。对需求、可读性、运动、材质光照和总体偏好分别记录。两位评审起步，分歧时复核。用视觉模型预筛和优先挑出分歧样本 | 胜/平/负、双方可评数量和已交付成片的可用比例。单边未交付另计 |
| 迭代质量 | 同一运行对比初稿和最终正式候选，按修复目标查同机位、同相位证据、对应指标及其他需求是否回归 | 初稿到终稿的修复率、回归率、失败恢复成本 |

例如旧「三摆」题要求 6 秒循环，三个周期分别为 1.5、2、3 秒。现有检查采六个时刻，旧报告里 DeepSeek 在正常播放帧出现两球接触。对球体密集计算 `球心距离 - 两半径之和`，并对着实际相机测屏幕投影轮廓间距。前者回答是否穿模，后者回答观众能否清楚分辨两球。再检查各周期、接缝两侧速度和真实时间轴。用通过场景与只改变相位或间距的反例验证探针。非球形物体可先用 AABB/OBB 报疑点，配合具体形状或复核。当前 `check_case.py` 的签收含模型自审 pass，评测的技术结论应从独立重放取得。Three.js 的 DevTools hook 可作为采集入口，需用实际输出和已知反例验证覆盖及语义映射。三摆任务（本地附件未发布） · 接触实例（本地附件未发布） · 浏览器采样（本地附件未发布） · 签收检查（本地附件未发布）

Opus 提出这可能是屏幕轮廓重叠。本轮在 Chromium 重放两个归档候选各 720 个时刻，从交付 HTML 的 `renderAt` 读取实际几何和相机，计算 960×540 画布上轮廓的有符号间距。在 **3.358 秒**，DeepSeek 两球投影重叠约 **1.21 px**，同一时刻的三维表面净距仍有 **0.196 场景单位**。旧六个采点的屏幕间距都至少为 **46.05 px**。Fable 对照的最小屏幕间距为 **39.00 px**。两组最坏帧实际重新渲染并查看。这给出了可用于验收新探针的一对反例和通过样例。测量数据（本地附件未发布） · DeepSeek 最坏帧（本地附件未发布） · Fable 对照帧（本地附件未发布）

Opus 还找到了两个易漏的验收边界。C2 音箱检查用真实零件，但自行复制了爆炸时间函数，后续应读实际 `renderAt` 之后的对象状态。时间轴测试应核对滑块值、场景时间和该时刻的渲染一致。自动挑最小间隙、遮挡或循环接缝处的帧供评审定位，保留连续视频让人随时复看运动。像素阈值随题目和分辨率设定。Opus 成片验收审查（本地附件未发布） · C2 探针源码（本地附件未发布） · 时间轴现有断言（本地附件未发布）

参考视频只有在目标明确为还原时才做相似度。固定视角和时间后，检查关键动作、速度与接触事件，也可借用 Animation2Code 的外观和物体轨迹指标。允许时间对齐的外观分与严格时长、节奏约束分别出结果。风格参考或开放生成用任务条件和匿名连续视频评分，保留多种合格解法。Animation2Code 评测方法（本地附件未发布）

## 教师思考是否改写

**教师在线回放保留原样，学生首版先学习动作。** K3 官方模型卡要求多轮和工具调用回传完整 assistant 消息，包括原样 `reasoning_content` 和 `tool_calls`。保存原始响应供回放、筛选和分析。训练助手轮可另行生成不同监督版本。文本一问一答的 Ready 数据已经验证过 0.5/1.0 段权重，真实多轮需重新验证每次有效工具动作是否有标签、tool result 是否为输入、目标模板能否回读实际解析的调用。旧 normalizer 遇到非法参数时可退化成空对象，对正式轨迹应先拒绝或隔离这类记录。[K3 多轮用法](https://huggingface.co/moonshotai/Kimi-K3/blob/1f5d44f794ef598de7b6f529ef7923729b7e5408/README.md#6-model-usage) · 现有段权重验证（本地附件未发布） · 工具参数转换（本地附件未发布）

- **A，行为监督。** 同一批通过验收的轨迹，监督可解析工具调用、实际代码改动和交付正文。
- **B，行为加短决策说明。** 保持 A 的动作和代码相同，只给关键决策补「当前证据 → 假设 → 下一步检查」。例如「画面 3.36 秒两球轮廓接触，先测投影间隙与三维净距，再决定调整镜头还是摆幅」。说明只能引用该轮之前能得到的证据。来源与改写版本可追溯。
- **C，可选原始思考对照。** 选同时有原始思考与短说明的同一批回合，复用 A/B 的分组和起始权重，测试原样监督的收益与长度成本。用同配置的推理思考档与预算比较。真实思考档位的最佳部署配置可另跑。

结果以正式交付、返修成功、画质盲评、截断率和每次成功成本决定。已知 Qwen 高思考档会产出长规划，旧适配器曾把它写回可见历史并误报截断。短说明或原始思考若只增加上下文和成本，保留 A。事后可用成片与失败记录写审核说明，下一动作前的监督只使用当时的输入。Qwen 历史诊断（本地附件未发布）
