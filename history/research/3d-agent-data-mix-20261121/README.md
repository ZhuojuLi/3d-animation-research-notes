# 3D Agent 训练数据配比：通用开源代码与前沿难点任务簇

> 公开整理版 · 2026-11-25。历史原文；部分建议已由后续方案替代。 环境路径已泛化，未收录的附件已标注；发布范围见 [整理说明](../../../PROVENANCE.md)。

2026-11-21—2026-11-22 · 主调研方与 Astra 独立调研后的汇总

## 先读结论

**最直观的记法：通用代码底座占 80–90%，Agent 轨迹占 10–20%；难点任务簇占 Agent 增量的 40–60%，不要占满全部 Agent 数据。** 前一层按**有效监督 token**衡量，后一层按**独立、验收合格的 case**衡量。

- **当前约 150 条合格轨迹**：建议从 **90:10** 的通用代码 : Agent 有效监督预算起步；如果每个 case 只有一条训练序列、需要高频重复才能达到该比例，则退到 **95:5**，或缩小本轮通用代码子集。若自然混合后的监督占比已经落在 5–20%，直接记录并训练，不为凑数重复或降采样。
- **扩到约 500 个 case 后**：以 **80:20** 为主配置，以 **90:10** 和 **70:30** 做低、高剂量对照。
- **Agent 内部**：首批按 **40% 难点、30% 中等、15% 简单、15% 健康控制**；随后把 **60% 难点**作为难度对照，而不是默认全部上难题。

这些是基于公开证据的**实验起点**，不是 Three.js 已验证最优解，也不自动修改项目的生效训练决定。

## 一、OpenAI 与 Anthropic 是否公开过类似内容

**在本次核对的一手材料中，没有找到两家产品模型“通用代码 : 领域数据 : 高难度 Agent 任务”的通用配比。** 公开的是局部研究配方和任务构建方法。

- [OpenAI 的 Ironclad 合作](https://openai.com/index/advancing-computer-use-with-ironclad/)把专家工作流变成可执行环境，围绕代表流程构造合成训练题并做 RL。11 道是研究评测题，每题有 8–50 项验收标准；训练题总数及其占全部训练的比例没有公开。
- [GPT-5-Codex system-card addendum](https://openai.com/index/gpt-5-system-card-addendum-gpt-5-codex/)说明模型在真实编码任务和多环境中做 RL，学习迭代运行测试，但没有给通用数据与难题的比例。
- [GPT-4 Technical Report §2](https://arxiv.org/html/2303.08774v6#S2)明确说明不进一步披露 dataset construction 和 training method。
- [InstructGPT](https://arxiv.org/html/2203.02155)的 PPO-ptx 证明混入预训练梯度能减轻部分能力回退，但其 SFT、RM、PPO 数据属于不同阶段，不能把各阶段数量当成同一次混合的比例。
- [Anthropic A3](https://alignment.anthropic.com/2026/automated-alignment-agent/)直接采用“真实失败 → 失败假设 → 变体与正常对照 → 自适应调权”的流程。固定随机基线是 15% 通用后训练 + 85% 定向生成，**这是对照基线，不是普适最优或 Claude 产品配方**。
- [Anthropic 审计 Agent RL](https://arxiv.org/html/2608.25460#S3.SS4)的最佳配置把 50% 训练 batch 给无预埋行为目标，以控制误报。这支持保留健康控制，但不能换算成 Three.js SFT 的简单题比例。

因此，两家材料支持的是用户提出的方向：**从真实高价值失败出发，构造能运行、能反馈、能验收的任务，再用通用/正常数据防止行为回退。** 它们没有给出可以直接照抄的百分比。

## 二、最有参考价值的公开数字

| 工作 | 原始配方及分母 | 对本项目的意义 |
|---|---|---|
| [AgentTuning §2.2.2](https://arxiv.org/html/2310.12823v2#S2.SS2) | 1,866 条经验证 Agent 轨迹；7B 上把 Agent 分布权重从 0 到 1 扫描，最终选 **20%** | 与本问题最直接：20% 是混合目标中的分布权重，不是 case 条数；纯 Agent 的留出泛化更差 |
| [Hephaestus §5](https://arxiv.org/html/2502.06589v1#S5) | 继续预训练中约 **36% Agent token**，Agent/文本/代码约 1:1:1；用小模型 scaling-law 实验估计 | 说明比例可实测，也说明继续预训练配方不能套到当前 SFT |
| [DeepSeek-R1 §2.3.3](https://arxiv.org/html/2501.12948v1#S2.SS3) | 约 600k 推理 + 200k 非推理，即 **75:25 的样本条数** | 推理与通用分层、正确样本筛选值得借鉴；75% 不是 Agent 难题推荐值 |
| [3DCodeVerse §5.2、附录 C](https://arxiv.org/html/2610.22341) | 27B 的 104K-pair、75M-token 配方恢复执行验证 bootstrap 并平衡方言；其 9B 消融通过重复将 Blender 份额从 15% 提至 34%，留出 Blender F@0.05 从 0.705 到 0.816 | 多源通用代码与目标领域增量可以互补；仍是单轮代码配方，不等于多轮难点轨迹比例 |
| [ManimCode §3–5](https://arxiv.org/html/2611.08294v1) | 24,034 条渲染验证、质量筛选轨迹展开为 305,452 个角色条件监督样本；同一 8,416 个输入上，精修监督让 ManimData-test 渲染率 57.2%→63.2%，ManimBench 69.0%→76.0% | 最贴近“动画 + 执行/视觉反馈 + 修复轨迹”的证据：质量和纠错过程确实能改变模型能力；展开样本数不能当成独立 case 或 loss 比例 |
| [SFT Data Composition](https://arxiv.org/html/2310.05492v4) | 数学、代码、通用指令实验中，绝对数据量常比比例更关键；顺序学习会遗忘 | 配比之外还要看每类有效数据量、训练顺序与回归 |
| [Data Mixing Optimization for SFT](https://arxiv.org/html/2508.11953v1) | 通过多种小规模混合拟合验证损失，优化权重接近网格搜索结果 | 用小实验选配比，比复制任何“黄金比例”更可靠；最终仍须看真实任务成功率 |

公开数字从 20%、36%、75% 到 85% 都有，恰恰说明**训练阶段、目标、数据单位不同，比例就没有可比性**。

## 三、为什么不能按 case 条数直接混合

当前有 10,697 条通用代码记录：

- 150 条 Agent 轨迹按原始记录数只占 **1.38%**。
- 500 条时占 **4.47%**。

但一条 Agent 轨迹可能包含多轮代码、工具调用和修复动作，与一条短 answer-only 记录的监督长度完全不同。应分别记录：

1. **独立 family/case 数**：衡量真实覆盖，控制同源泄漏。
2. **导出训练序列和采样概率**：决定优化时抽到什么。
3. **有效监督 token**：assistant 正文、代码、工具调用、EOS 中真正计 loss 的部分；长工具结果和图片上下文不等于监督。
4. **实际训练 loss 与更新**：还受 loss_scale、mask、batch reduction 和梯度方向影响。

令 \(r\) 为“平均每条 Agent 记录的有效监督 token / 平均每条通用记录的有效监督 token”，目标 Agent 监督份额为 \(q\)，则 Agent 记录抽样概率应约为：

\[
p=\frac{q}{r(1-q)+q}.
\]

仅作敏感性演示：

- 若 \(r=4\)，150 条 Agent 与全部通用数据各看一次，Agent 自然占 **5.31%** 有效监督；要到 20%，每条 Agent 平均约出现 **4.46 次**。
- 若 \(r=16\)，同样自然拼接已经达到 **18.32%**，几乎不需要额外加权。

如果每个 case 只有一条训练序列，且 10,697 条通用数据全部看一遍，按记录采样时的重复压力为：

| Agent 采样权重 | 150 条时平均重复 | 500 条时平均重复 |
|---|---:|---:|
| 5% | 3.75 次 | 1.13 次 |
| 10% | 7.92 次 | 2.38 次 |
| 20% | 17.83 次 | 5.35 次 |

所以当前不能机械地把 150 条轨迹复制到占 20%。更好的选择是降低本轮目标比例、使用通用子集控制总预算，或先扩大独立 Agent 池。

## 四、难点任务簇应该怎样组成

首批 200 个 case 可按以下规划，最终只让验收合格者进入正样本：

| 类型 | 比例 | 200 个采集名额 | 学什么 |
|---|---:|---:|---|
| 难点 | 40% | 80 | 原版 27B 可重放的稳定失败；跨步骤定位、返修、复验与交付 |
| 中等 | 30% | 60 | 有时能成功的近边界任务，学习一段可迁移的观察→修改→复验 |
| 简单 | 15% | 30 | 基本工具契约、最低充分操作和直接成功路径 |
| 健康控制 | 15% | 30 | 初始结果已合格，检查后保持并交付，避免误改和无效抛光 |

难点应符合四个条件：**失败能重放、失败属于能力而非坏 fixture、教师能跑通、独立验收能区分好坏。** 单纯代码更长、场景更炫或所有模型都失败，不构成合格难点训练题。

一个任务簇应围绕同一失败机制包含不同正确动作。例如“暂停后画面不动”可以分别派生：时钟冻结但仍绘制、恢复后错误跳零、原本正常应直接交付。换颜色、换标题的副本不能冒充新的难点家族。

第二批可在同一通用/Agent 配比下，把难点从 40% 提到 60%，相应减少中等任务，保持简单与健康控制，检验用户提出的“难点是腾飞核心”能否在留出家族上转化为实际增益。

## 五、推荐实验矩阵

从同一个原版 27B 出发，固定教师数据、模板、mask、优化器、学习率日程和总有效监督预算：

| 组 | 通用代码 : Agent | 目的 |
|---|---|---|
| G | 100:0 | 通用底座对照，排除“继续训练本身”带来的变化 |
| L | 90:10 | 当前首选低剂量；小池高重复时改为 95:5 |
| M | 80:20 | 500 case 后的主配置；20% 仅借 AgentTuning 作启发式锚点，并非同分母复刻 |
| H | 70:30 | 高剂量压力测试，观察覆盖、遗忘与过度操作 |
| D | 与 M 相同 | Agent 内部难点 40%→60%，单独测难度效应 |

预算有限时先做 G/L/M，再做 H/D。每组都记录独立 case、导出序列、每题曝光、有效监督 token、输入 token、优化步数和实际训练 loss；等监督量不代表等计算成本。

主要选型指标不是训练 loss，而是留出家族上的：

- 正式交付率及全部必要断言通过率；
- 难点修复成功率、非目标保持率；
- 健康控制误改率与简单题回归；
- 通用代码验证及可执行子集表现；
- 每次成功的耗时、token、无效工具调用与超时率。

6 个 dev 题簇只能做粗粒度选型，不能证明 10% 与 15% 的细微差异。最终 test 必须继续按场景、素材和任务模板家族隐藏。

## 六、最终判断

用户的理解与公开证据是一致的：**大规模开源代码提供基础能力，真实前沿失败转化而来的可运行难点任务簇，提供通用数据很难给出的反馈利用、定向返修和交付能力。**

但“难点是核心”不等于“难点必须占大多数”。更合理的起飞路径是：

1. 通用代码保持 80–90% 的有效监督基本盘。
2. Agent 轨迹从 10% 起步，覆盖充分后测试 20% 和 30%。
3. 难点在 Agent 内先占 40%，再用 60% 对照验证其边际收益。
4. 用真实任务成功率而非直觉或文献常数决定最终比例。

论文和前沿理论主要用于发现难点、定义任务簇和验收，不建议把论文文本按篇数当成第三大块训练语料。若以后专门训练理论知识和方法选型，应另设数据域与评测。
